## 1. 定位与边界

这是**独立于隧道文件传输、Telegram 网盘本体及 SNS/YouTube 下载队列**的管理员媒体处理和收藏子系统，入口 `/media-library`，须经过管理员身份认证。页面标记 Beta，六个主视图为：基础设施设置、资源导入、提取会话、收藏资源库、标签与人物、系统状态。

新模块以自身持久业务数据库 `media-library.sqlite` 管理账户工作区、导入、会话、任务、截图、Clip、压缩版本、候选与正式收藏、授权关系和事件；使用 `node:sqlite` WAL/FULL、短事务、乐观版本与作用域隔离。**不修改网盘 `disk.sqlite` schema**。临时字节缓存、工作片段与正式 Telegram 网盘内容各有所有权和生命周期。模块自己的数据库、队列不嵌入 SNS/YT 下载业务内部。

## 2. 工作区授权与来源导入

初次使用须为“工作区”与“正式收藏”分别选择并授权已登录的网盘账号、原生分区和目录。两者不可为同一账号同分区同路径；授权可以撤销，恢复旧位置须重新授权**原账号、原分区和原目录**，不能悄悄重定向到当前登录的其它账号。子系统后台读取仍逐次校验身份、分区、目录、审核与授权，不依靠页面 Cookie 持续保持登录；不同工作区隔离。

导入支持本机完整上传、已有网盘文件引用及 SNS/YT 已有成品/新建下载任务。已有网盘对象只关联，不随意复制或删除原件；新下载页面通过临时绑定参数关联媒体导入任务，绑定失败不能自动创建第二个下载任务。下载完成可由独立队列转存，即使页面关闭也继续执行。来源版本改变、字节未完整接收、权限失效、远端写入确认未知等情况进入失败或中断恢复，不能标作成功或盲目再传一份。

服务端网盘读取通过短期、随机、仅绑定 `127.0.0.1` 的 HTTP 资源地址供 FFmpeg 读取，并支持 Range 与取消。相关本机读源不启用 FFmpeg HTTP 代理，不改变其它 Telegram/SNS 的代理设置。

## 3. 提取会话、截图与视频 Clip

- 可按多范围、等间隔或随机策略抽帧，单批至多 500 张；分别保存请求的时刻和真实帧时刻，支持跨会话查找重复来源/时刻。
- 截图区域独立于候选 Clip。完成后按原视频**实际播放时刻**合并多个批次的截图，支持批次磁贴持续高亮、单项预览及同会话可用截图的上一张/下一张、键盘方向键与横向触摸切换。全屏图库会保留操作区；批次标记不改变实际排序、删除或过滤资源。
- 视频逐帧定位根据 ffprobe 的实际帧时刻（含可变帧率、非零时间原点）选择邻帧，长 GOP 使用能够覆盖目标区间的探测范围。浏览器实际 seek/帧确认有自己的精度边界，不保证不支持的编码也能播放。
- 可选择起止范围，采用精确重编码或快速流复制生成候选 Clip。临时兼容 MP4 工作片段最长一小时，可供后续抽帧/裁切复用；播放工作片段有“返回原视频”入口，不覆盖原素材或候选。
- 会话标题及 Clip 可保存独立备注；Clip 提供查看、下载、收藏、压缩。候选视图可切换宫格与紧凑列表，生成任务从排队占位转为结果卡片；未保存备注不能在轮询重绘时丢失，也不能阻止别的卡片刷新。
- 可使用感知哈希及灰度像素比较辅助发现相似画面；参考图片、正式收藏、人物/组织/标签及时间关系独立管理，不会自动识别人或删除疑似重复项。

## 4. 压缩版本、命名与上传

候选 Clip 可创建多个独立 H.265 / MKV 压缩版本：`libx265`、可选尺寸、CRF（默认 28）、preset（默认空）、音轨复制；每次产生独立进度、缓存、缩略图及媒体校验。任务提交时即展示排队占位，完成时原位替换，多个版本按最近加入优先。右侧播放器、下载、网盘转存和参数随选中版本更新；窄屏改为上方版本区与下方播放器。浏览器不支持 HEVC/MKV 播放时仍可下载。

Clip 与压缩文件使用统一命名辅助 `server/media-library/clip-name.js`：原始 Clip 名称含会话前缀、保存的备注与起止时刻；**压缩版**进一步使用持久 `clipOrdinal`、版本 ordinal 和实际分辨率，例如 `{Clip名称主体}-CLIP{序号}-压{版本}-{宽}x{高}.mkv`。每个会话的 Clip 成功事务才占用持久序号，删除不复用；失败/重试保留已分配压缩版序号。历史已确认的名称冲突可用原转存记录安全重试，**已成功或写入结果不明的文件不自动重命名**。

正式收藏/压缩版存网盘必须确认 Content 引用与字节，才显示已收藏和定位链接。重复提交复用原任务/收藏 ID；后台阶段与已发送/已确认字节会持续反馈。取消、过期、转码失败或丢失缓存只影响候选与任务，不应连带销毁已确认收藏或其它 Content 引用。

## 5. 生命周期、可靠性与测试边界

- 工作区默认自就绪日起一年，可续期；候选与工作片段受容量、最近使用和期限限制，运行任务持有租约与 pin。清理只处理归属明确的专用文件，不能递归删除任意用户路径。
- 单媒体队列及进程领取：运行中的有效租约不会被其它实例抢走；死进程任务可恢复。Telegram 上传及 Content 结果未知时保留原身份与幂等预约，禁止凭文件名再上传。
- 视频处理检查轨道、时长、时间戳/DTS 连续性及完整解码；校验不能保证所有源文件主观音画同步。抽帧、裁切和压缩的浏览器真机编码/内存支持仍须单独检验。
- 最新 261017-2 开发记录报告**全量 932/932 通过**，另有媒体、压缩、导航和真实合成视频的隔离浏览器验收；这是当时开发验证记录，**不代表生产 Telegram、真实外部 SNS/YT、Android 真机已验收**。
