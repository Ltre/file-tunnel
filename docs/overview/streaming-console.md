## 1. 定位与数据所有权

串流控制台在主页面内提供“发现 / 本机节目 / 已订阅”、创建/导入/编辑节目单、观看页、操控页、邀请与可见范围、封面、资源预览、后台播放及小窗。它是**节目编排与观看授权层**，不是把文件上传到单独的串流存储空间。

- `server/streaming-console.js` 用 `.tunnel-data/streaming-console.json` 持久化节目、设备、可见性、邀请、收藏订阅、配置版本和全台播放时钟；以受控原子写入更新，不使用 `disk.sqlite` 作为节目数据库。
- 节目媒体正文仍由原来源持有：`disk` 使用 Telegram 网盘的 Object Storage/Content，`tunnel` 依赖源隧道的消息/资产及读取授权，`local` 由本机浏览器作为供源者。保存节目单只是保存**引用、编排和校验结果**，不等于转存正文、增加网盘永久引用或缓存所有字节。
- `server/streaming-http.js` 挂载 `/api/streaming`，负责设备认证、频道/节目 CRUD、媒体票据及 Range、NDJSON 状态、观看上报、邀请码和来源工作；`server/streaming-sources.js`、`streaming-disk.js`、`streaming-tunnels.js` 以独立适配器访问现有来源。原网盘和隧道传输模块不应反向依赖串流台实体。

## 2. 设备、登录、节目归属与权限

- 每台设备向串流系统登记独立设备标识和密钥，后续请求用 `X-Stream-Device` / `X-Stream-Key` 鉴权。另可附用户登录证明，但串流设备凭据不能代替**网盘原账号**或**源隧道的 grant**。
- 创建的节目首先归属发起设备；绑定登录身份的节目还有 owner 用户。编辑、删除、转让及操控须经身份、来源设备与登录状态校验；**操控权限不等于在其它设备上编辑来源文件**。账号退出或撤销登录可使相应操作被拒绝。
- 新节目初始不可对外观看（`offline`）。可切换 `public` 或受邀访问；订阅、邀请、设备/账号黑名单、撤权和来源离线各有独立状态。邀请码有设备定向/通用、失效/撤销及过期检查；邀请海报是受长度和 MIME 限制的图片快照，不包含网盘 Secret、隧道 grant。
- 观看与操控是不同职责：观看者有自己的播放器和观看心跳；管理员对节目播放、暂停、跳转及可见范围进行全台控制。撤权或原来源授权失效时，每次媒体读取重新校验，不能凭已拿到的旧媒体票据持续读取新的来源。

## 3. 节目单、保存与状态恢复

- 支持图片、音频、视频、Markdown/富文本等可读取来源；为媒体条目保存真实时长/播放范围，图片/文档用停留时间。支持循环、节目单排序、候选筛选、封面上传和多种来源导入。
- 编辑器区分**本机未保存草稿**与已确认的 `configVersion`；保存前对网盘/隧道来源进行实际可读性抽样检查，缺失源/版本冲突返回逐项错误或 `STREAM_CONFLICT`，不可仅靠名称、Hash 或前端保存按钮显示成功。
- 保存/检查支持 NDJSON 真实阶段进度；某些版本曾有长时间“保存中”或错误时按钮无响应，当前改为**失败保留编辑草稿、允许再次检查和提交**，并避免重复创建未确认的台号/节目。切离编辑器时须明确“保存/放弃/继续”，离开失败不清空输入。
- 选中项的来源定位通过 `/stations/:id/items/:itemId/source-location` 在配置版本不变、具备管理资格时返回受限位置摘要，再导航到对应账号/分区或源隧道；不暴露物理服务器路径和源账号鉴权信息。来源短码从当前持久隧道目录读取，不能凭节目备注猜测。

## 4. 播放时钟、来源读取与缓存

- 全台播放位置以服务端时钟和节目进度为准；观看设备分别上报 `playing/paused/buffering/waiting/blocked/error/reading`。没有可用观看者时服务端可暂停，下一位有效观看者按规则恢复。播放器的本机暂停/缓冲、全台暂停、无源和自动轮播不能混成同一种状态。
- HTTP 媒体票据按节目、条目、来源版本、设备与访问授权签发；`/media/:ticket` 支持合法单段 Range 和取消。未确认完整或来源失效不把 UI 100% 当作内容有效。普通浏览器媒体元素仍走原生解码、seek 与 206 响应。
- 本机/隧道来源由短时 `provider-work` 拉取和按需字节请求提供，不常驻复制媒体。具有安全上下文、Service Worker 与浏览器支持时，`server/streaming-peers.js` + `client/streaming-peers.js` 可在授权及票据核验后尝试**局域网 WebRTC 字节直传**；无对应能力/握手失败时回退服务端原生 Range。无 Worker 的 HTTP 环境仅对较小素材尝试 Blob 直连，**不是全部视频都能脱离服务端读取**。
- `client/streaming-cache.js` / `server/streaming-buffer.js` 对明确节目、来源版本和授权范围做受限短时 Range/预读复用；**缓存不是永久文件仓库**。浏览器局域网直传、串流台的 HTTP 源代理和隧道普通文件的 WebRTC P2P / Socket.IO Relay 是相邻但**不同的传输状态机**，不能套用同一进度判断。
- 资源请求优先复用当前本机已有可验证字节；缓存来源消失、Cookie/登录撤销、网盘 Content 变动时应失效或安全回退，不绕过权限。对于不同 Origin 的进度/缓存差异，历史上曾有特定环境观察，但不能在没有网络 HAR 或原设备复现时断言“代理必然阻断 P2P”。

## 5. 当前 UI 行为与交互

- 主要界面：发现、创建/编辑、导入、观看、操控、订阅、邀请、封面及黑名单。移动端有独立页面与底部导航；宽屏按当前断点排布，播放器可横屏全屏，操作控件按交互显示并自动收起。
- 观看页用**同一播放器实例**维持普通页、小窗和全屏，避免音频重复播放。页面切换、自动播放下一个节目和恢复时尽量复用列表 DOM、保留滚动、只在当前节目真实变化时自动定位。小窗保留简化控制和拖动，不偷偷改变全台播放权限。
- 邀请支持生成正文含海报的 Markdown 消息；海报可按受限当前画面、封面与节目信息生成，图片本身需通过授权映射，不能把任意 `data:` URL 提升为普通 Markdown 可执行/可共享权限。
- 当前版本增加多个节目同时勾选和受控管理（取消订阅、黑名单/开放范围编辑等），严格区分选中项、正在操控项和管理员能够编辑的台；批量操作应逐项确认结果，失败只影响对应项。
- i18n 从 `client/streaming-i18n.js` 扩展；`client/streaming-console.js/.css`、`streaming-player.js`、`streaming-app-adapter.js` 实现本地视图、播放器及隧道/网盘来源衔接。主 UI 新主题只能改变可视样式，不得改源授权、节目顺序或播放时钟。
