# 系统备份程序：范围、快照、分段与恢复边界

> **源码基线 Commit**：`71e58b07350a0ef3b480fa82272177863de74448`  
> **文档更新时间**：`2026-11-07`  
> 入口：`/system-backup`；后端 `server/data-backup.js`，页面 `pages/system-backup.html`，前端 `client/data-backup.js/.css` 与 `data-backup-i18n.js`。

## 1. 功能定位

独立管理员系统备份页面通过网盘 Object Storage 保存服务器数据目录的**一次受控文件快照**，并显示任务进度、取消、重试和释放本机快照。该功能不是“网页下载全部文件”，也不是将网盘数据直接混写回 `disk.sqlite`。

两种模式**各自绑定管理员明确指定的网盘账号、原生分区与已存在目录**：

- `FULL`：包含数据目录下除根部 `telegram-content-cache`、`telegram-drive-staging`、`telegram-part-cache` 之外的内容。
- `CORE`：包含根目录下的普通文件，以及 `disk-spaces`、`streaming-console`、`youtube-premium-downloads`、`sns-downloads` 四个指定目录。不能把缺失/空名称猜成一个真实路径。

目标下按“**步进序号-YYYYMMDD**”创建版本目录。任务请求有幂等标识，单进程串行执行；前台账号切换不改变已启动任务绑定的目标。

## 2. 文件快照、持久化与上传

- 刷新基础设施的已提交/审计状态后，在受限临时目录创建任务专属快照。源文件、目录和目标路径要验证实际范围，**不跟随符号链接**进入其它系统目录。源 EACCES/EPERM 与状态持久写入失败分别记录，不把异常伪装成成功。
- SQLite 使用**在线备份接口**读取已提交 WAL，不能运行中只复制主 `.sqlite` 文件并漏掉 WAL。普通文件检查复制前后属性并有限重试；多数据库和普通文件之间**没有全局原子时间点**，业务仍可发生写入。
- 逐项经既有网盘对象接口写入；大于单对象限制的文件按分段清单上传，空文件/空目录保留。不能表示为“上传完毕”直到后端实际确认；上传完成后再保存最终 manifest。
- manifest 记录原路径、类型、字节数、SHA-256、分段顺序、目标文件 ID、别名及失败信息。目标不支持的路径片段通过安全别名记录，**不能在恢复时忘掉原路径**。
- 任务失败、用户取消或进程恢复时，保留专属快照和已完成分段；重试先按清单及目标内容校验后复用已有物理对象。只在用户明确释放时删除本任务的本机快照，不删除网盘上的成功备份。
- 任务记录与目标之间没有覆盖所有文件的分布式事务；若在“正文已读取、Telegram 还在等待”时取消，需通过已有受控取消/恢复判断，**不能猜测远端是否完成并再次盲写**。

## 3. 访问控制、恢复与安全界限

- `/system-backup`、`/api/system-backup/state`、`/targets`、配置与 job 接口须管理员 Session；写入另外检查 Origin。不能把账号登录、目标路径选项或凭据放入公共邀请链接。
- **当前未实现自动一键灾难恢复。** 恢复必须停应用写入，按 manifest 找回文件和分段，校验大小/摘要后重组、归位，并考虑 SQLite schema、密钥、原始账号映射和业务文件。不能认为“恢复旧版 `disk.sqlite` 就自动出现备份产生的新网盘索引”：备份目标和清单可能在该数据库快照之后写入。
- `FULL` 也有明确被排除的缓存目录；`CORE` 只是列举范围，均不意味着全部服务和外部 Telegram 消息在同一原子时刻被保存。正式备份完成之后还应做**真实网盘恢复演练**，不能用合成夹具 6/6 或 7/7 代表数据可灾难恢复。
- 来源中可能包含 TOTP、授权密钥、Cookie 和网盘用户资料；管理对象目录必须采用相应 ACL，备份不得作为公开 S3 bucket 或静态资源地址发布。
