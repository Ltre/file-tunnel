## 用途

本文件是 `docs/overview` 文档体系的增量更新锚点。

后续更新总览文档时，应先读取本文件，再将当前代码版本与这里记录的源码基线进行比较，并重点检查：

1. 基线之后新增、修改、删除的源码；
2. 基线之后的 Git Log；
3. `prompts/dev-prompt-logs` 中新增或修订的需求、测试反馈和 Codex 执行记录；
4. `docs/devlog` 中新增或修订的开发日志；
5. `prompts/ideas` 中已经进入实施阶段或改变现有架构边界的设计；
6. 新增测试、回归测试和人工验收结论；
7. 已有需求被后续需求覆盖、废弃或收敛后的最终行为。

## 更新规则

- 本文档体系描述的是“截至某一 Git 基线的当前行为 + 能追溯到的原始需求与演进”，不是简单复制 README。
- 源码代表当前实现事实；Prompt / Devlog / Git Log 用于解释需求初衷、演进和仍未解决的问题。
- 如果历史需求与当前实现冲突，应明确标出“历史要求”和“当前实现”，不能把旧需求误写成当前行为。
- 人工验收结论优先级高于仅有 Codex 自述但没有后续验收的“已完成”声明。
- 对无法从当前源码、日志、Prompt 互相印证的内容，应标记为“待核实”，避免 AI 后续把推测当成既定设计。
- 每次大范围更新后，应把本文件中的基线 Commit 更新为此次文档已经完整覆盖到的源码 Commit；如果只更新某一局部模块，可以在对应模块文档中单独记录局部更新 Commit，同时保留全局基线说明。
