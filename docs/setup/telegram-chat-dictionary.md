# Telegram Chat 字典与历史文件过渡迁移

在后台 `/tgbot` 的 **Telegram Chat 字典库** 区域维护映射，点击该区域的“保存 Chat 字典”。这与上方“保存配置”独立，不调用 Telegram，也不会变更 Token、Webhook 或网盘分区。

## 填写映射

- **Chat ID**：非零十进制整数，以字符串保存。例如频道 / 超级群的 `-1001234567890`、普通群负数 ID 或私聊正数 ID。不会从 public 名称拼接或猜测数字 ID。
- **public 名称**：可选，接受 `@example_channel`、`t.me/example_channel` 或公开完整链接，统一为小写 `@example_channel`。不接受邀请链接或消息链接。
- **备注 / 显示名称**：可选，最多 100 字符。
- **历史 public 别名**：可选，多个名称用逗号分隔。频道改名后可以保留旧名称；变为私有后不要删除仍有历史数据依赖的名称。

一个 Chat ID 只允许一条记录；不同记录不得占用相同的 public 名称或历史别名，大小写不同也算重复。最多 500 条映射，每条最多 20 个历史别名。两个管理员同时编辑时，后保存者会收到版本冲突提示，应重新加载并检查修改后再保存。

字典单独保存为 `.tunnel-data/telegram-chat-dictionary.json`，与小规模 Bot 管理配置同属管理员配置，未加入网盘用户数据表。保存通过临时文件和原子替换完成；无效输入及版本冲突不覆盖旧字典。请将该文件一并纳入备份；不建议在服务运行期间手工修改。读取错误会明确报告，损坏的字典不会被自动清空。

## 双向查询与回源

服务端公共字典的 `lookup()` 支持 public 名称 / 历史别名 → Chat ID，也支持 Chat ID 查条目；`publicUsername()` 返回指定 Chat 的主要 public 名称，仅供显示及过渡兼容。该反向查询不会写回来源数据。

现有 Bot 文件的下载使用 `getFile(file_id)`，这个接口不接收 chat_id；所以仅包含 file_id 的历史文件不需要猜测所属频道，也不会凭字典新增一个不确定的频道标注。参见 [Telegram getFile 官方文档](https://core.telegram.org/bots/api#getfile)。

对于已有 public Chat 标注的实际服务端回源，公共 resolver 先查字典，以数字 ID 调用 `getChat` 确认会话可访问及返回 ID 一致。没有映射时保留旧标注，继续原有 file_id 回源；不会仅凭某个 public 名称当前的查询结果就迁移历史来源，因为旧名称可能已经转让给另一个 Chat。新上传目标不属于历史回源，可以用 `getChat` 将当前 public 目标解析为数字 ID，再发送文件。成功验证短暂缓存五分钟，按 Bot 和 API 地址隔离，并合并同时进行的验证。数字 Chat ID 已经是规范来源，不进行反向查询或重复 public 解析。

验证最多等待 10 秒。如果查询失败，保留旧来源并继续原有 file_id 下载；历史回源在失败后的 30 秒内不重复验证，避免每个 Range 都重新等待。新上传仍必须解析成功才能继续。不会将旧来源改为空 ID。映射返回的 ID 与 Telegram 结果不一致时拒绝操作，防止错误迁移。字典本身由管理员确认同一 Chat 的关系，`getFile` 无法证明某个 file_id 属于哪个 Chat，也不能从任意 public 页面恢复一个已经丢失的 file_id。

## 何时迁移

1. 浏览器仍优先使用完整本机缓存和原有在线设备 / provider 传输。
2. 真正需要 Node / Telegram 回源时才进入兼容处理。
3. Bot 资源完整下载、字节数验证成功后，服务端保存数字 Chat 标注；网盘资源保留逻辑文件 ID、分片顺序和现有 Range 下载方式。
4. 完整响应通过 `X-Drop2Tunnel-Telegram-Chat-Id` 传回确认的数字 ID。浏览器收齐字节并写入、验证完整缓存后，更新本机文件及同文件的单文件 / 合辑传输记录中的 `telegramChatId`。
5. 短响应、下载失败或缓存校验失败不迁移；Range 响应携带的标注也不能单独触发完整缓存迁移。已经使用数字 ID 的记录不重复改写、不降级回 public 名称。

这个过程只更新 Telegram 来源字段，不改变文件字节、所有权、内容版本、缓存清理标记或 provider 调度，不广播新的传输记录。新收到的 Bot 媒体直接保存 Telegram 返回的数字 Chat ID 和消息 ID；网盘新上传 / 备份目标若配置为 public 名称，会先解析数字 ID 再创建记录。内容管理的托管频道排除规则同时识别字典中的数字 ID，避免频道移除 public 名称后误采集自身存储消息。

## 改为私有之前

先填写并验证映射，部署新服务与前端，让需要回源的浏览器逐步迁移。字典兼容不会主动扫描或强迫已缓存的浏览器重新下载，离线设备也不能被提前迁移。永久保留历史名称映射可以继续支持这些旧浏览器的下一次回源。

网盘 SQLite 中现存的托管频道标注，仍可停服后使用 `tools/change-tgdisk-channel-id.cjs` 批量迁移；此工具与字典兼容各自解决不同数据范围。字典不替代 Bot 在私有频道中的成员 / 管理权限，不转换邀请链接，也不会更换现有 file_id。
