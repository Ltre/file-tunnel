# 视频画面提取与多媒体收藏

后台入口：`/media-library`。需要本站管理员登录，与网盘前台是独立页面。

## 首次配置

1. 在 `/disk` 登录将要授权的网盘账号，再回到子系统。
2. 分别选择工作区与正式收藏的账号、分区、原生目录。两者不能是同一账号同一分区下的同一目录。
3. 明确点击“授权并保存位置”。这是子系统用于关页后继续处理的持久访问授权，可在设置页单独撤销；不会将浏览器 Cookie 或 S3 密钥写入任务 URL。
4. 设置两类缓存的目录、容量、期限，并执行基础设施检查。默认使用项目 `.tunnel-data/cache` 下的专属目录。

服务端网盘对接使用同进程适配接口。FFmpeg 读取媒体通过短期 `127.0.0.1` 范围读取地址，不请求外部站点域名。业务数据单独持久化到 `.tunnel-data/media-library.sqlite`（WAL），不修改网盘数据库 schema。

工作区账号决定本子系统当前展示的数据范围。切换工作区账号前须完成或取消进行中的任务；旧账号的日志及文件保留，切回该账号可以继续查看和管理。正式收藏可明确授权到另一个账号的原生位置，不会凭工作区账号身份越权写入。

## 导入

- SNS / YouTube Premium：选择已完成且服务端成品仍在的任务。子系统不重新下载；后台转存工作区后才标记就绪。
- SNS / YouTube 链接：先建立导入记录，再跳转原下载页面创建任务。页面自动关联任务 ID；下载完成后服务器继续转存，浏览器可以关闭。关联暂时失败时刷新原下载页重试关联，不必再次创建任务。
- 已有网盘文件：经当前登录账号确认后直接引用，原件和其生命周期不归子系统管理。
- 本地上传：必须等文件完整到达服务器，后续由后台继续；字节尚未传完时关页会中断接收。

重试先核对确定的网盘成果。若先前写入仍处于恢复或结果未知状态，不会重复发送另一份；请先查看原网盘恢复任务。工作区默认从就绪时保留一年，可以续期。

## 提取会话

同一视频可以建立多个会话，重复进入继续筛选。每次提取形成批次，保留参数与日志。

- 等间隔：指定范围与间隔；每批最多 500 张。
- 随机：指定一个或多个范围与张数。间隔是可选约束，留空时不使用固定等间隔取帧。
- 时间支持秒、`分:秒`、`时:分:秒`，可以含毫秒。重叠范围先合并，候选不足时返回实际数量。
- 请求时刻和实际解码帧时刻分别记录，不能视为相同。日志可按实际播放时刻或提取时间排序。
- 暂停播放器，通过按钮或左右键查询实际帧时刻微调，设置 Clip 起止点。快速模式会调整切点，不保证任意毫秒精确；精确模式重新编码并校验音画轨道与解码。
- 源编码不支持浏览器播放时，可先生成兼容 MP4 工作片段；该片段供范围内后续取帧和裁切复用。工作片段最长一小时。

相似度先用感知哈希初筛，再比较归一化灰度像素。可比较当前会话、同视频全部日志、已收藏画面和上传的参考图。结果只是提示，不自动判断人物身份、不自动删除相似画面。

## 正式收藏与分类

点击收藏只是创建转存任务，确认网盘存储后才标记已收藏。工作区、会话、候选缓存清理不会级联删除正式收藏。已有外部文件可以仅建立收藏引用，也可以独立转存。

人物、组织、标签支持多重关联和别名，人物与组织关系可以记录加入、离开日期。资源失效时保留来源和分类，显示当前不可用。

“移除收藏记录”保留网盘文件；“删除收藏及其网盘文件”仅删除本系统持有的逻辑文件，外部原件受保护，其它共享内容引用不受影响。

## 缓存与状态

- 两类缓存分别按期限、最近使用和容量管理；执行中的任务会保护其文件。
- 缓存清理保留取帧日志，失去候选文件的记录显示“缓存已清理”。
- 自动清理每 15 分钟检查一次，系统状态也提供主动清理。
- 来源或存储授权失效时暂停，不能悄悄切换到其它账号、分区或后端。
- 撤销后，在设置中明确重新授权原账号、原分区和原目录，可以恢复该位置旧记录的授权，再手动重试失败任务。授权到其它位置不会自动搬迁或改写旧任务。
- 后台采用单任务媒体队列、受限 FFmpeg 线程和进程超时，尽量降低对网盘及隧道的资源影响。
- 服务重启只恢复已经退出的工作进程持有的任务；活跃进程的租约不会只因耗时长而被抢占。

实际同步感受仍受源媒体质量、编码器、网络与播放器影响。错误结果不能仅凭文件存在或进程退出成功判定合格。

SNS/YT 原下载流程继续负责抓取，仅在指定片段时增加关键帧裁切和共享的轨道、时长、DTS 连续性及完整解码校验。精确裁切与流复制的切点差异参见 [FFmpeg 官方说明](https://ffmpeg.org/ffmpeg.html)；`--force-keyframes-at-cuts` 的开销与局限参见 [yt-dlp 官方文档](https://github.com/yt-dlp/yt-dlp#usage-and-options)。这些校验不能识别所有源文件中已经存在的感知音画失步，源片段无法可靠解码时仍会报错，不会自动标成成功。
