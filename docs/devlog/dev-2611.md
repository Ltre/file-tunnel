### 第 1 项：A 的记录临时出现在新隧道 B

**证据及根因：**

- 两个版本都存在同一发送端问题：`emitToReadableSessionDevices()` 遍历 A 的成员，却用全局 `deviceSockets.get(deviceId)` 取目标连接。同一设备新连接进入 B 后，全局映射已经指向 B，但旧 A 的成员记录在连接关闭被识别前仍可能保留；A 的延迟历史广播因此会发给 B。另一标签页仍在 A 时也可形成同样的映射差异。
- 用实际服务端函数构造 A/B 两个连接、相同设备 ID，修改前断言应发送到 A，实际发送到 B。没有以“输入文字”直接触发广播作为结论；现场输入时刻可能正好与迟到广播重合。
- 客户端原先收到历史后，只按消息 ID 查询 IndexedDB。即使查出的是 `sessionId=A` 的旧记录，也会加入当前 B 的界面，并把原快照中的文件排入缓存恢复。65 条 A 缓存记录的隔离复现中，B 实际渲染 65 条、没有产生 B 的记录副本，符合重新进入 B 后又为空的表现。
- 该具体复现是临时错显，不能据此概括所有错误快照都不会持久化：原先遇到本地尚未存储的记录时，会按当前隧道写入。因此发送和接收两端都补了归属边界。
- 修改前 `tests/history-scope-261102-2.test.cjs` 最初五个客户端场景中四个失败、合法 B 场景通过；随后独立执行发送目标场景，也以“实际 B、预期 A”失败。不是只检查静态源码字符串。

**实际修改：**

- 服务端共同广播函数改用本隧道成员记录的 `socketId` 查找活跃 Socket，并核对设备身份。保留原有读权限和排除发送者规则；旧连接失效时，不再退回另一个隧道的最新设备连接。这个共同入口也用于记录新增、更新等广播，避免逐个事件打补丁。
- 首次快照、定时广播、历史合并及空快照均附带 `sessionId`，不改变历史全文加载或可选 revision 协议。旧客户端可以忽略新增字段。
- 客户端在快照进入队列及处理时拒绝明确属于其它隧道的包；逐条核对记录及已有缓存的隧道归属。旧服务器没有归属字段的快照仍兼容，但不会借用 IndexedDB 中其它隧道的同 ID 记录。
- 处理过程中捕获发起隧道，等待本地存储后重新核对当前隧道；写入和 ACK 使用捕获的身份。删除标记也不能删除已知属于其它隧道的记录。只把本次接收的有效记录安排到后台恢复；排队后隧道已经变化的恢复记录跳过。
- 对完全没有归属信息、且本地从未见过的旧服务器记录，客户端无法仅凭消息正文推断来源；本轮服务端定向修复和明确的快照归属共同封闭了本次误发路径，未把兼容旧包描述为万能的归属识别。

#### 无头浏览器、代理及资源边界

- 新增 `server/twitter-post-browser.js`，仅由用户发起的 X 帖子转换中、前序结果仍不完整时按需使用；不接入后台历史自动扫描，不常驻、不后台播放媒体，全进程最多一项浏览器补救任务。
- 使用本机已有 Chrome/Edge/Chromium，默认自动查找常见安装位置，可用 `SNS_X_BROWSER_BIN` 指定。**不会自动下载浏览器**，服务器未安装可用浏览器时给出缺失资源错误，不能据此承诺所有环境均能使用最后一层后备。
- 每次使用隔离的临时目录和无痕浏览上下文，Cookie仅进入该上下文；不加载、修改用户的浏览器配置或账号。抓取完成后关闭子进程、销毁上下文及临时目录。实测结束后 `tunnel-x-reader-*` 残留目录为0。
- 只允许 X 及指定静态/API域名的 HTTPS 请求，阻止任意外站、私网 URL、文件协议及媒体/图片/字体正文下载；此浏览器仅取结构清单。保留浏览器原生沙箱，单页读取默认22秒、上限30秒，启动/协议命令单独有时限，传输量超过24 MiB阈值停止加载，响应体及协议消息也有上限。
- 新发现并复现一个真实部署问题：`NODE_USE_ENV_PROXY=1` 且 `NO_PROXY` 为空时，Node原生 WebSocket 将连接本机 Chrome 的 CDP 控制流量送入出站代理，约5秒后 `SNS_X_BROWSER_CONNECT_FAILED`。
- 最终复用项目原本已随 Socket.IO 安装的 `ws 8.21.0`，在 package/lock 中显式声明同一版本；没有升级其它包，也没有增加 Puppeteer/Playwright 运行时。仅 CDP 环回连接使用专用 `http.Agent({ proxyEnv: {} })`，不改变任何全局代理变量或共享代理对象；浏览器访问 X 仍走原代理。离线 `npm install --package-lock-only --ignore-scripts` 校验通过，两个依赖文件只各增加该一项声明。
- 原生 CDP 接口依据 [Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/tot/Target/)；WebSocket 专用连接参数依据 [ws 官方 API](https://github.com/websockets/ws/blob/master/doc/ws.md)。仅使用现有合法 Cookie 及平台实际返回内容，未实现自动登录、验证码绕过或账号权限扩张。
