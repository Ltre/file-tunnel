## 3. 新增或实质扩展的功能

### 3.1 串流台：从没有该子系统到完整的台、节目及观看/操控流程

- 新增串流台发现、我创建的、我收藏的，以及台的创建、上线、下线和基本信息管理。
- 新增节目单和来自本机文件、网盘、隧道记录的来源适配；支持视频、音频、图片、TXT、Markdown、富文本等可展示内容。
- 新增独立观看与操控界面、播放/暂停/停止、进度定位、节目切换、播放起点/时长检查、全屏及后台小窗。
- 新增公开/邀请访问、定向邀请、有效期、撤销、踢出及台归属账号校验。
- 新增供源在线状态、读取授权、来源定位、封面、缓存和来源变更检查。
- 串流有独立的范围读取、缓冲及供源模块，不等同于隧道文件整体同步。不能将两套传输模块的策略混写。

主要实现：`server/streaming-*.js`、`client/streaming-*.js`。

### 3.2 独立媒体库、画面提取与收藏

- 新增管理员媒体库 `/media-library`，独立数据库、工作区和任务状态。
- 新增本机、网盘文件和下载成品的媒体来源接入，以及预览/分析。
- 新增逐帧取图、截图、Clip 截取、时间轴、候选结果和正式收藏。
- 新增人物/标签、片段备注、按提取会话归档的收藏目录。
- 新增压缩版本、缩略图、排队占位、版本下载和转存，Clip 使用持久编号。
- 新增截图连续预览、方向键/触摸切换，以及候选截图/Clip 及其关联产物的安全删除。

主要实现：`server/media-library/`、`client/media-library.js`。

### 3.3 网盘分区、静态开放与跨作用域操作

- 新增稳定分区 ID、显示名称、分区设置、切换、复刻和删除流程。
- 新增按账号/分区管理的静态资源开放、签名静态链接及管理入口。
- 新增跨目录、跨分区及适用的跨账号复制/移动、目标树选择和操作结果。
- 新增文件/目录属性、传输记录、操作明细及更完整的状态反馈。
- 新增回收站、还原及永久删除的区分。回收站保留内容引用，不能按永久物理删除处理。

### 3.4 网盘协同、挂载、目录上传和文件编辑

- 新增文件/目录协同邀请、成员、角色、邀请链接、撤销及管理页面。
- 新增将他人的协同项目挂载到自己的网盘、原地浏览、移动/移除挂载及挂载内路径导航。
- 新增递归目录上传、多级目录创建、同批及目标目录重名确认。
- 新增纯文本、Markdown、十六进制编辑及撤销、未保存状态、分段读取/编辑和写时复制相关处理。
- 新增网页工坊从网盘选择资源/目录导入的连接流程。

### 3.5 网盘多账号和可恢复转存

- 新增浏览器多套独立网盘账号会话、通用“登录 / 移除账号”界面及明确账号选择。
- 新增登录完成回执、跨页面/弹窗的交接和账号切换期间的状态保护。
- 新增携带账号、分区、路径和任务来源的网盘定位/保存结果入口。
- SNS/YouTube 成品转存新增服务端文件描述符和幂等预约，浏览器保留可恢复待办，而非承载整份文件正文。
- 已接受的后台转存或备份任务可以继续执行，关闭发起页面与取消业务任务分开处理。

### 3.6 共享 Content Object 与内容生命周期

- 新增逻辑文件、物理 Content Object 和 Telegram Anchor 的分层。
- 新增内容哈希、浏览器持有证明、内容复用、引用/租约、清理任务及删除代次隔离。
- 新增后台 Content 查询、引用关系、物理清理和迁移工具。
- 不同逻辑文件可以复用已授权且已证明的物理内容；这不等于知道文件名或哈希即可获取其它用户内容。

主要实现：`server/disk-content-repository.js`、`server/disk-content-proof.js`、`server/disk-content-admin.js`。

### 3.7 本系统网盘的 S3 兼容接入

- 新增 S3 管理页面、Access Key/Secret、签名校验、对象列表和对象读写等兼容接口。
- 接入映射到系统已有账号、分区和目录作用域；新增分区级凭据及配置。
- 增加 S3 错误、限流、签名、目录语义和 FolderSync 诊断工具。
- S3 对协同挂载保留只读边界，不因挂载或知道路径而取得远端修改权。
- 这是让 S3 客户端访问本系统网盘的接口，不应描述成新增一个通用外部 S3 网盘客户端。

### 3.8 Telegram 上传与多目标转发

- 新增增长文件读取和渐进分片推送：浏览器继续上传时，Telegram 可消费已落盘的分片数据。
- 新增上传调度、远端字节进度、临时消息/最终关联、失败分类、重启恢复及清理记录。
- 新增多目标 Telegram 转发任务、逐目标进度、取消和撤回的独立语义。
- 新增频道 Chat 字典、历史来源/频道 ID 迁移和检查工具。

### 3.9 系统数据备份

- 新增 `/system-backup`，将系统数据备份到选定账号/分区/目录。
- 新增 SQLite 一致性快照、普通文件稳定拷贝、清单、哈希和大文件分段。
- 新增后台任务进度、取消、重试和丢弃残留任务。
- 临时下载/上传缓存不作为全部系统数据备份的必选内容。
- 当前有备份与恢复说明，不应扩写成已经提供“所有数据库和文件构成同一事务的一键在线恢复”。源码明确不同文件/数据库不是一个全局快照事务。

### 3.10 隧道准入、权限和后台管理

- 新增长期隧道标识、可轮换短码和已登记设备签名凭据之间的明确分工。

- 新增更独立的隧道/设备权限管理页面，以及默认、自定义、管理设备等模式。
- 扩充网页 ZIP、全局对讲、群语音等权限的显示/管理。
- 后台从集中页面扩展为布局侧栏及设备、磁链、隧道、权限、媒体库、备份、S3、出口等独立入口。
- 新增磁链分享/真实下载事件持久统计及隧道删除后的撤销。

### 3.11 上游服务多出口管理

- 新增 Telegram、YouTube、X/Twitter、Facebook、LINE、Instagram、TikTok、Bilibili、网易云及其它服务的独立出口配置。

### 3.12 下载表单、本地日志和控制中心

| Telegram 查询 | 空闲转发历史共享缓存/节流，执行中进度继续更新；收起界面不停止发送。 |
| 媒体提取 | 合并帧解码/签名工作；尾帧缺失时寻找真实前一帧，减少重复解码，避免伪造时间点。 |
| 数据持久化 | 网盘元数据使用 SQLite WAL/事务；infra 从完整 WASM 导出转为原生 SQLite，减少整体快照和关闭句柄风险。 |
| 后台任务交互 | 分类/翻页加载图标及毛玻璃反馈、删除成功后侧滑、标记确认、表单输入保护、任务日志尾部和更新反馈。 |
| 限流与错误解释 | 将信令和业务消息计数分离；对本地限流、外部依赖、目录/权限/上传错误给出更具体来源与状态。 |
| 抓取与下载 | 扩展手写格式、截取范围、文件命名、音乐艺术家/标题、来源元数据补充；保留既有候选媒体格式缓存。 |

这些是实现层面的优化。除明确列出的实测范围，不把它们统一等同于真实手机、VPN 或所有外部服务都已得到性能提升。

## 5. BUG 修复及状态修正

以下列的是已存在对应修正的缺陷类别，不是“全部场景最终验收通过”的清单。

| 类别 | 已修改的问题 |
| --- | --- |
| 记录与隧道隔离 | 迟到记录/历史进入错误会话、删除记录被旧响应复活、退出后重渲染状态不一致。删除标记及异步作用域得到保护。 |
| 文本/记录交互 | `existingMessage` 未定义、编辑器输入状态、复制缺少文件名、不同多选入口不一致、Esc/Shift 行为缺失。 |
| 缓存覆盖 | 恢复请求写入无正文元数据时覆盖原完整缓存；现在在写事务内读取最新内容并保护正文，明确清理另走显式语义。 |
| 缓存恢复来源 | 转发来源字段在资源清单/排队/供源广播中丢失，造成错误来源请求；恢复时保存记录锚点和源授权上下文。 |
| 磁链 | 已有本机缓存仍停在 0%、下载按钮不启用，以及部分历史链接/统计的持久性与授权问题。 |
| 文件传输 | 已耗尽的失败尝试未释放、迟到完成/正文污染新尝试、过期范围启动报错、分片完成误作整文件完成。详见第 7 节。 |
| 局域网 IP 上报 | ICE candidate 正则未跳过 priority 字段，真实候选无法识别；修正的是设备信息/附近设备依据，不是新建一套私网文件连接。 |
| 网页发布/回源 | 发布后状态、旧草稿关联、连续编辑失去转发来源证明、必须切回源隧道才回源、同源锚点更新与版本问题。 |

## 6. 移除了什么，哪些只是改名/替换

### 6.1 相对基线确实移除的界面支持

1. **Graphite 主题**：基线可选，现在不在七主题列表中。
2. **波斯语界面支持**：基线语言列表含 `fa`，当前删除，新增 `de` 德语；当前仍是 16 种语言。用户保存的波斯语内容没有因此被禁止或改写。

### 6.2 删除了旧实现方式，功能由新方式接替

- 前台生产页面不再把完整中央翻译目录作为启动语言包全量加载；源目录仍保留，生成启动包和单语 JSON。
- 分散的翻译词条/语言规则集中到中央目录；部分旧资源保留兼容桥接，并非删除国际化。
- infra 的 WASM 数据库整体导出路径被原生 SQLite/WAL 替代；网盘旧 JSON 主存储被 SQLite 数据仓库及迁移替代。兼容读取/迁移不能等同于仍以旧主存储工作。
- 新的 SNS/YouTube 成品转网盘流程不再先把正文下载至浏览器再传回服务端；浏览器待办、目标选择、版本/授权和回执仍保留。
- 原集中后台及首页的部分内联代码被独立页面/模块接替，页面行数减少不是对应功能被删除。
- 发送分片的 100% 不再直接结束整个文件进度条；临时复合进度标签在当前未提交版本中撤掉。

### 6.3 不是删除功能的改名

- 网盘“下载并缓存”改成“下载”，原下载和缓存行为保留。
- 串流“我订阅的/订阅时间/取消订阅”统一为“我收藏的/收藏时间/取消收藏”，原 bookmarks 数据和逻辑保留。
- “默认节点设置”改为“上游服务出口设置”；最终采用纵向选项卡，而非曾试过的卡片瀑布布局。

### 6.4 净差异和中间撤回的区别

- 本次执行的基线至工作区 `--diff-filter=D` 检查没有已跟踪文件整项删除；上述属于选项/行为/实现路径的移除或替换。
- 历史中尝试过有界历史、延迟历史渲染等方案，当前前端已不采用：继续正常完整渲染缓存历史，不以视口可见性作为文件恢复前提。不能把这些试过后撤回的方案列成当前新增优化。
- 不把用户保留在其它分支或暂存记录里的失败产物，当作当前工作区的实现。

## 7. 传输链路专项：经历了什么，最终与基线差在哪里

### 7.1 首先区分四件事

1. **信令**：经服务端交换 offer/answer/ICE。
2. **实际连接**：原生 PeerConnection 最终选择哪对候选及哪个文件通道。
3. **文件任务**：全文件/多源范围、授权、请求、失败、重试和缓存完成。
4. **显示和诊断**：进度条、线路标签、统计采样及操作日志。

这些层次相互影响，但某层出现变化，不能被概括成整套 P2P 算法换掉；反之建链区相同，也不能说文件层完全没改。

### 7.4 最终与基线的行为差异

| 层次 | 基线 | 当前最终实现 |
| --- | --- | --- |
| 服务端信令限流 | `signal` 使用业务消息的 `checkMessageRate()`。 | 单独 `checkSignalRate()`，业务突发消息不直接消耗同一份信令额度；仍有独立有界限流及诊断。 |
| 跨隧道文件授权 | 请求携带来源隧道定位信息，授权组装较少。 | `sourceAuthorization()` 提供源设备身份、访问凭据和记录锚点；仍校验源权限，不因转发拿到额外访问权。 |
| 队列中的来源 | 发现/广播可能用较少的传输元数据覆盖原来源上下文。 | 合并传输字段，保留 `backupSourceSessionId` 等来源，排队之后仍能找到原锚点。 |
| 背压失败结束 | 部分明确耗尽的等待只上报 failed，未关闭对应文件通道；接收端可能仍等待原 P2P。 | 对既有等待已经失败的特定停滞/超时关闭该文件通道，保留共享 PeerConnection，使用 5 秒冷却和原重试调度。 |
| drain timeout | 未纳入上述明确放弃路径，可能直接进入一般 Relay 尝试。 | 纳入匹配 attempt 的明确放弃/后续重试；不让旧活动通道无限占着接收任务。 |
| 接收方释放 | 活动 P2P 对普通 failed 保持谨慎，容易继续等原接收期限。 | 额外识别经服务器核验的 `abandonedAttemptId`，仅释放同请求、同供源、同尝试；普通 failed、陌生/旧通知不强制打断。 |
| 失败进度 | 若干失败路径用 100% 清除上传 UI。 | 使用结束/空闲回调，不把失败显示成成功；范围失败也不直接清掉仍在进行的整文件行。 |
| 迟到正文/完成 | 部分旧供源或旧接收对象完成后可能继续影响新尝试。 | 检查供源、attempt 和对象身份；等待队列/持久化后再次核对；忽略的完成返回负 ACK，不伪报成功。 |
| 迟到范围启动 | 已完成/重试后的范围可能走到 Invalid multi-source range metadata。 | 先按当前范围和请求身份拒绝为 stale；活动范围的起止边界仍严格检查。保持 120 字符 request/attempt 兼容。 |
| 服务端 Relay 拒绝 | 多种生命周期拒绝进入异常日志；迟到清理可能误删新实例。 | 分类记录并返回失败 ACK，清理限定本实例；already-cached 保持幂等跳过成功，未知/传输异常仍显式报错。 |
| Relay 完成 | 已等待接收端完成 ACK。 | 继续等待同类 ACK、相同 90 秒期限；新增失败阶段、耗时及关联字段，不是新加了“才等接收方”。 |
| 多源进度出现 | 清单阶段就可能出现 0% 行。 | 取得/接受实际范围后显示，发现意图和空队列不冒充已开始传输。 |
| 多源发送百分比 | 范围百分比及范围完成回调可控制整文件行，造成 99%/100% 循环。 | 按文件和接收设备归组，唯一范围累计；P2P 使用接收端整文件已收字节，范围结束不完成整文件。 |
| 进度反馈 | 无当前新增的整文件接收进度报文。 | 可选 `file-asset-progress`，校验文件/范围/attempt 和数值；中间最多每通道 5 次/秒，不参与路由或超时延长。 |
| 整文件 100% | 发送端范围 ACK 容易被 UI 当成整文件完成。 | 完整缓存公告，或整文件持久化成功后的反馈及原完成 ACK，才结束整文件行。 |
| 旧端/Relay 进度兼容 | 原传输。 | 原传输仍可用；无整文件反馈时只累计本机供给的唯一范围，不把它冒充多源接收总量。 |
| 进度内存/重连 | 没有新增的整文件上传显示状态集合。 | 最多 64 组、90 秒空闲 UI 清理；重连保留，明确取消清除；这些期限不是传输取消/降级期限。 |
| 实际路径诊断 | 没有 `capturePeerRoute()`。 | 最多 32 个对端采样槽、同对端至少 5 秒、pending 去重，异步读取地址/协议/RTT/连接字节，统计失败不使传输失败。 |

关键区别：**调度常量和原生 ICE 代码相同，不等于信令额度、授权、失败释放、迟到隔离和进度都相同。当前与旧版之间也不是“只换了进度条样式”。**

### 7.5 与传输相关、但不属于 ICE 算法的缓存/上层变化

- 缓存元数据写入现在保护事务内最新的完整正文；明确清理才删除正文，恢复请求本身不作为清理理由。
- 资源浏览器、批量还原、磁链、SNS 服务端文件恢复及跨隧道记录请求，修正了来源、身份和缓存判定的连接方式。
- 对象 URL 的释放与页面/播放器实际引用分开，避免缓存还在但预览引用先失效。
- OPFS 探测和读取等待改进，不代表启用新正文 OPFS 写入：该开关在基线和当前都为 false。
- 新增串流范围供源、Telegram 渐进上传、S3 读写和上游代理出口属于其它管线；它们没有取代隧道文件 DataChannel/Socket.IO Relay 协议。

### 7.6 如何理解目前两台电脑供源时的 P2P/Relay 并存

- 多源文件的两条供源连接独立。一台电脑到手机走 P2P、另一台到手机走 Relay，在当前和原多源模型下都可能存在，不等于同一个范围同时双发。
- 现有策略在某个对端 P2P 失败后可能进入 5 秒冷却，期间该对端新请求可能走 Relay；另一台供源的状态不因此同步变化。
- 用户 115384320 字节文件的所附电脑日志可辨认 27 个范围请求、24 次 P2P 范围完成和 1 次背压失败。这支持分析进度口径和失败路径；折叠日志没有提供另一台电脑全部具体 reason，不能把每个 Relay 都归因于这一处失败。
- 手机关闭代理、同局域网/同网段是现场条件，不单独证明每次 ICE 选中的地址、UDP 路由或文件通道都一致。
- 当前原生建链代码和旧版相同这一事实，既不能否认现场问题，也不能单独证明所有变化都与上层修改无关。

## 8. 非隧道功能与隧道传输的耦合

### 8.1 这里的“耦合”具体指什么

不能仅按页面名称判断是否影响隧道传输。有的独立功能直接生成隧道记录、调用文件恢复或登记供源；有的只共享同一份文件缓存、账号/隧道授权、服务器文件、Socket.IO 或数据库；还有的只共享 CPU、内存、HTTP 连接和磁盘。

本节区分这些层次。**存在调用或资源耦合，不等于已经证明它导致现场低速或降级。** 同样，原生 ICE 区相同，也不代表这些上层入口、缓存、授权和资源竞争都与基线相同。

### 8.2 功能—耦合点—传输影响矩阵

| 非隧道功能或独立界面 | 与隧道共享/连接的内容 | 当前代码中的实际作用和边界 |
| --- | --- | --- |
| SNS/YouTube 抓取成品 | 服务端 asset、记录中的文件元数据、本机 files 缓存、供源公告 | 成品可以作为文件进入隧道。浏览器通过 `requestServerAssetWithPeerPreference()` 检查本机缓存、尝试既有供源，再按条件回服务端恢复；完整缓存可 `announce()` 成为新供源。其入口、来源字段或恢复顺序会影响文件从谁取、何时取，不需要改 ICE 就能改变用户看到的行为。 |
| SNS 图文转 Markdown | 帖子任务、图片/视频文件 ID、Markdown 内部资源引用、记录发布/更新 | 生成正文之前必须处理关联媒体，重试复用同一资源身份。附件遗漏、身份不一致或过早清理，会表现为“媒体文件已有但正文仍失败”或预览缺资源；这不等同于 P2P 建链失败。 |
| 网页工坊/ZIP 发布 | 本机资源、文件资产、创建者/编辑凭据、源隧道及消息锚点 | 发布/更新网页会关联文件和记录，编辑回源依赖源权限及可用内容。编辑同步模块本身不加入隧道，也不实现新文件传输；资源正文仍依赖原缓存/供源路径。 |
| 网盘文件转发到隧道 | DiskTunnelAdapter、选定账号/分区/路径、目标隧道、导出文件 | 通过宿主桥接把网盘文件交给隧道发送入口，保留页面当前隧道，不以切换界面代替授权。目标选择、文件物化和待转发恢复会影响进入隧道的文件身份及来源。 |
| 隧道记录转存网盘 | 隧道文件读取/Markdown 归档、账号选择、目录目标、备份关联 | 网盘保存可能先读取或恢复隧道资源，再由 DiskClient 上传；成功后关联备份位置。文件传输进度、网盘上传进度、Telegram 远端确认是不同阶段。 |
| 网盘 Content Object/协同/挂载/S3 | 同一套逻辑文件、物理内容、权限、引用和租约 | 影响隧道导入/导出时资源是否存在、能否读取及何时允许清理。S3/静态链接自己的 HTTP 访问并不自动转换成隧道 DataChannel；有内容引用也不等于获得源隧道访问权。 |
| 串流台读取隧道来源 | 隧道目录/访问证明、messages/files 缓存、外部文件句柄、服务端 Range | `StreamingAppAdapter.readTunnel()` 优先读已有本机内容；必要时可读受限服务端 asset Range。适配器明确不发起 P2P 整文件恢复、不回填缓存、不更改隧道传输调度，也不创建/加入隧道。 |
| 串流台自己的设备供源 | 串流自己的 PeerConnection、范围请求和临时 broker；可能同时使用同一网卡/浏览器/服务器 | `client/streaming-peers.js` 自建 `RTCPeerConnection({iceServers:[]})` 和 `stream-program` 通道。它是新串流范围传输，与 `app.js` 的隧道文件 PeerConnection 不是同一个实现入口；不能把它的无 STUN 配置说成隧道原生 ICE 被清空。两者可以有资源竞争，但没有因此合并成一套文件调度器。 |
| 独立媒体库/FFmpeg | 网盘工作区授权、下载成品、Content/服务器磁盘、CPU、Telegram 队列 | 使用独立媒体任务和缓存，结果可转存网盘，再经既有网盘/记录入口使用。未直接接管 FileAssetTransfer。并行转码/抽帧/上传可能竞争资源，但本次比较没有证明其是手机低速根因。 |
| 文件预览、播放器和远程预览 | 同一 files 记录、Blob/object URL、缓存恢复、文件完整性 | 打开预览可能触发文件内容取得，播放期间又需要保留 URL/缓存引用。过早撤销 URL 会使预览失败，即使正文缓存仍在；错误清缓存则会进一步改变其它设备可用供源。 |
| 磁链独立下载页/资源浏览器 | FileAssetTransfer、本机完整性判定、已保存授权、发现/恢复队列 | 独立下载页本身实例化文件引擎；资源浏览器批量恢复也会发起原文件请求。其进度/授权/清单修正会影响恢复任务，但没有另换一种 P2P 算法。 |
| 账号、OIDC 和隧道权限 | 网盘账号会话、当前任务身份、源隧道 grant、设备身份 | 网盘会话和隧道 grant 不是同一种凭据。来源任务必须保持发起账号/作用域，跨隧道文件需对应源身份；错误串用可能表现为资源不可读或恢复失败。账号切换本身不应把后台任务换成新身份。 |
| 通知中心、控制中心、抽屉 | 同一事件循环、真实进度 DOM/状态和 Socket.IO 生命周期 | 控制中心读取/镜像进度显示及真实未读状态，不因多显示一份进度而再传一次文件。重绘/翻译/日志可能增加主线程工作，但不等于调用了第二份传输任务。 |
| 系统备份 | 正在使用的 SQLite、普通文件、网盘后台写入、磁盘和 Telegram 网络 | 备份与文件同步可能同时读写基础设施和占用资源；SQLite 使用快照方法，排除部分临时缓存。备份模块并不负责为隧道选择 P2P/Relay，也不能把备份进度视为文件链路进度。 |
| 上游出口管理 | 服务端外部 HTTP/yt-dlp/必要浏览器请求、抓取成品的源可用性 | 影响元数据/媒体/Telegram 等上游获取。它不会把浏览器设备之间的 WebRTC UDP 或浏览器到服务器的 Socket.IO Relay 改成经过某个 Trojan 节点。服务器上游出口、手机 VPN 和隧道实际文件路径是三件不同的事。 |
| 国际化和 Service Worker | 同一前端主线程、启动资源、动态 DOM、资源缓存和版本 | 可能影响页面何时就绪、显示何时更新以及两端是否运行同版脚本；不能由显示翻译或旧静态资源推断实际线路。新增进度报文保留旧端兼容，不要求清业务文件缓存来升级 UI。 |
| infra、操作日志、审计和后台统计 | 同一 Node 进程、数据库、事件循环、任务身份及持久记录 | 落盘/异常/大量审计可能影响实时处理，所以当前有异步审计和有界诊断。它们会影响证据完整性和资源开销，不能等同于媒体正文经过审计数据库中转。 |

### 8.3 三条必须分清的调用关系

**SNS/YouTube 媒体进入隧道后的恢复：**

```text
抓取任务生成服务端文件
  → 发布带文件身份和来源的隧道记录
  → 浏览器检查现有完整缓存
  → 条件满足时请求已有设备供源（原 FileAssetTransfer）
  → P2P 或 Socket.IO Relay
  → 按恢复条件回服务端 HTTP 取源
  → 完整缓存确认后登记本机供源
```

这是一条组合路径，不表示每个文件每次都必须依次执行全部分支。本机已经完整缓存时不会为了走遍流程而再次下载。

**串流读取隧道内容：**

```text
串流节目引用隧道记录/文件
  → 验证可见隧道及来源作用域
  → 消费本机已有消息/文件缓存或服务端受限 Range
  → 串流自己的范围供源/HTTP 读取
```

这一读取器没有顺便请求“下载整份文件到隧道缓存”，也没有把 `stream-program` 通道变成 `file-asset` 通道。

**网盘和隧道互通：**

```text
网盘导出 → 宿主适配器 → 指定隧道发送入口
隧道记录保存 → 宿主读取/必要恢复 → 固定账号/目录的网盘上传 → 关联备份结果
```

因此，网盘目录、账号、内容引用和上传改动可能影响资源的可用性及前置等待；它们不是隧道 ICE 本体，却仍是完整用户流程的一部分。

### 8.4 相对基线，耦合规模本身也发生了变化

- 基线已经有网盘/SNS/Telegram 与隧道的连接；当前新增了串流、媒体库、Content Object、分区/挂载、多账号、后台直传、系统备份等，来源与消费者明显增多。
- 多个模块复用同一完整缓存和文件身份，减少重复内容；同时更依赖正确的引用保留、来源证明、作用域及异步版本隔离。
- 同一个页面可能同时进行目录读取、进度 SSE、媒体预览、串流读取、文件恢复和 UI 重绘。辅助 SSE 占满 HTTP/1 连接阻塞目录读取是此前已复现的一类耦合问题；不能把所有卡顿都归入该原因。
- `app.js` 仍是多功能组合入口。保留原生 ICE 区域不等于整个 app 和所有上层入口未变；反过来，为恢复一段旧链路而覆盖整份 app 会一并丢掉上述新增连接。
- 本节没有把“存在共享资源”提升为“已测得导致低速”。当前传输现场的每次失败仍要以当次供源、请求/范围身份、降级 reason 和实际候选对判断。
