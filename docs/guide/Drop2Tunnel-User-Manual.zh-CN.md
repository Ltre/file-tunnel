# Drop2Tunnel 普通用户使用手册

> 适用基线：`dev/2608A-NEWCODE`，核对至 `4af5873`（2026-08-12）。
> 本手册面向使用浏览器或 PWA 进行文件传输、消息协作、缓存恢复和多设备同步的普通用户。

---

## 1. Drop2Tunnel 是什么

Drop2Tunnel（即时传输隧道）用于在多台设备之间发送和同步：

- 文字；
- 富文本；
- 文件；
- 多文件合辑；
- 文件夹；
- 协同编辑内容；
- 剪贴板；
- 音频、视频和摄像头内容。
- Telegram 消息中的 SNS 媒体链接。
- 浏览器发送的文字或备注中的 SNS 媒体链接。

它不像普通网盘那样默认把所有文件永久存到服务器。文件通常保存在参与设备的浏览器缓存中，并可从在线设备、原始本机文件或 Telegram 备份来源恢复。

---

## 2. 先理解四个概念

### 2.1 隧道

隧道是多台设备共同加入的传输空间。

每个隧道通常有：

- 5 位隧道暗号；
- 较长的内部隧道 ID；
- 可选的隧道备注名；
- 创建者和默认权限。

### 2.2 传输记录

你发送的文本、富文本、文件或合辑都会形成一条传输记录。

传输记录可以继续保留，即使本机已经释放了文件缓存。

### 2.3 缓存副本

缓存副本是当前设备浏览器中真正可用的文件内容。

“有记录”不等于“当前设备有文件缓存”。

### 2.4 供源设备

持有完整文件缓存或仍能读取原始本机文件的在线设备，可以向其他设备提供该文件。

---

## 3. 第一次进入

打开部署者提供的网址。

路由页通常提供以下方式：

- 输入 5 位隧道暗号；
- 从本机已加入的隧道列表选择；
- 进入最近访问的隧道；
- 创建新隧道；
- 扫描二维码或打开别人分享的隧道链接。

### 3.1 输入 5 位暗号

依次输入 5 个字符。输入完整后，页面会自动查找并进入隧道。

桌面端通常会自动聚焦输入框；移动端不会自动弹出输入法，以免遮挡隧道列表。

### 3.2 创建新隧道

点击“创建新隧道”。创建后请保存：

- 5 位暗号；
- 二维码；
- 隧道链接。

### 3.3 扫描二维码

让另一台设备扫描隧道二维码即可加入，不需要注册账号。

### 3.4 最近隧道

从根地址或 PWA 打开时，应用可能直接恢复最近访问的本机隧道。

---

## 4. 主界面

### 4.1 桌面端

通常分为三栏：

1. 连接设备；
2. 传输记录；
3. 协同编辑。

### 4.2 移动端

底部通常有：

- 连接；
- 隧道；
- 协同。

可点击底栏，也可左右滑动切换。页面会尽量跟随手指移动，而不是瞬间闪切。

### 4.3 顶栏常用入口

可能包括：

- 返回/首页；
- 音乐播放器；
- 设置；
- 暂时离开隧道；
- 强制刷新。

切换隧道前，如果当前有传输任务，系统会提示切换可能中断当前任务。

界面语言可在设置页切换。当前包含简体中文、繁体中文、英语、日语、法语、俄语、西班牙语、意大利语、韩语、马来语、印尼语、越南语和泰语。动态消息也会尽量按当前语言显示；发现残留旧语言时，可先切回目标语言并强制刷新。

---

## 5. 连接和管理设备

“连接设备”区域会显示：

- 本机；
- 当前在线设备；
- 附近设备；
- 已关注设备；
- 设备网络和状态信息。

### 5.1 给设备添加备注

可给远程设备设置本地备注。

有备注时会显示：

```text
备注名(原设备名)
```

备注只对设置者显示。被备注设备只可能协助保存一份不可见备份，不会看到你给它起的名字。

### 5.2 邀请附近设备

附近设备尚未加入当前隧道时，可以点击“邀请”。

对方会收到加入邀请，并自行决定是否加入。

### 5.3 关注设备

关注后可在“已关注设备”中更方便地找到该设备。关注不等于自动获得远程控制权限。

---

## 6. 发送文本

在传输记录区域底部输入文字：

- 按 Enter 或点击发送；
- 多设备会收到同一条文本记录；
- 记录下方的操作入口可查看详情、复制锚点、备注、转发或删除。

如果隧道创建者关闭了“发送文本”权限，普通设备将无法发送。

---

## 7. 发送文件

可通过以下入口发送：

- 点击文件选择区域；
- 把一个或多个文件拖到传输记录底部的文件区域；
- 从设置页选择相关文件工具；
- 在 Android 中使用系统“分享”到 Drop2Tunnel PWA；
- 关联本机文件；
- 发送文件夹；
- 同步目录；
- Telegram Bot。

### 7.1 发送单个文件

选择文件后，记录会先写入传输列表，再在后台准备缓存、预览和供源状态。

### 7.2 发送多个文件

系统会询问：

- 以合辑发送；
- 拆分成多条记录。

桌面端拖放和文件选择器都支持多文件。拖放目录不会被当作普通文件发送；需要发送目录时，请使用设置页的“发送文件夹”或“同步目录”。

### 7.3 合辑

合辑是一条包含多个文件的记录。

合辑支持：

- 宫格预览；
- 合辑备注；
- 下载全部；
- 还原所有文件：只请求合辑内当前设备尚无完整缓存的文件，不重复拉取已有缓存；
- 打开其中某个文件；
- 删除合辑中的单个文件；
- 转发到其他隧道。

### 7.4 Android 系统分享

安装 PWA 后，可在相册、文件管理器等应用中：

1. 选择一个或多个文件；
2. 点击系统“分享”；
3. 选择 Drop2Tunnel；
4. 等待页面载入；
5. 多文件时选择“合辑”或“拆分”。

处理期间，传输记录底部会出现“发送处理中”，显示读取文件、生成预览、写入记录和准备发送等阶段。

不要在处理中立即关闭 PWA。

## 8. 文件是怎样传输的

系统会尽量采用以下顺序：

1. 当前设备已有缓存，直接使用；
2. 从在线设备通过 WebRTC P2P 拉取；
3. 大文件可从多个在线供源设备分段拉取；
4. P2P 不可用时使用 Socket.IO Relay；
5. Telegram 来源文件在没有普通供源时，才使用 Telegram `file_id` 兜底恢复。

因此，看到“正在等待”不一定表示文件丢失，也可能只是当前没有供源设备在线。

### 8.1 传输进度抽屉

有真实任务、排队任务或建链任务时，页面会显示传输进度抽屉；所有任务消失后会自动隐藏。

- 收缩状态显示任务总数以及进行中、停滞、建链中、等待等摘要；
- 点击可展开或收缩；
- 收缩后可按住并拖动位置；
- 展开后点击某个进度条，可定位到对应传输记录；
- 上传使用红色上箭头，下载使用绿色下箭头；
- P2P、multi-source P2P 和 Socket.IO Relay 是实际采用的不同链路标识。

进度暂时停在“建链中”不代表已经开始传文件。如果长时间没有变化，可先确认供源设备仍在线，再检查双方代理/VPN、浏览器权限和网络状态。

## 9. 查看文件和手势

### 9.1 支持网页内预览的类型

主要包括：

- 图片；
- 视频；
- 音频。

文本、CSV、PDF、JSON、XML 等通常显示文件信息和操作按钮，不会在预览层强行读取整个内容，以免大文件卡死页面。

### 9.2 图片和视频预览

在文件预览层中：

- 双击图片/视频：进入全屏；
- 手指上滑：进入全屏；
- 手指下滑：关闭文件预览；
- 在合辑子文件中左右滑动：切换相邻文件；
- 桌面端可使用左右按钮或键盘左右键。

全屏中：

- 左右滑动：切换相邻图片/视频；
- 向下滑动：退出全屏；
- 点击媒体周围透明区域：退出全屏；
- 也可使用关闭按钮或浏览器返回键。

### 9.3 合辑的返回层级

界面层级可理解为：

```text
传输记录 P → 合辑宫格 F → 文件预览 G → 全屏
```

正常返回顺序：

```text
全屏 → G → F → P
```

从合辑宫格进入文件预览后删除文件，应返回合辑宫格；从传输记录直接打开文件，则返回传输记录。

## 10. 音频和音乐播放器

### 10.1 临时试听

打开音频文件时，会显示：

- 封面；
- 文件名或歌曲标题；
- 播放/暂停；
- 进度条；
- 当前时间和总时长。

临时试听会暂停后台音乐队列。关闭预览后，原后台音乐可恢复。

### 10.2 后台音乐队列

点击音符按钮可将当前音频加入音乐队列并进入播放器。

播放器支持：

- 封面；
- 标题、歌手、专辑；
- 播放/暂停；
- 上一曲/下一曲；
- 进度拖动；
- 队列抽屉；
- 收藏；
- 定位原文件；
- 分享和下载；
- 最小化；
- 系统媒体通知控制。

播放到队尾时，系统可从当前隧道的本机音频缓存中随机补充未在队列中的歌曲；它不会只从收藏歌曲中筛选。

音乐队列按设备和隧道隔离。

## 11. 文件记录上的操作

点击传输记录的菜单按钮，可看到部分或全部操作。

### 11.1 详情

在当前页面打开详情浮层，显示：

- 所属隧道；
- 发送设备；
- 文件信息；
- 缓存来源；
- 合辑成员；
- 原始记录信息。

不会通过重新载入页面中断正在进行的传输。

如果记录正文或备注中包含 YouTube、YT Music、TikTok、Facebook、Instagram、Threads、LINE、Twitter/X 等可识别链接，无论记录来自浏览器还是 Telegram，详情浮层底部都可能出现“SNS媒体文件”区域，记录标题旁会显示 `◉SNS`。

在该区域中：

- 可能显示一个或多个独立媒体；
- 播放列表或合集链接会显示为可展开的列表；
- 默认只显示标题、封面、URL 和状态；
- 点击“获取文件内容”后，服务端才开始抓取完整媒体；
- 获取成功后，会在当前隧道中生成一条普通文件传输记录；
- 新生成的文件记录可以像普通文件一样预览、还原、下载、释放空间或转发。

YT Music 链接只获取音频。获取完成后会尽量写入曲名、艺术家、专辑、年份和来源 URL，裁掉封面左右黑边并嵌入方形封面，最终文件名通常为“艺术家 - 曲名.m4a”。普通 YouTube 链接按视频处理，不会因为使用同一套下载器而一律生成 M4A。实际清晰度、码率和格式取决于平台源、部署者的 `yt-dlp/ffmpeg`、cookies 和网络条件。

由“SNS 媒体文件”生成的新记录会保留来源关联，但不会再次显示“获取文件内容”，从而避免递归抓取同一个链接。

### 11.2 复制此锚点

复制一条可定位到当前传输记录的链接。

别人打开链接后，应用会进入指定隧道，并在历史加载后定位和高亮该记录。

### 11.3 备注

给单文件或合辑添加备注。备注会随传输记录同步。

### 11.4 发到其他隧道

将文本、富文本、文件或合辑转发到本机已加入的其他隧道。

转发文件会在目标隧道使用新的文件 ID，避免两个隧道共用同一个缓存键。选择器会记住当前设备上次使用的目标隧道。

### 11.5 删除

删除传输记录。

删除后系统会先从界面和消息库移除记录，再在后台检查是否可以清理孤立文件缓存。

“删除”与“释放空间”不是同一件事。

### 11.6 收藏

收藏分为两层：

- 记录收藏：收藏整条文本、单文件或合辑记录，入口位于记录菜单；
- 单文件收藏：收藏具体文件，入口位于文件预览底部的 `☆/★`。合辑中的每个文件可独立收藏，音乐播放器收藏也属于单文件收藏。

资源管理器的“已收藏”筛选会汇总两类收藏，并分别标记“记录收藏”和“单文件收藏”。

## 12. 释放空间与还原文件

### 12.1 释放空间

“释放空间”会删除当前设备浏览器中的文件缓存，但保留传输记录。

适用于：

- 文件暂时不用；
- 本机存储不足；
- 确认还有其他设备或 Telegram 来源可恢复。

释放后，记录可能显示无缓存状态。

### 12.2 还原文件

“还原文件”会尝试重新取得文件内容。

可能来源：

1. 当前隧道的在线设备；
2. 转发记录所关联的源隧道；
3. 原始本机文件系统句柄；
4. Telegram `file_id`。

### 12.3 不要误解“有记录”

只有文件名、大小和传输记录，并不代表服务器永久保存了文件。

在释放空间前，最好确认：

- 另一台设备已经有完整缓存；
- 原发送文件仍存在；
- Telegram 恢复来源有效；
- 或已经做过“含全部数据”的备份。

### 12.4 强制拉取

当恢复任务卡住时，可以重新发起强制拉取。

为了避免浪费已经完成的传输，若当前进度已超过约 30% 且没有卡住，系统可能阻止强制重拉。

## 13. 外部文件和文件系统句柄

在支持 File System Access API 的 Chromium 浏览器中，文件可能显示：

```text
💾 外部文件
```

这表示应用可以从你授权的本机文件或目录直接读取内容。

### 13.1 特点

- 不一定把完整文件永久复制到浏览器 IndexedDB；
- 其他设备需要文件时，当前设备可从本机文件读取并供源；
- 文件移动、改名、删除或权限失效后，句柄可能不可用；
- 浏览器可能重新询问文件访问权限。

当前策略只为较大文件保留外部句柄；小文件通常使用普通浏览器缓存。

### 13.2 安全副本

句柄文件可能暂时保留浏览器安全副本，直到确认另一台设备已有完整副本。只有句柄而没有任何其他可靠副本时，系统可能阻止释放空间。

## 14. 文件夹、目录同步和本机挂载

设置页中可能提供：

- 发送文件夹；
- 同步目录；
- 关联本机文件；
- 挂载本机目录。

### 14.1 发送文件夹

将文件夹打包或按目录结构发布。

### 14.2 同步目录

监视指定目录变化并更新资源。使用时不要随意撤销浏览器的目录授权。

### 14.3 挂载本机目录/文件

挂载后，资源可作为只读供源，不必把全部内容复制进浏览器缓存。

注意：

- 需要 HTTPS 或 localhost；
- 主要支持 Chromium；
- 单次目录遍历最多约 500 个文件；
- 挂载只存在于授权过的当前设备；
- 其他设备仍会把收到的文件缓存到各自浏览器。

---

## 15. 富文本消息

在协同编辑器中编辑内容后，可以发送为富文本传输记录。

富文本记录支持：

- 图片和文件引用；
- 完整查看浮层；
- 直接编辑；
- 修改历史；
- 版本对比；
- 多设备同步；
- 离线草稿和冲突处理。

### 15.1 版本历史

每次有效修改会生成新版本。历史至少记录：

- 版本号；
- 修改设备；
- 修改时间；
- 版本内容。

### 15.2 版本对比

可选择两个版本，通过双栏只读 Diff 查看：

- `+`：新增行；
- `-`：删除行。

### 15.3 编辑冲突

如果设备 A 离线编辑旧版本，而线上已经更新，重新联网时不会直接覆盖线上内容。

可选择：

- 手动合并；
- 将本地草稿作为新记录发送，并关联原记录。

---

## 16. 协同编辑

“协同”区域是实时共享编辑器。

支持：

- 多设备实时同步；
- 富文本格式；
- 插入图片和资源；
- 固定高度编辑区域；
- 将当前内容发送为富文本记录。

它与“已经发送的富文本记录”不同：

- 协同编辑区是持续变化的共享工作区；
- 富文本记录是传输历史中的一个版本化快照。

---

## 17. 会话资源管理器

从设置页打开“资源浏览器”。

可用于查看：

- 文件缓存；
- 引用位置；
- 合辑引用；
- 富文本和协同编辑引用；
- Telegram 渠道；
- 本机挂载；
- 未引用资源。

### 17.1 引用定位

点击资源的引用位置时，资源管理器会自动最小化，然后定位并高亮对应的传输记录或编辑器位置。

### 17.2 最小化

最小化后会显示可拖动的“资源管理器”悬浮胶囊。

点击胶囊恢复时，会保留：

- 当前搜索；
- 筛选条件；
- 列表内容；
- 滚动位置。

关闭资源管理器后，下次打开会重新扫描。

### 17.3 清理垃圾

“清理垃圾”会查找已经没有消息、合辑、富文本或协同编辑引用的缓存。

执行前请确认重要文件已有其他副本或备份。

资源管理器还支持按 Telegram 渠道、已收藏等条件筛选。记录收藏和单文件收藏是不同状态：收藏合辑记录不会自动收藏其全部成员，收藏合辑内一首歌也不会自动收藏整个合辑。

## 18. 备份和导入

设置页提供“备份/导入”。

### 18.1 元数据备份

保存：

- 传输记录；
- 文件信息；
- 来源隧道；
- 来源服务器；
- 供源设备信息；
- Telegram 等恢复线索。

不一定包含完整文件内容。

### 18.2 含全部数据备份

除记录外，还包含当前设备已有的完整文件缓存，文件会更大。

### 18.3 导入位置

可选择：

- 保留原时间；
- 按原顺序追加到当前隧道末尾。

跨隧道导入时，系统会为文件重映射新的文件 ID，避免两个隧道共用缓存键。

## 19. Telegram Bot 使用

前提：服务部署者已经配置 Telegram Bot。

### 19.1 进入固定隧道中转模式

向 Bot 发送：

```text
/tunnel 12345
```

其中 `12345` 替换为实际 5 位隧道暗号。

进入后，发给 Bot 的内容会直接转入该隧道。

### 19.2 退出中转模式

```text
/leave_tunnel
```

### 19.3 未绑定模式

未绑定隧道时，可以：

1. 先发送文字、文件或相册；
2. Bot 提示输入 5 位暗号；
3. 再发送暗号；
4. 内容成功转入隧道。

也可以选择“放弃发送”。

### 19.4 Telegram 相册和备注

- Telegram 相册会作为合辑进入隧道；
- 单文件 Caption 会成为文件备注；
- Album Caption 会成为合辑备注；
- 已处于固定中转模式时，不再把 Caption 中的 5 位字符误当成另一个隧道暗号。

### 19.5 Telegram 不是首选下载源

Telegram 来源文件一旦被某台设备成功取得，就会成为普通在线供源。

之后的新设备会优先从在线设备拉取；只有没有普通供源时，才使用 Telegram `file_id`。

### 19.6 Telegram 中的 SNS 链接

如果发给 Bot 的文本、单文件备注或 album 备注中包含 SNS 链接，系统会把原备注保留在传输记录中，并在记录详情里提供“SNS媒体文件”区域。

使用流程：

1. 把含链接的内容发送给 Bot；
2. 等待内容进入隧道；
3. 打开该条传输记录的菜单；
4. 点击“详情”；
5. 在“SNS媒体文件”区域点击“获取文件内容”；
6. 等服务端处理完成后，隧道中会出现一条新的普通文件记录。

注意：

- 识别链接不等于已经下载文件；
- 点击“获取文件内容”才会启动完整下载；
- 下载速度和成功率取决于部署者服务器网络、SNS cookies、`yt-dlp` 和 `ffmpeg`；
- 如果平台限制访问、cookies 失效或链接已失效，可能显示获取失败；
- 获取成功后的文件会优先走普通设备缓存供源，不再只依赖原 SNS 链接。

### 19.7 Telegram 大文件限制

Telegram 官方云端 Bot API 的 `getFile` 目前只能下载不超过 20MB 的文件。Bot 收到超过该边界的文件时会直接拦截并发送官方说明链接，而不是先让服务器完整下载后再失败。该限制来自 Telegram 云端 Bot API，不是 Drop2Tunnel 页面中的普通 P2P 文件上限。

## 20. PWA 安装

在支持的浏览器中打开 HTTPS 站点，选择：

- “安装应用”；
- “添加到主屏幕”。

PWA 安装后可：

- 独立窗口运行；
- 使用 Android 系统分享；
- 接收部分通知；
- 缓存应用外壳；
- 快速恢复最近隧道。

Android Share Target 同时兼容 `/share` 与 `/share/`。如果系统分享后看到 `Cannot GET /share/`，通常是服务器、反向代理或 PWA 仍在使用旧版本；先让部署者确认这两个路径均由当前服务端和 Service Worker 接管。

升级后界面异常时，先使用应用内“强制刷新”。

## 21. 隧道设置和权限

点击顶栏齿轮进入设置页。

设置页通常包含：

- 隧道权限；
- 发送文件夹；
- 同步目录；
- 剪贴板共享；
- 清理垃圾；
- 资源浏览器；
- 备份/导入。
- 界面语言；
- 增强局域网 P2P。

隧道创建者可设置普通设备的默认权限，例如：

- 只允许读取；
- 禁止发送文件；
- 禁止删除；
- 禁止协同编辑；
- 禁止全局对讲机；
- 禁止群语音。

权限不仅隐藏按钮，服务端也会检查。被禁止时，页面会提示操作被隧道权限阻止。

### 21.1 增强局域网 P2P

部分 Android Chrome 在 VPN/代理开启时，即使设备位于同一 Wi-Fi，也可能隐藏或改变 WebRTC 的局域网 host candidate，最终只能走 Socket.IO Relay。页面在 HTTPS、检测到同局域网设备或实际走 Relay 后，可能显示一次“增强局域网 P2P”引导。

点击授权后：

1. 浏览器请求摄像头和麦克风站点权限；
2. 媒体设备只会短暂启动；
3. 程序立即停止所有媒体轨道；
4. 不会把音视频上传到服务器或其他设备；
5. 刷新页面后，新建的 WebRTC 连接可能更容易获得局域网候选。

这是对特定 Chrome/VPN 行为的兼容手段，只提高成功率，并不保证一定走 P2P。用户可以稍后在浏览器站点设置中撤销权限；撤销后相关网络环境可能重新降级到 Relay。

## 24. 暂时离开、切换和退出隧道

### 24.1 暂时离开

离开当前页面或返回路由页，但不代表销毁隧道数据。

### 24.2 切换隧道

进入另一个隧道。正在运行的传输任务可能中断，系统会在检测到任务时提醒。

### 24.3 退出隧道

退出会清理当前设备上该隧道的：

- 消息；
- 文件缓存；
- 编辑器内容；
- 本机挂载；
- 本地会话目录记录。

这不等于销毁服务器上的隧道，也不等于删除其他设备的数据。以后重新输入暗号，仍可能重新加入并从其他设备同步元数据。

## 25. 隐私和安全

### 25.1 谁能看到内容

加入同一隧道并具有读取权限的设备，可以接收传输记录。

不要公开分享：

- 隧道短码；
- 隧道二维码；
- 隧道链接；
- 单条记录深链。

### 25.2 文件存在哪里

文件可能位于：

- 当前浏览器 IndexedDB；
- 其他参与设备的浏览器；
- 某台设备的本机文件系统；
- 传输过程中的 Socket.IO Relay；
- Telegram 基础设施；
- 服务端 Telegram 临时目录。

浏览器缓存当前仍以 IndexedDB Blob 为主。代码中虽有 OPFS 驱动和统一 `CacheStore` 接口，但接收侧 OPFS 分块写入目前未启用，不应把 OPFS 视为已经接管全部大文件缓存。

### 25.3 不是完整端到端加密产品

HTTPS 和 WebRTC 会保护传输链路，但当前没有独立的应用层端到端加密体系。

高敏感文件应在发送前自行加密。

### 25.4 清除浏览器数据的影响

清除站点数据、卸载浏览器或重置设备，可能删除：

- 文件缓存；
- 消息；
- 隧道列表；
- 音乐队列；
- 设备备注；
- 挂载句柄；
- 离线草稿。

重要数据请做客户端备份。

## 26. 常见问题

### 26.1 文件名还在，但打不开

该设备只有文件元数据，没有完整缓存。

点击“还原文件”，并确保至少一个来源可用：

- 有缓存的设备在线；
- 原发送文件仍存在；
- Telegram `file_id` 有效。

### 26.2 还原一直等待

可能没有在线供源，或 P2P/Relay 卡住。

可以：

1. 让持有文件的设备保持页面在线；
2. 检查双方网络；
3. 等待 Relay；
4. 在任务明显卡住后使用强制拉取；
5. 检查 Telegram 恢复来源。

### 26.3 释放空间后文件又回来了

可能是你主动打开了下载/还原，或某些旧版本行为自动拉取。当前设计中，仅查看无缓存文件通常不应自动恢复，明确点击“还原”“下载”“下载全部”才会拉取。

### 26.4 外部文件标识消失

原文件可能：

- 被移动；
- 被改名；
- 被删除；
- 浏览器权限被撤销。

重新关联文件，或从其他设备恢复。

### 26.5 麦克风或摄像头不能使用

确认：

- 使用 HTTPS；
- 浏览器站点权限已允许；
- 设备未被其他程序占用；
- 没有阻止权限的悬浮窗；
- 隧道权限允许；
- 当前浏览器支持。

### 26.6 页面像旧版本

点击“强制刷新”，完全关闭 PWA 后重开。仍无效时清理该站点缓存并重新安装 PWA。

### 26.7 切换隧道后传输停止

每个页面一次只专注当前隧道。切换会中断该页面正在进行的任务，这是预期行为。

### 26.8 删除和释放空间有什么区别

- 删除：移除传输记录，并可能清理无引用缓存；
- 释放空间：保留记录，只删除当前设备缓存；
- 下载：把文件保存到系统下载目录；
- 还原：把文件重新取回浏览器缓存。

### 26.9 同一 Wi-Fi 为什么仍显示 Socket.IO Relay

同一 Wi-Fi 只是 P2P 的有利条件，不保证浏览器一定暴露可达的局域网候选。常见影响包括：

- Android VPN/代理应用改变 WebRTC 路由或候选；
- 浏览器对不同 Origin 保存了不同的权限和网络隐私状态；
- mDNS host candidate 在对端不可解析；
- 页面仍混用旧 Service Worker 静态资源；
- ICE、DataChannel 或完成确认超时。

可先尝试：

1. 确认两端页面和 PWA 都已强制刷新；
2. 保持供源设备页面在线；
3. 在 HTTPS 页面使用设置页“增强局域网 P2P”；
4. 刷新两端页面重新建链；
5. 仍失败时接受 Relay 兜底并把日志交给部署者。

---

## 27. 推荐使用习惯

- 重要文件至少保留两台设备副本；
- 释放空间前确认恢复来源；
- 重要隧道定期做“含全部数据”备份；
- 不在不可信隧道开启剪贴板共享；
- 长时间大文件传输时不要切换隧道或关闭页面；
- 外部文件不要随意移动、改名或撤销权限；
- Telegram 重要文件定期执行防失联检测；
- 高敏感文件发送前自行加密；
- 发现 PWA 更新异常时先强制刷新；
- 退出隧道前先确认本机缓存是否仍有唯一副本。

## 28. 术语速查

| 术语 | 含义 |
|---|---|
| 隧道 | 多台设备共同加入的传输空间 |
| 暗号 | 用于加入隧道的 5 位短码 |
| 传输记录 | 文本、文件、富文本或合辑在时间线中的记录 |
| 缓存副本 | 当前设备实际保存的完整文件内容 |
| 供源设备 | 能向其他设备发送完整文件的在线设备 |
| 合辑 | 一条包含多个文件的传输记录 |
| P 层 | 传输记录平层 |
| F 层 | 合辑宫格浮层 |
| G 层 | 单文件预览浮层 |
| Relay | P2P 不可用时经 Socket.IO 服务器转发 |
| 记录收藏 | 收藏整条传输记录 |
| 单文件收藏 | 收藏某个具体文件，合辑成员可分别收藏 |
| 增强局域网 P2P | 通过明确媒体权限改善部分 Android Chrome/VPN 场景的局域网候选暴露 |
| 外部文件 | 通过本机文件系统句柄读取的文件 |
| 释放空间 | 删除本机缓存但保留记录 |
| 还原文件 | 从设备、句柄或 Telegram 重新取得文件 |
| SNS媒体文件 | 从 Telegram 备注或正文中的第三方平台链接识别出的可按需获取媒体 |
| 锚点链接 | 直接定位到某条传输记录的链接 |
