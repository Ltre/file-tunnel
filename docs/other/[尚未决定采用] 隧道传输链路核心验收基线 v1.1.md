# 隧道传输链路核心验收基线 v1.1

> **尚未决定采用。** 根据 [v1.0 草案](%5B尚未决定采用%5D%20隧道传输链路核心验收基线%20v1.0.md)和[历史需求清单](../../prompts/resources/prompt-list-about-tunnel-transfer-261118.md)整理。本文验收普通隧道文件传输、缓存恢复和跨隧道转发，不固定现有实现，也不代表当前版本已通过。

## 一、核心验收项

1. **可直连时优先 P2P，不通时自动兜底。** 正常局域网的单文件、批量传输应能快速开始并使用实际可用的直连。P2P 无法建立或已无法继续时，有可用来源就自动尝试 Socket.IO Relay 等可用兜底，无需重发原文件。代理开关、短暂背压、界面上的「P2P」标签都不能单独作为选路或验收依据。已在正常传输的任务不必因网络条件变好而强制换路。
2. **文件收齐，状态真实。** 核对收到的大小、内容、文件名和集合对应关系。发送进度不能把排入缓冲当作发完；单个分片完成不能当作整文件完成。接收成功以本次操作的文件确实可用为准，缓存恢复要等缓存写入可用。进度要反映实际阶段和路径；只找源时不反复弹出传输条。小文件很快完成可以短暂显示，但不能漏掉实际结果。
3. **批量互不拖死，失败可以恢复。** 慢源、大文件或单项失败不能长期占住队列；有其他合格来源时能继续或重试。允许多来源并行、分片或整文件重试。已成功的文件不因迟到事件再传一遍；旧失败不能覆盖新成功，取消的任务不被旧消息复活。
4. **历史、缓存和隧道归属准确。** 新设备加入能同步本隧道历史；仅有记录不表示文件已缓存。已有有效且有权使用的本地缓存就直接用；缺失时能单项或批量找源，重复点击不堆任务。有可用设备缓存时，SNS 等文件也优先用现有缓存。切换、退出或清理不能串入别的隧道的数据，也不能误删仍被引用的缓存或按规则应保留的安全副本。
5. **转发看目标结果。** 批量按条报告，只有目标侧达到相应结果才报成功。只加入目标隧道的设备可读取、同步已成功转发的文件，无需加入源隧道或获得源隧道访问权；源隧道的其他内容仍受保护。涉及网页 ZIP 时，同一目标隧道内同源副本共用编辑授权，任一副本改动都能同步其他副本并回源，同时保留每条转发记录。

## 二、怎么验收

- **普通改动：** 验证本次改动涉及的场景。涉及传输主链路时，至少对照一次正常局域网 P2P 和一次 P2P 不可用后的 Relay，两者都核对实际路径、文件结果和双端进度。
- **改动选路、调度、恢复或准备发布时：** 按影响补测真实设备。优先选手机代理开关（含不刷新切换）、电脑用 localhost 与局域网 IP 的对照、三设备多来源、批量和 SNS 文件、断线后重试、只加入目标隧道的转发接收。涉及网页 ZIP 回源时，连续改两个同源副本，核对源网页和目标记录数。正式站有问题就用正式站条件复验，不能只用本机结果代替。
- **有性能或完整性疑问时：** 同设备、网络、访问入口和样本下做前后对照，分别看首个有效数据、进度何时出现和完成耗时。可以用几百 KB 小文件、约 40 MB 大文件、45 个文件共约 220 MB 等历史样本；代表文件用外部哈希核对。样本大小、哈希方法和性能降幅都不是统一门槛。记录实测结果和未测环境。

**待决定：** TURN 支持另行验收；启用条件及其与 Socket.IO Relay 的顺序留待确认。诊断时应区分设备直连、TURN 和 Socket.IO Relay。这版不固定超时、并发数、分片大小或性能百分比。
