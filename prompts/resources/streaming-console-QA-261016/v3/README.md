## 首页共存与移动手势约束

- 全屏浮层直接遮住当前首页视口，关闭或收起后原首页仍在原位置，不替换、重建或改写连接设备 / 传输记录 / 协同编辑三栏。
- 首页顶栏沿用当前按钮分布，仅增加一个串流运行与恢复入口；连接设备标题右侧菜单增加串流入口。条件按钮仍按原规则显示。未另造产品总导航。
- 窄屏控制台根节点在原三栏侧滑容器之外，不是第四个横滑栏。控制台内部的滚动、资源拖动、媒体手势与方阵操作只在前景层处理。
- 控制台打开时暂停原三栏手势入口，清理未结束的触点 / pointer capture / 临时位移；返回时恢复原有栏位索引和滚动。不要向首页转发同一次点击或滑动。
- 移动端控制台底部的三个按钮是「收起并打开对应原页面」快捷方式，不给控制台冒充一个三栏索引。从控制台点传输记录只进入传输记录，不触发首页重复点击该按钮的其它动作。
- 控制台与首页分别保留草稿、焦点与滚动；弹层内只保留一个纵向主滚动区，底部操作适配安全区。键盘弹出、横竖屏切换、来源弹层和浏览器权限框打开时重新计算尺寸，不能影响原三栏位移。
- 接收播放、监控、采集与界面焦点分离：切换页面不停止串流或退订。浏览器后台播放与采集仍受实际权限和系统能力限制，异常应明确提示。

## 状态与控制范围

- **观看与订阅分开（Q30／Q31）**：观看不需要先订阅，订阅必须登录，接受邀请不自动订阅；订阅记录本身不是观看授权。订阅列表跟随用户账号跨设备共用，但各设备创建的台、加入的隧道及监控布局仍独立。旧原型中“接受邀请并订阅”等捆绑文案需后续分开整合。
- **随机导入与播放分开（Q18／Q19）**：保留从所选来源范围随机选取并确认导入资源，图 16／17 继续承载这一流程；导入后按手动调整的节目单顺序播放，本期不做随机播放，也不持续从来源范围自动补充资源。此前将图 16／17 一律标为待修正旧示意的说法已纠正。
- 同台共享当前文件、播放 / 暂停和目标进度；各接收端显示实际状态，缓冲滞后单独标识。音量、静音和暂停本机观看独立；恢复时追随当前台状态。
- 监控单格和批量按钮均标注本机观看范围；修改整台共享播放进入单台观看控制，避免无意影响其他接收端。
- 普通设备发现列表按同隧道／已关注设备筛选；Q12／Q32 已确认公开台也可经创作者主页或直接观看链接进入，不要求设备原本可见。仅邀请台仍需有效观看许可；公开转仅邀请时踢出旧接收端，Q38 确认切换前生成的邀请链接／邀请码也一并失效，需要重新发出邀请。下线继续按原规则处理。
- Q7／Q20 按 Q30 的模型更正：邀请自然到期或被主动撤销，只阻止后续凭该邀请取得观看许可，不追溯撤销已获观看许可；终止现有设备访问另用“踢出”。订阅记录独立处理，旧移动原型中“邀请被撤销时，停止接收”的文案需纠正。
- Q23／Q24 已确认：通用邀请链接／邀请码是独立加入渠道，即使接收设备不同隧道、未关注创建设备，也可凭有效邀请加入，普通设备发现范围保持不变；通过设备选择器发送的定向邀请仅限指定设备接受，不能转交给其它设备使用。
- Q33／Q39 最新结论：通用邀请可供多设备多次进入；最初未登录接受，也可在之后登录时通过账号携带订阅及相应观看资格到其它设备，不能限制为首次接受的设备专用。定向邀请只限固定设备多次进入，不因账号登录而扩展。观看与订阅仍分开，邀请到期、撤销及访问限制按既定规则处理。
- Q25／Q26 已确认：定向邀请支持离线送达，接收设备上线后可查看并接受有效邀请，不要求创建者同时在线；到期或撤销时显示实际状态。通用和定向邀请默认自生成起 24 小时有效，生成／发送时可设置其它期限或不过期，不过期邀请仍可撤销。
- Q27／Q28／Q35 已确认：登录后新建台默认归属当前账号，归属用户可在创建设备随时放弃自己台的归属，同时撤销其针对该台授予的特殊操作权限，不因此取消普通观看许可及订阅记录；登录不会自动认领已有无归属台，台配置也不因此同步到其它设备。
- Q29 已确认：节目单修改保存后采用新顺序，仍在列表中的当前节目及进度保持；移除当前项时按新节目单继续，清空节目单则停止并提示。
- Q34 至 Q37 已确认：同一归属用户从 B 打开 A 创建的台，仍使用观看者视图，标明创建者是自己、来源为 A；允许全局播控、下线／公开／仅邀请设置、生成／发送／撤销邀请，以及踢出观看设备和重新允许其加入，不允许修改导入源、删除台或放弃归属等重大管理操作。不能把 A 的台当作 B 本机创建的台或自动导入配置。
- 文件来源可跨本机、网盘、隧道混合；摄像头与屏幕是各自独立的实时来源，不混进文件播放列表。切换来源保留已保存文件配置。
- 本机文件引用失效需重新选择；台配置持久化不意味着浏览器文件权限可无限持久化。实时采集必须发起端授权。

## 261017-3 · 邀请与 Markdown 消息补充

已确认的来源原则：网盘和隧道来源不受串流台创建者离线影响；串流按普通网页方式读取原始来源，不制作保底副本、不冻结来源或阻止删除。来源删除后允许后续播放失效，浏览器已经缓存或缓冲的内容可继续使用。配置持久化不等于另存一份媒体。

[打开补充交互原型](42-invitation-flow.html)（单文件，可直接打开，支持 PC 和窄屏）。原浏览页顶部新增同名入口；移动原型在创建“仅限邀请”台后进入邀请管理，提供“邀请设备”和“转发到隧道”。移动首页菜单的“通知中心”可进入接收端演示。

- 定向邀请：选择创建者可见的设备 → 发送 → 接收设备在自己的通知中心查看 → 接受或拒绝。可附带媒体缩略图，发送结果用有背景色的横向提示面板展示。通知中心无设备切换，发起端无查看对方通知中心的操作；审核导航用于对照不同设备的页面，不是产品菜单。
- 隧道转交：选择目标隧道 → 发送包含说明、链接及可选缩略图的 Markdown 邀请。消息不附带完整串流源文件，也不显示“下载”“上传到网盘”；能看到消息的隧道设备可直接接受，无需另行逐个批准（Q4 已确认）。
- 普通 Markdown：[独立消息示例](42-invitation-flow.html#markdown) 展示约 10 行预览、毛玻璃、展开／收起，以及仅包含正文与作者自行引用的隧道资源的 ZIP 清单。“下载”“上传到网盘”只在此类无特殊用途的消息中显示，按钮不写“下载 ZIP”。该示例与邀请消息分开，不将 Markdown 附件当成串流资源导入步骤。不读取真实 Blob，不发送消息，不生成 ZIP，也不上传网盘。
