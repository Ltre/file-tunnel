# UI-261026 扩展约束细节

方案是：**沿用当前产品的 DOM、布局和业务逻辑，把原型中的 Lumen、Orbit 视觉样式接入现有主题机制；同时分离通用样式与旧主题专属样式，保证旧主题以后可以独立移除。** 本轮仅做了只读核对，未修改文件。

对照了[设计入口](D:/Workspace/github/Ltre/file-tunnel/prompts/resources/UI-261026/index.html)、[皮肤样式](D:/Workspace/github/Ltre/file-tunnel/prompts/resources/UI-261026/assets/skins.css)、[Orbit 修订记录](D:/Workspace/github/Ltre/file-tunnel/prompts/resources/UI-261026/review-feedback.md)及当前源码后，有几处实施基准需要先固定：

- 原型保存的是 **10 月 26 日的静态界面**。此后新增的首页双栏布局、串流小窗、节目单自动定位等，以当前代码为准，补上同套视觉，不能被旧快照覆盖。
- 原型中的 `index.html` 是设计展示器；其导航、示例数据、预览脚本、冻结操作不能进入正式产品。
- 产品当前使用 `body[data-theme]` 和 `uiTheme` 保存选择；原型使用 `html[data-skin]`。正式实现继续使用现有主题机制，避免出现两套互不一致的主题状态。
- 当前旧主题不仅改变颜色，Graphite、Atelier 还包含列宽规则。因此不能让 Orbit 继承 Graphite、Lumen 继承 Classic，再靠覆盖规则拼出来。

实施按以下顺序进行：

1. **先固定当前界面基线。** 记录相关页面及动态状态的控件位置、尺寸、滚动容器、可见条件和交互结果，包含当前未提交修改。
2. **分离主题依赖。** 将通用结构、共同视觉规则、各主题参数划清边界，先确保旧主题显示和行为不变。
3. **接入两款新主题。** 从最终版原型提取颜色、背景、边框颜色、圆角、阴影等视觉规则，映射到当前真实组件。
4. **补齐深层界面和特殊状态。** 覆盖动态创建的浮层、菜单、播放器、任务状态及原型之后新增的组件。
5. **完成视觉、交互和旧主题移除验证。** 最后再接入现有构建及 Service Worker 更新机制。

你提出的第 1 条，以及需要补充明确的特殊要求，整理如下。

**1、控制中心容器内部的磁贴空白处，仍然能够关闭遮罩。**

直接为现有控制中心容器绘制背景、边框和圆角，不为了外观新增一层拦截事件的容器，也不使用真正的表单 `<label>` 包住这些按钮。

当前代码已经按点击位置区分磁贴、隧道选择面板和外部空白。因此首先保留现有判断，验证新外观下：

- 点击遮罩外部空白、磁贴之间空白，以及矩形容器内磁贴周围的空白，都能关闭。
- 点击磁贴、切换隧道面板及其滚动按钮，继续执行原有操作。
- 拖动排序、长按、滑动列表结束时，不误触关闭或磁贴动作。
- 通过控制中心切换主题，仍保持当前控制中心的原有交互方式。

**2、主题不能改变当前布局，也不能恢复原型中的旧布局。**

新主题不设置新的列宽、断点、字体尺寸、行高、控件宽高、间距、排列顺序或滚动规则。

特别保留当前：

- 宽屏三栏、中等宽度双栏、窄屏底部选项卡布局。
- 双栏模式下协同编辑的展开区域及顶栏避让。
- 移动端菜单双列、底部操作栏、视口高度及安全区域。
- 串流编辑页、导入页、观看页的布局和封面位置。

原型的视觉参数可以采用，但不能把快照中的旧 CSS 整体复制回来。

**3、切换主题只能换外观，不能重建业务界面。**

继续通过主题属性更新样式，不重新打开页面或重新渲染工作区。切换时应保留：

- 当前账号、隧道、网盘分区和目录。
- 输入内容、草稿、勾选项、排序及滚动位置。
- 已打开的对话框、编辑状态、焦点和文字选区。
- 正在播放的串流、播放位置、静音、音量及后台播放状态。

不能因切换主题重新提交请求、重启任务、重新连接供源或触发账号切换。

**4、两款新主题必须独立于旧主题，通用组件不能随旧主题一起被删。**

样式依赖按以下关系组织：

| 层次 | 内容 | 删除旧主题时 |
|---|---|---|
| 通用结构 | 布局、尺寸、定位、滚动、显隐、交互状态 | 始终保留 |
| 通用视觉基础 | 完整的语义颜色默认值、组件使用变量的规则 | 始终保留 |
| Lumen／Orbit | 各自完整的主题参数及必要视觉差异 | 独立保留 |
| 旧主题专属规则 | Classic、Graphite、Atelier、Social 的专属外观和现有差异 | 可以分别移除 |

当前散落的 `--text-main`、`--text-color`、`--accent`、`--primary-color` 等变量需要建立一致映射，避免主界面正常、账号对话框却使用错误的兜底颜色。

不进行与换肤无关的大规模 CSS 重构；只处理形成主题依赖或妨碍完整换肤的部分。

**5、所有主题入口的顺序必须一致，但不能强制改掉用户已保存的选择。**

设置中的主题列表、顶栏快捷菜单、顶栏循环切换和控制中心循环切换，统一为：

```text
Lumen → Orbit → Classic → Graphite → Atelier → Social
```

保留现有已保存主题。**列表排在前面不等于强制设为默认主题**，本轮不因此改变现行首次进入的默认选择规则。

同时预留明确的失效主题回退：以后移除某个旧主题后，旧偏好不能导致空白、缺色或变量缺失，应回退到仍存在的主题。

**6、不能用宽泛按钮规则覆盖业务状态。**

原型中有 `.sc-overlay button` 等范围较大的规则，正式接入时需要按组件和状态收窄，分别保留：

- 主要操作、普通操作、危险操作。
- 当前选中、未选中、禁用、处理中。
- 成功、警告、失败、需要重新登录。
- 当前播放、订阅、未读、权限受限等状态。

不能把删除按钮、当前选项、普通按钮全部涂成同一种紫色。Hover、按下和键盘焦点也必须能够辨认，不能覆盖禁用或选中状态。

**7、Orbit 必须覆盖深层组件，不能只让首页变黑。**

重点落实原型已经反馈修订过的区域：

- 隧道设置、权限项及提示文字。
- 资源浏览器的文件名、统计、挂载、引用和状态标签。
- 网盘树形目录选择器、目录菜单及选中节点。
- 账号选择、登录提示、离线身份和任务提示区域。
- 富文本／Markdown 预览、历史和编辑浮层。
- 传输记录菜单、详细数据、备份及清理对话框。
- 通知中心、网页工坊及串流各层页面。

同时检查动态挂到 `document.body` 的组件，以及延迟注入的样式，避免出现“首次打开正常、后打开的对话框又变成旧颜色”。

**8、用户内容和媒体不能被主题重新着色。**

换肤作用于系统界面，不能使用全局反色或滤镜处理整个页面。

图片、视频、串流封面、网页工坊预览、用户网页和富文本中的显式颜色、背景，保持其原意。未指定颜色的正文可以继承主题；作者明确设置的格式不能被统一覆盖。

二维码保留原始图案及必要留白，不反色、不裁切。单色系统图标可以针对性适配，不能连带改变彩色标识和媒体内容。

**9、播放器、小窗和页面内全屏需要独立保护。**

不能让普通面板或按钮样式覆盖播放器的专用规则。重点保留：

- 小窗现有的暂停、声音、关闭及倒计时控件。
- 小窗拖动、点击恢复和按钮命中区域。
- 页面内全屏及横屏切换。
- 静音、音量、暂停、缓冲、错误提示的可见性。
- 节目切换后，节目单在自身可视区域中部定位的行为。

媒体上方的按钮和状态文字需要维持稳定对比度，不能再次出现白底白字。主题也不能给播放器祖先随意增加会影响固定定位或层叠关系的效果。

**10、遮罩、浮层和滚动的关系不能被装饰样式改变。**

保留各类浮层现有的层级、关闭边界和焦点行为，包括嵌套对话框、Markdown 向串流控制台交接、最小化与恢复。

阴影和模糊不能拦截点击、遮盖 toast，或改变固定操作栏的定位。控制中心、目录树、节目单及任务列表继续在原有容器内滚动，不能因为换肤出现额外的整页滚动条。

**11、保留原生控件和现有性能特征。**

不借换肤把原生 `select` 改成新的自绘下拉组件，也不改变鼠标、触摸、长按和拖动处理。

对 Orbit 的原生输入框、选项和浏览器控件设置协调的颜色方案；切回浅色主题时完整恢复。装饰性 CSS 需要具备基础颜色回退，不能因某个效果不可用就导致文字不可读。

重点检查多条传输记录、长目录树、控制中心展开和串流播放期间的重绘，避免叠加大面积模糊、阴影或持续动画。

**12、主题资源更新不能影响业务缓存和后台过程。**

新增样式接入现有资源构建、版本和 Service Worker 更新流程，不清理账号、文件缓存、草稿或业务数据。

主题名称沿用现有国际化机制；不改系统按钮文案和用户内容。后台页面当前具有独立样式，也不接入前台主题切换，不能通过无作用域的样式顺带改变后台界面。

- **视觉对照：** 对照最终版 Lumen、Orbit 桌面及手机截图；原型之后新增的界面按同套视觉补齐。原型已有的静态检查不能替代正式界面的动态验证。
- **几何对照：** 同一数据、视口和状态下，对比换肤前后的控件位置、尺寸、滚动范围及浮层定位，覆盖三栏、双栏、窄屏以及断点附近宽度。
