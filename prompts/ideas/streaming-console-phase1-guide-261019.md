# 串流控制台第一阶段开发指引：文件放送、发现、邀请、用户与订阅

编制日期：2026-10-19。状态：开发前指引，未表示功能已实现或已验收。

依据：[串流控制台 QA](streaming-console-QA-261016.md) 的最新确认结论及其末尾“两阶段开发划分”，界面参考 [v3 原型说明](../resources/streaming-console-QA-261016/v3/README.md)。后续阶段见 [第二阶段开发指引](streaming-console-phase2-guide-261019.md)。

## 1. 阶段目标与依据优先级

第一阶段交付可实际使用的文件串流台：本机、网盘和隧道资源导入，节目单编排与持续放送，普通设备发现，公开及邀请访问，全局用户与台归属，以及账号级订阅书签。不是只播放一个视频的演示版。

规则冲突时，以用户最新明确答复、QA 后续纠正和本次阶段划分为准。QA 早期“设备订阅”“任何观看者均可全台播控”“随机播放”等表述已经被后续结论替代；旧原型中的按钮也不能反过来覆盖最新权限规则。

本阶段不实现摄像头、屏幕实时采集、监控方阵、Plus Mock、创作者会员 Mock 和向他人授予特殊操作权限。但必须先落实普通观看者与归属用户的权限区别，第二阶段再增加能力，不能先让所有观看者自由换节目或全台播控。

## 2. 身份与数据范围先确定

### 2.1 分别保存的业务对象

| 对象 | 作用与范围 |
| --- | --- |
| 全局用户 | 复用原网盘用户的稳定身份，用于全站登录、台归属、订阅及后续会员；不另造一套不相通的用户 |
| 设备 | 保留各自的隧道集合、关注关系和本机台集合；同一账号登录不合并这些集合 |
| 串流台 | 长期存在的台标识、台号及来源设备；不等同于一个播放器或一次媒体连接 |
| 台归属用户 | 可空；记录实际归属，不能根据页面当前账号临时推断 |
| 节目项 | 一次导入编排的独立条目，保存来源定位、顺序和播放参数；不是一份媒体副本 |
| 全局播放状态 | 台当前节目、播放／暂停及目标进度；与各观看端实际缓冲位置分开 |
| 观看许可、邀请和踢出限制 | 分别处理已取得的访问资格、用于取得资格的凭据，以及指定设备对指定台的访问限制 |
| 订阅书签 | 用户账号收藏的台入口；不是观看授权、设备订阅或付费资格 |

台的内部标识必须能够跨设备唯一定位；台号只是创建设备范围内的显示编号。A、B 都有“01 台”不构成同一个台，不能用台号代替权限或节目状态的归属标识。台名称、台号、来源及配置保存后可再次复用。

本机保存完整可复用的台配置及界面状态。服务端只保存对外继续服务、权限判断和重启恢复必要的信息，按设备／台隔离；账号下保存订阅书签等明确属于账号的数据。服务端运行信息不得变成登录后向其它设备恢复完整台配置的云端配置库。

服务端持有台的运行信息、公开索引、归属和观看许可，不等于接收设备取得创建配置，也不等于获得来源资源的管理权限。

### 2.2 创建、认领和放弃归属

- 未登录也可以创建和放送无归属台；观看者看到来源设备而没有创建者用户名，是正常情况。
- 已登录后新建台，默认归属当前账号；归属用户可在创建设备随时将自己的台改为无归属。
- 后来登录不自动认领已有无归属台，只能由用户主动认领。认领或账号切换不能擅自覆盖其它台的归属。
- 放弃归属只在创建设备执行，不删除来源资源，不自动取消已有观看许可或订阅。第二阶段增加特殊授权后，放弃归属必须同时撤销原归属用户针对该台发出的特殊授权。
- 删除台只删除台及其自身配置、服务状态，不删除网盘、隧道或本机原文件，也不要求来源为串流台保留副本。

### 2.3 本机与远程管理权限

| 操作位置与身份 | 可执行范围 |
| --- | --- |
| 创建设备上的无归属台 | 本机已登录或未登录操作者均可管理；远端观看者不能因此取得管理权 |
| 创建设备上的当前归属用户 | 管理自己的台、来源和节目单，以及归属、可见性与访问设置 |
| 创建设备上当前账号与台归属不同 | 仍可列出并标注归属；尝试管理时引导切换或登录对应账号，不能借用后台保留身份直接操作 |
| 归属账号已退出或确实失效 | 该账号在本机的台下线、灰显并禁止控制；仍保留本机删除入口 |
| 归属用户在另一台设备打开自己的台 | 使用观看者视图，标明“创建者为自己”和真实创建设备；允许全局播控、可见性、邀请、踢出及重新允许，不允许修改导入源、删除台、放弃归属 |
| 普通远端观看者 | 按访问许可观看和使用本机观看控制；不具有来源管理或全台播控权限 |

另一台设备上的归属用户不能把远端台当成本机创建的台，不能自动导入其配置。远程权限应按请求实际身份校验，不能只靠隐藏按钮。

### 2.4 多账号与登录生命周期

- 本机 U1、U2 都保留有效登录时，两者归属的台均可运行；仅切换当前账号不使另一账号的台下线。
- 主动退出某账号，或确认该账号登录确实到期失效，才使它在当前设备的台下线并锁定。不影响其它设备的台、其它仍登录账号的台或无归属台。
- 关闭网页、PWA 或暂时断网不等同于退出或会话失效，不能用设备心跳超时直接代替账号失效判断。
- 原归属用户必须在源设备恢复登录；不能从其它设备替源设备完成登录。重新登录只恢复控制资格，不自动重新上线。
- 源设备的账号仍有效时，归属用户可以从其它设备遥控其台上下线；不能因源页面暂时关闭就一律拒绝可继续服务的文件台。

## 3. 三渠道导入与节目单

### 3.1 统一“导入可视资源”

提供本机文件、网盘文件、隧道文件三个渠道，支持单个或多个文件、单条或多条隧道记录中的可预览资源，以及网盘和隧道范围内的随机导入。文件类型覆盖视频、音频、图片、Markdown、TXT。

网盘渠道支持选择有权访问的账号、分区和目录；隧道渠道按当前设备实际可访问的记录列出资源。不能因登录同一用户就显示另一设备加入的全部隧道。

三个渠道共用待导入清单：切换渠道保留候选勾选，预览不等于导入，确认后才追加节目项，取消不追加。确认后的节目单使用排序、预览和移除，不把来源勾选与节目单排序混为一个操作。

随机功能只用于从用户选择的来源范围、按指定数量抽取候选，再由用户确认加入。导入后不随机播放，不持续从原目录或隧道补充新资源；来源范围后来增加文件，不自动增加节目。

### 3.2 编排与播放参数

- 支持拖动及上下移动调整节目顺序，确认保存后按手动顺序播放。
- 同一来源可多次加入，每次是独立节目项；分别排序、设置参数和移除，不额外复制媒体。
- 图片、Markdown、TXT 等静态节目项默认停留 10 秒，可逐项调整；观看端显示倒计时数字，并支持指定显示位置，或采用图片边缘异色薄进度条。
- 视频和音乐逐项支持设置播放起始时刻；非法或超出实际可播范围的设置应明确反馈，不静默保存无法执行的值。
- 默认整份节目单循环；创建者可以改为播完停止。
- 播放中保存新节目单后，立即采用新顺序；当前项仍存在时保留其播放进度，移除当前项则按更新后的节目单继续，全部清空则停止并提示。
- 以节目项身份而不是来源文件身份判断“当前项是否仍存在”，否则同一文件多次编排时会误跳转。

本机文件重开后是否仍可读，取决于实际文件引用及浏览器授权；需要重新选择时明确提示，不把配置持久化描述为媒体永久托管。

## 4. 来源读取、权限与离线服务

### 4.1 有限读取能力

有效观看许可允许读取该台选定的节目资源，不要求观看者另外登录来源网盘账号或加入来源隧道；不得把创建者凭据交给观看者，也不得开放来源目录浏览、未选文件或来源修改能力。

Markdown 节目文件明确引用、且创建者有权读取的隧道资源，属于该节目必要的有限观看范围。只解析和授权这些明确引用，不开放整个隧道，不另行插入节目单；没有获准的资源引用应按实际结果显示。

业务授权与传输方式分离：复用现有文件资产传输、网盘读取等能力，但每次读取仍受台、节目项及访问状态约束。不能把知道来源标识或复用缓存当作访问许可。

### 4.2 不复制、不冻结、不保底

- 导入保存定位、顺序和设置，不偷偷上传、复制或归档源文件。
- 不因被串流引用就冻结文件或隧道记录，不阻止删除、不延长源内容生命周期、不建立用于防止清理的关系。
- 原来源删除后，后续读取允许失败；已在观看端缓存或缓冲的字节可以继续使用，不强制撤回已交付内容。
- 后续响应按实际来源状态处理缓存校验，不能把普通播放缓存变成永久副本，也不承诺修改缓存头就能追溯清除浏览器已有内容。

### 4.3 设备离线与来源失效分别处理

仍可读取的网盘来源，不因创建设备关闭页面或离线而停止服务。隧道来源也不能仅因创建者离线被判定失败；按 QA 后续补充，观看者处于来源隧道且内容仍可取得时，可继续观看。不能承诺所有跨隧道来源均能独立续播，更不能通过保底副本伪造这种能力。

本机文件继续依赖实际提供设备及可读引用。确认某来源已删除或不可读取时，显示原因并跳过下一项；全部不可用则停止并提示，避免无限空转。单个观看端短暂缓冲、断网或解码失败，不应被直接判为全台来源失效。

## 5. 全局放送与观看控制

### 5.1 一份权威全局状态

台维持当前节目项、播放／暂停、目标位置和状态版本。全局操作由有权身份提交，统一确定生效结果后广播；迟到请求、重连旧状态不能覆盖新状态。以服务端可继续维护的播放时钟为依据，不能让某个观看者播放器成为唯一时钟。

按 261020-1 对 Q9 的最新修订：文件台无人观看时暂停；观看数 0→1 自动启动／恢复，新台首次观看以及手动停止、播完停止后的 0→1 均适用。已有观众时新进入者不能解除全台暂停。创建者观看、收起控制台、本机暂停仍计入观众；全部断线由心跳租约失效确认并冻结位置。不得为模拟时钟持续下载、解码或转码。正常观看取得权威状态并尝试静音播放，浏览器拒绝时提供明确的本机开始按钮。详细边界以 QA 文档 Q9 当前结论为准。

发起端可看到观看设备、实际正在查看的节目、进度、连接和缓冲状态；不能将浏览器尚未播放、自动播放受限或等待数据显示为已经同步播放。允许合理短暂偏差并校准，不承诺所有设备每帧绝对同时。

### 5.2 第一阶段控制范围

| 能力 | 创建者／有权归属用户 | 普通观看者 |
| --- | --- | --- |
| 全局播放、暂停、切换节目、调整进度及快进快退 | 允许，影响全台跟随者 | 不允许 |
| 默认跟随全局节目与进度 | 可以查看全局状态 | 默认跟随 |
| 本机音量、静音／取消静音、暂停观看、文档滚动 | 允许 | 允许，不影响他人 |
| 本人自由选节目、拖动到另一进度 | 第二阶段另提供 Plus 个人模式；全局管理不受 Plus 限制 | 第一阶段不提供；不以免费自由观看替代最终规则 |

普通观看者恢复本机观看时追随当前全局位置；不能把本机暂停做成普通用户的任意进度播放。第二阶段加入 Plus 后再按所处模式区分恢复行为。

同一设备可同时发起与接收不同台，多台运行互不覆盖；第一阶段虽不做监控墙，运行层也不能采用全站唯一播放器／唯一当前台来排斥其它台。

## 6. 搜寻、主页与公开入口

- 进入控制台后自动列出来自可见设备的台，体验类似设备发现，不要求输入关键词，也不是扫描附近 Wi-Fi 或蓝牙。
- 可见设备是当前设备已关注的设备，或当前同隧道设备；单向关注即可，不要求对方反向关注或同隧道。
- 普通发现列表不泄露无许可的仅邀请台；发现、访问资格和是否订阅分别判断。
- 有归属用户的台显示该用户、来源设备和主页入口；无归属台仅显示设备，不伪造用户名。
- 创作者主页可聚合同一用户在 A、B 等设备发布的公开台，即使观看者按普通设备发现规则看不到 B。不能列出该用户各设备的私人配置、草稿或全部未公开台。
- 公开台直接观看链接允许原本不关注、不同隧道的设备进入，不强制登录或订阅；普通发现范围不因此扩大。被踢出及台下线限制仍生效。
- 从主页、邀请或链接进入，不自动关注设备、加入来源隧道或导入台配置。

## 7. 可见性、邀请与踢出

### 7.1 三档状态

| 状态或操作 | 访问结果 |
| --- | --- |
| 公开 | 按第 6 节提供普通发现、主页及公开链接入口 |
| 仅限邀请 | 获得有效观看许可后访问；普通未授权设备不能据此发现私人台 |
| 下线 | 停止服务，保留台、已有订阅书签及后续方阵位置，不等同于踢出或删除台 |
| 公开改为仅邀请 | 明确确认影响；退出旧观看端并撤销旧观看资格，切换前生成的所有通用／定向邀请一并失效；书签保留 |
| 踢出设备 | 终止指定设备对该台的访问，禁止凭旧许可、旧邀请或公开链接立即重入；其它设备及其它台不受影响 |
| 重新允许或重新邀请被踢设备 | 由有权管理者明确处理，不能靠自动重连或换入口绕过踢出 |

邀请到期／撤销与公开转仅邀请的整体访问重置是不同操作，不能复用一个模糊的“失效”逻辑。

### 7.2 通用邀请与定向邀请

| 项目 | 通用邀请 | 定向设备邀请 |
| --- | --- | --- |
| 交付渠道 | 链接／邀请码，可转交；包含转发到隧道的邀请 | 设备选择器发送，当前设备通知中心接收 |
| 可用范围 | 多设备、多次；不要求事先可见或同隧道 | 仅固定目标设备、多次；同账号另一设备也不适用 |
| 登录关系 | 允许未登录接受；先接受后登录也能关联相应账号观看资格 | 登录不会把设备邀请扩展为账号全设备许可 |
| 有效期 | 默认自生成起 24 小时，可改期限或不过期；可撤销 | 同左 |
| 到期／撤销 | 阻止以后凭该邀请新取得许可，不撤回已接受形成的许可 | 同左 |

通用邀请先在未登录手机接受、后在手机登录，之后同账号电脑可以携带相应观看资格进入；不能因最初未登录而固定在第一台设备。书签可提供入口，但不能作为一切私人台通行证。

邀请接受形成许可后，断线重进按已有许可处理；自然到期或撤销不自动踢出。公开转仅邀请的访问重置、手动踢出及台下线仍可限制访问，不能用邀请曾经有效绕过。

### 7.3 定向发送与通知中心

创建者可选择自己可见的其它设备发送邀请；接收设备在自己的通知中心接受或拒绝。不存在“切换查看设备”或让发送者查看对方通知中心的产品功能。

已关注的离线设备支持待送达，上线后可查看并接受仍有效的邀请，不要求创建者同时在线。已发送、已送达、已接受、已拒绝、已到期和已撤销按实际结果显示，不能发送即宣称对方已加入。

邀请可带媒体缩略图，但不导入完整节目资源。发送结果使用带背景色的横向长条提示面板，不只在按钮下面追加一行细小文字。

## 8. 邀请消息与普通 Markdown 支线

### 8.1 将邀请转发到隧道

创建者选择有权发送的隧道，新增 Markdown 类型的串流邀请消息，内容为说明、邀请超链接及可选媒体缩略图。看到该消息的设备可接受有效通用邀请，不再逐个等待定向批准；也不能把定向邀请偷偷转换为可转交邀请。

邀请消息带明确用途标记，不显示“下载”或“上传到网盘”。不能要求把节目单媒体导入消息，不能把 Markdown 邀请做成串流资源打包器。

### 8.2 普通 Markdown 消息

这条已确认支线属于第一阶段邀请交付的配套能力，不能只做邀请示意后遗漏普通消息要求：

- 提供普通 Markdown 消息的编写与发送能力，作为隧道中的记录展示；不把自动生成邀请消息当作普通消息发送功能的全部实现。
- 普通 Markdown 默认预览最多约 10 行，后续部分用毛玻璃效果遮挡，点击可展开查看完整内容。
- 可引用当前发送者有权读取的隧道 Blob 媒体资源，不引用需另行网盘账号授权的网盘资源。
- 普通消息提供“下载”“上传到网盘”；导出时将正文和其明确引用的隧道多媒体一起打包为 ZIP。按钮文字使用“下载”，不用“下载 ZIP”。
- ZIP 只包含正文及实际引用资源，不扫描打包整个隧道，不附带串流节目单。打包后引用应可定位，文件缺失和打包失败须按真实结果提示。
- 普通 Markdown 消息、带用途标记的串流邀请、作为节目源的 Markdown 是三个场景，不能互相套用按钮或授权范围。

## 9. 用户订阅与界面接入

### 9.1 订阅是账号书签

观看不要求订阅，订阅必须登录。接受邀请或打开播放器不自动添加书签；用户主动订阅后，在同账号其它设备展示同一列表。取消订阅只移除账号书签，不撤销观看许可，也不关闭当前有权观看的连接。

台下线保留书签并显示状态；切换当前账号显示对应账号列表，不能混用另一账号的收藏。订阅入口仍独立校验观看资格，不能绕过定向邀请设备限制、踢出或公开转仅邀请。

同步书签不等于同步本机台配置、隧道集合或监控布局，也不等于开通 Plus 或创作者会员。

### 9.2 首页与 v3 接入

在首页连接设备区右上角菜单增加“串流控制台”。控制台采用全屏浮层，保留现有三栏；收起后回原首页状态，顶栏提供运行及恢复入口，恢复最后页面、台、滚动位置和未提交表单。

移动端浮层位于原三栏侧滑容器之外，不增加第四栏。前景手势、排序拖动、媒体控制及文本选择不能触发后台三栏；开关浮层清理未结束手势，返回保留原栏位。快捷返回传输记录不能顺带触发首页重复点击的磁贴动作。

适配窄屏、虚拟键盘、横竖屏和安全区；控制台收起不取消放送或观看。媒体沉浸全屏与控制台全屏分别管理，退出媒体全屏恢复原观看页。

v3 第一阶段主要对应 01–07、09–13、16–17、19、22–25、27–31、33–35、40–41 及邀请补充 42；26 中文件播放部分属本阶段，监控部分后置。旧图中的设备订阅、任意接收端全台播控及过时邀请文案应按本指引整合；本次编写指引未修改原型代码。
