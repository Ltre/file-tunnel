## 3. 各项实施前指引

### P3-1：请求成本与即时控制

原设想是在操控页提供 `启用即时控制`，文案右上角带 `p` 上标。启用时评估即时通信，未启用时评估随媒体请求取得最新指令。该外观和行为仍是待确认设想，`p` 不自动代表 Plus 或付费资格。

后续需完成：

- 按实际代码和请求记录区分播放控制、供源通知、观看租约、身份／授权同步和媒体读取的成本，记录设备数、观看实例数、空闲与播放状态。
- 比较保留或优化现有 HTTP 状态推送、Socket.IO、轮询及随媒体请求附带状态的效果；不预先指定迁移框架，也不直接借用隧道连接作为串流观看授权。
- 确认开关由谁操作，是作用于单台、当前观看端还是全体观看者，以及哪些命令允许延迟。权限撤销、踢出、下线等访问控制和必要观看租约不能依赖下一次媒体请求。
- 覆盖图片／文本等静态节目、暂停后无后续媒体请求、断线重连、迟到状态及多设备控制；媒体正文不能混入控制 JSON。
- 比较优化前后的请求量、连接数、控制响应时间、媒体首播及内存开销，再确定方案。不能把请求次数减少直接等同于整体成本降低。

本项延期不取消第二阶段实现实时源所需的通信，也不允许把该功能的基本可用性、资源上限和正确清理留给第三阶段。

### P3-2：真实购买与资格

原始需求列出的包月、包季、包年及点数购买是后续可能形式，尚未选定，也没有确定价格或扣点规则。

- 先明确采用哪些购买形式、实际权益与期限，再确定支付及订单流程，不直接把所有形式都实现。
- 明确资格来源、支付结果确认、重复回调与重试、续期／到期、取消或退款涉及的资格处理，以及既有 Mock 资格的处置方式。
- 真实购买继续绑定现有用户身份。串流购买及资格由对应业务模块管理，不重做登录、多账号或网盘账号系统。
- Plus 不附带私人台观看许可、来源访问权或管理他人台的权力，不把本机音量、静音、暂停和阅读等已有免费能力改为收费。

以上是实施前需要补齐的问题，不是已经确定的支付渠道、退款政策或商品规则。

### P3-3：创作者等级与权益

- 创作者会员继续以创作者用户为对象，与平台 Plus、单台订阅书签和观看许可分开。
- 等级名称、数量、递进规则、具体权益及真实付费方式均待确认；不能从“完整会员业务”自动推导出成员专享内容或新的管理能力。
- 第二阶段已有按用户、台和操作直接授予的特殊权限。本阶段只细化尚未确认的会员业务及其可能关联，不重复开发直接授权，也不把直接授权整体延期。
- 若将来讨论等级与权限关联，需明确获得、调整、到期及退出等级时如何处理显式授权；非会员仍可获创建者明确授权，会员身份本身不能替代操作权限检查。

### P3-4：主动配置同步

原始 QA 允许将“用户主动把某个隧道或某个串流台配置同步到另一台设备”留待以后开发。此处强调用户主动选定对象和目标设备，不因登录同一账号自动合并全部设备的数据。

实施前需确认：

- 同步哪些字段，是一次性复制、持续同步还是其它明确操作；是否新建目标台、如何处理身份与已有配置冲突，均尚未决定。
- 隧道与台配置分别说明权限、来源定位和目标设备需要的确认，不能凭配置同步跳过隧道加入或资源访问校验。
- 本地文件副本、设备文件引用及摄像头／屏幕授权不能因收到配置就被视为已迁移可用。是否传输文件内容以及来源设备如何确定，需另行确认。
- 归属用户已经可以远程管理自己的台，与把台复制或同步为另一设备的本机台是不同业务；不以同步功能替代第二阶段的远程管理。

### P3-C1：条件性的广告议题

“将来有广告时 Plus 可免广告”是已保留原则，引入广告本身尚未确认。本项只有在用户决定引入广告后才进一步定义，不作为真实购买、Plus 或其它第三阶段事项的前置条件。

## 4. 不能被当作延期项的内容

下列已属于现有能力或第二阶段范围，应在对应阶段完成，不因本指引而延期：

- 摄像头／屏幕实时源及必要通信、采集与账号生命周期、监控大爷模式和 profile；普通单台与监控多台的互斥及离开监控后的资源释放。
- Plus Mock、创作者会员 Mock、三项独立特殊授权及其对象选择、期限、撤销；归属用户跨设备管理，只有节目单编辑限于创建设备。
- 创建设备的本地导入内容副本、观看端缓存及关联清理；播放、授权、重连和缓存正确性，以及内存、连接和任务的必要资源控制。
- 已确认的观看、邀请、书签及文件台无人观看规则，和隧道传输、网盘、账号、网页工坊等已有功能的回归。

以下事项也不因收录未来指引而自动进入第三阶段：

| 事项 | 状态 |
| --- | --- |
| 文件随机播放 | 已取消，保留的是随机导入；不列为后续待开发功能 |
| 同账号自动同步全部台、隧道、监控布局或个人播放位置 | 不符合设备独立规则；P3-4 只讨论主动选定的配置同步 |
| 云端录像、实时回看／时移及新增 RTMP／RTSP／SRT／HLS 等协议 | 未纳入既定阶段范围，需另行提出并确认需求；不预设为第三阶段交付 |
| 已移出的 Media Library 删除与取帧事项 | 不属于串流控制台开发计划 |
| 为串流业务重构隧道传输、Telegram 网盘 API、网页工坊或账号系统 | 不属于阶段默认任务；继续遵守第二阶段的核心接口约束 |

## 5. 后续执行与验收

按选定事项先确认业务细则和验收条件，再安排实现。请求优化、会员商业规则及主动同步可以分别评估，不强行捆绑为一次核心系统改造。

涉及代码时重新核对实际工作区、第二阶段最终确认及已完成实现；通过串流侧接口消费既有能力，不把会员、监控或支付状态加入隧道传输及网盘基础权限判断。

验收应记录所选范围、设备／浏览器、数据及权限条件、实际测量和回归结果。本轮只整理文档，没有实施第三阶段功能，也没有执行或宣称通过其功能测试。
