# file-tunnel｜yt-dlp / SNS 多出口代理支持方案

## 一、需求背景

正式环境曾出现 YouTube Music 曲目无法解析、普通 YouTube 内容仍可抓取的问题。最初怀疑 yt-dlp 版本、Deno / EJS、Cookie、播放器客户端及后台调用参数。对齐工具版本后，问题依旧；随后对同一曲目进行跨环境、跨出口测试，确认日本出口能解析并下载，而测试过的新加坡出口及韩国服务器本机出口无法播放，YouTube 返回 `UNPLAYABLE / Video unavailable`。浏览器直接访问也复现了地区间差异。

因此，本次不以修改抓取算法为目标，而是**让每个抓取任务能够选用不同网络出口，在初次获取失败时尝试其他节点，提高地区受限内容的抓取成功率**。

## 二、总体方案

- 新增独立的网络出口管理能力，作为现有 yt-dlp / SNS 抓取流程的**旁路基础设施**；保留原有解析、格式选择、下载、进度和错误处理逻辑，避免重度耦合。
- 项目内置并由 Node 服务托管 **sing-box** 可执行组件，负责连接 Trojan-GFW 节点。无需另外安装图形客户端，也无需通过服务器系统代理或启动终端的 `HTTP_PROXY` 等环境变量切换出口。
- sing-box 组件按 `tool/sing-box/` 下的 `win-x64/`、`linux-x64/` 组织。运行和配置由后台统一管理；日常切换节点可直接在 Web 页面完成。
- 每次 yt-dlp 调用按**当前任务选定的节点**使用相应代理；同一任务的解析、后续下载及相关资源请求使用一致的节点。不同并发任务可使用不同节点，互不影响。
- 支持直接使用服务器本机出口，以及用户自行维护的代理节点；不能因某个代理不可用就无提示地改走直连。

## 三、节点管理

- 每个配置以**唯一节点 ID** 标识；节点名称、备注由用户自行填写。
- 节点配置包含连接地址、端口、Trojan 密码、TLS SNI / Server Name、**是否验证 TLS 证书**等必要信息。
- 兼容 Trojan 直连节点，以及通过 HAProxy **TCP 透传**中转的节点。TLS 仍开启，允许按节点配置关闭证书验证；中转地址与最终 TLS 服务端的 SNI 可不同。
- **不按 IP、端口、地区或配置内容去重**：相同 IP / 端口乃至相同参数均可建立多个不同 ID 的节点。
- **不检测公网出口 IP 变化，不做自动地区识别、节点测速排名、历史成功节点推荐或跨任务偏好学习。**
- 节点密码等敏感配置仅存放于独立、受保护的私有数据中，不硬编码到程序逻辑，不进入仓库或普通日志。

## 四、任务出口选择与切换规则（核心）

1. **每个新任务独立选初始出口**：优先使用该任务单独指定的节点；未指定时使用当前全局指定节点。不得继承上一个任务实际成功使用的节点。
2. **仅在首次成功获取目标内容之前允许自动切换**：初始节点获取失败，则尝试其他已配置的候选节点；继续失败则继续尝试，直到有节点成功获取可用内容，或候选节点全部失败。
3. **一旦首次成功，本任务即固定使用该节点**：其后的音频、视频、封面、元数据补充、下载或重新请求，均保持这一出口。**即使后续某个请求失败，也绝不再自动换节点。**
4. 这种固定只适用于**当前任务**，不锁定全局节点，也不影响其他任务。管理员修改全局默认节点，只影响之后创建的任务。
5. 所有候选节点都失败时，明确报告任务失败和各次尝试结果；日志用节点 ID 标识，不泄露密码。

**示例：** 任务 1 指定 A，首次解析失败 → 试 B 失败 → 试 C 成功；之后任务 1 的全部相关请求固定使用 C，后续失败也不再换。任务 2 仍从自己指定的节点（否则全局节点）开始，与任务 1 使用 C 无关。

## 五、Web 管理与验收重点

Web 管理端应支持维护节点、填写备注、设置全局默认出口；提交抓取任务时允许单独指定节点，并能查看本任务尝试过的节点及最终采用的节点 ID。

验收时重点确认：**不开启新代理功能时，原有抓取行为不受影响；单任务出口选择优先级正确；首次成功前允许逐个切换、首次成功后绝不切换；解析与下载出口一致；多个任务互不干扰；配置节点无需再登录服务器手动切换代理工具。**

> 本文为需求与架构约束整理，不涉及现有业务代码的具体修改方式。
