## 1. 阶段范围与前置条件

本阶段在已可使用的文件台之上增加：摄像头实时源、屏幕／窗口／标签页实时源、监控大爷模式、平台 Plus Mock、创作者专属会员 Mock，以及创建者向观看者用户发出的串流台特殊授权。本轮另按最新澄清调整归属用户跨设备管理的范围：节目单只能在创建设备编辑，其它台管理功能均可跨设备使用，详见第 6.2 节。

### 1.2 与系统核心功能的接口约束

第二阶段的实时采集使用关系、监控观看实例、Mock 资格、个人播放状态及特殊授权，由串流模块管理。复用现有能力不等于向核心功能加入串流业务分支。

| 涉及功能 | 允许的集成范围 | 不应由第二阶段顺带改变的内容 |
| --- | --- | --- |
| 隧道文件传输 | 经现有读取接口获取有权读取的节目内容，读取已有设备可见关系 | 不因直播或监控改写隧道文件身份、转发副本归属、还原权限、P2P／Relay 调度或传输进度；串流凭据限于串流请求，不成为隧道传输的额外门槛 |
| Telegram 网盘 | 串流侧适配现有身份、对象及 Range 读取接口 | 网盘 API、分片存储、协同／静态开放权限及文件操作不依赖串流会员、监控或播放器状态 |
| 账号系统 | 消费现有用户身份、保留登录状态及有效性结果；串流侧检查资格、归属和授权 | 不重做登录、退出、多账号、Passkey／OIDC 或网盘账号选择流程；暂时请求失败不能被串流模块解释成账号失效 |
| 网页工坊、普通 Markdown | 保持已有资源引用和发布行为；共享读取能力时明确各自作用域 | 不要求这些功能先开通 Plus、建立监控实例或启动实时采集；不让串流专属状态成为其新前置条件 |
| 摄像头、语音等既有实时功能 | 在核对实际接口后复用可复用的采集或通信能力 | 不共用一个可被任意台替换或关闭的全站采集状态；关闭台、退出账号或结束监控不能停止其它功能仍在使用的轨道 |

实时媒体会话与文件字节供源分别管理，不能因已有模块名含有 `peers` 或使用 WebRTC，就把文件分块协议直接当作摄像头／屏幕放送协议。是否需要新增通信接口应在串流模块内评估，不把迁移隧道信令或文件传输架构列为默认前置工程。

现状也并非已经完全解耦：例如首页适配中的普通 Markdown 引用读取仍调用串流资源接口。这是本轮已发现的既有依赖，后续修改相关接口时必须核对其调用方；本轮不自动授权拆改该链路，也不将全系统重构列为第二阶段前置任务。确需改变核心接口时，应先说明现有接口缺少什么、最小改动及受影响调用方，再确认实施范围。

## 2. 摄像头与屏幕实时放送

### 2.1 来源模式与多台独立

- 文件节目单、摄像头、屏幕采集分别作为来源模式。摄像头和屏幕不插进普通文件节目单，也不参与图片停留倒计时或文件循环。
- 切换来源模式保留已保存的文件节目单和设置，不能为了直播清空原文件配置。
- 摄像头由创建设备选择实际可用输入并主动授权。屏幕共享由浏览器选择屏幕、窗口或标签页；是否可采集音频按实际设备及浏览器能力显示。
- 保存台配置不等于永久保存采集权限。首次启动或需要新建采集会话时，必须遵守浏览器授权及本机操作要求；拒绝或取消后保留配置，不显示已经开播。
- 同设备可为多个不同台供源；供源与本机观看分别管理。普通观看、后台播放和小窗播放仍是单台，只有监控大爷模式允许同时观看多台；不能将“多台供源”解释成普通界面多台并播。
- 某个台的切换、暂停、停止和失败，不能覆盖其它台的供源或原项目已有摄像头功能。

本阶段不额外宣称支持 RTMP、RTSP、SRT、HLS 等未确认协议。优先复用既有 WebRTC／信令和采集能力，但串流台运行范围独立，不能直接沿用原单个摄像头广播状态而让多个台互相替换。

### 2.2 采集、发送与观看的生命周期

| 动作或状态变化 | 采集及对外发送 | 观看与恢复 |
| --- | --- | --- |
| 接收端暂停本机观看 | 不改变源设备采集或其它观看端送流 | 仅本机暂停；恢复追当前实时 |
| 实时台所有观看端结束观看，台仍上线 | 保留已授权采集会话，无人时不对外发送此台媒体 | 原本在播的台有人再进入时恢复供流，接入当前实时，不补播无人期间内容 |
| 有权操作者执行全台暂停 | 保留本机采集预览，停止对所有观看端发送；本机明确显示仍在采集 | 全台恢复后看当前实时，不补播暂停期间内容 |
| 账号在线，仅将台设为下线 | 保留仍有效的已授权采集会话，停止对外发送，源设备显示该状态 | 归属用户可从其它设备将台上线，复用有效会话恢复发送 |
| 主动停止本机采集、共享被系统停止、页面关闭或权限丢失 | 实际采集会话结束或不可用，不假装仍有媒体可发送 | 显示需要在源设备恢复采集／授权；不能仅靠远程上线命令静默重建屏幕共享 |
| 归属账号主动退出或确认登录失效 | 其本机归属台下线锁定，结束其对应的本机采集使用 | 用户亲自到源设备恢复登录及必要采集授权；恢复资格不自动上线 |

实时台无人观看不结束已授权采集，不直接套用文件台的无人暂停流程。有人重新进入时仍需满足权限、台状态及实际采集条件；不能借重新进入解除已经生效的全台暂停或台下线。主动停止采集、账号失效及浏览器结束共享等情况继续按各自生命周期处理。

结束某个账号的采集使用时，不能误停其它仍登录账号或无归属台。若底层采集被复用，也应按实际使用范围处理，不能简单停止全设备全部媒体轨道。

控制台收起、打开其它功能、当前账号切换、台单独下线及账号退出不得混用一套清理动作。源设备离线不等于账号已失效，但实际无法继续的实时源必须显示不可用，不能假装与网盘文件一样可独立续播。

### 2.3 远程恢复的产品目标与浏览器边界

用户已确认：账号在源设备有效在线时，可由有权归属用户在其它设备控制台上下线，目标是尽可能自动恢复实时供流。Q46 采用保留仍有效采集会话的方式支持该目标。

必须区分：

1. 仍有效的已授权会话：台下线后重新上线，可恢复发送，不额外制造“必须本机点一次”的产品限制。
2. 已结束的屏幕会话：普通网页新调用 `getDisplayMedia()` 仍需要源页面上的用户操作和屏幕选择，不能静默绕过。远端应显示当前阻碍及需要在源设备完成的动作，不能提前显示恢复成功。
3. 摄像头会话：按已有许可、硬件和浏览器实际状态处理，不把屏幕共享的每次选择机制机械套到摄像头，也不承诺任何状态都能自动恢复。

Q45 已记录 [W3C Screen Capture](https://www.w3.org/TR/screen-capture/#dom-mediadevices-getdisplaymedia) 及 [MDN 安全要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia#security)；实施时复核所测浏览器，不把规范阅读当作实机验收。

### 2.4 实时观看界面

显示实时来源、送流状态、连接和实际播放状态，不显示文件进度拖动、快进快退或历史回放。静音、音量、本机观看暂停与全台暂停分开；暂停发送期间不偷偷录制或补播。

全局暂停、台下线及采集仍在进行的提示必须能够辨认，避免让源设备用户误认为摄像头或屏幕已经关闭。权限拒绝、设备占用、采集结束和播放受限按实际情况提示。

## 3. 监控大爷模式

### 3.1 方阵与台选择

允许同屏接收多个文件台或实时台，提供单画面、四宫格、九宫格等原型所示布局，支持添加、移除台及保存、恢复布局预设。

**同时观看多台仅限监控大爷模式。** 进入监控时，结束此前普通观看、后台或小窗的观看接收，不在方阵之外保留另一路串流台播放器；不将旧后台播放暂存为退出监控后自动恢复的任务。此处只结束本机观看，不等于停止这些台的供源或执行全台停止。

布局 profile 按当前设备保存，不随同账号自动同步到另一设备。添加台只改变本机布局，不自动订阅；订阅书签可以提供选择入口，但不是观看授权。profile 保存的是可恢复的台选择、布局及各格静音／音量配置，不是活跃播放器、连接或可绕过校验的观看凭据。恢复布局时逐台检查访问资格和实际来源状态，不借布局保存私人台访问能力。

台下线保留格位，显示状态；重连、被踢或等待采集不能随意挤走其它格位。移除格位不删除台、来源或账号书签。

### 3.2 单格及批量控制

各格仅保留静音开关、纵向音量短条、全屏和播放／暂停这组播放控件，按以下状态显示：

| 状态 | 右上角 | 画面水平／垂直中央 | 左下角 | 右下角 |
| --- | --- | --- | --- | --- |
| 加载后默认状态 | 很小的 `🔇/🔊` 静音开关 | 不显示播放按钮 | 不显示音量条 | 不显示全屏按钮 |
| 点击画面非按钮处后 | 隐藏静音开关 | 显示 `▶/❚❚` 播放／暂停按钮 | 显示纵向音量控制短条 | 显示 `全屏` 按钮 |

状态切换由鼠标左键单击或单指轻点格子画面的非按钮处触发。点击静音、播放／暂停、全屏按钮或操作音量条时，只执行相应操作，不能同时触发画面点击行为；展开控件本身不改变播放或静音状态。静音图标及播放／暂停按钮应反映本格的实际状态。

控件展开后，再次左键单击或单指轻点画面非控件处，立即收起；连续 2 秒无操作也自动收起。收起后隐藏中央播放／暂停、左下音量短条和右下全屏按钮，恢复右上角的小静音开关。拖动音量条期间暂停自动收起计时，操作结束后重新计时；其它控件操作也重新计时。收起只改变控件展示，不改变本格播放或声音配置。

- 批量按钮对当前选定范围执行本机静音／取消静音、暂停／播放观看，仍与格内控件分别提供。
- 初次进入某个 profile、尚无已保存声音设置时，默认开启全部格子的声音，不采用全部静音或只允许一格有声的默认策略。初始音量沿用现有播放器默认值，不另定强制最大音量。
- 用户可分别调整各格是否静音及音量大小，并随 profile 保存；下次进入该 profile 时恢复此前保存的各格设置。声音配置属于本机 profile，不影响台的全局状态或其它设备。
- 浏览器限制有声自动播放时，明确提示需要用户操作，保留 profile 的声音设置；不能将临时播放受限误报为全台暂停，也不能据此覆盖已保存的静音／音量配置。
- 批量操作不修改全局节目、进度或其它观看者状态，也不因某格台归属于自己就偷偷改变整台播放。
- 如需全局管理，进入单台并明确全局操作范围，继续检查归属或特殊授权；不能从普通墙面按钮隐式升级权限。
- 监控进行期间不保留方阵之外的串流台后台播放。离开、收起或关闭监控界面、返回功能首页时，结束全部监控观看接收，释放其观看实例、连接、解码及预读等运行资源，只保留布局 profile；不把某格转为后台或小窗继续播放。
- 离开监控不删除台、取消订阅或主动下线来源台。文件台若因此失去最后一个有效观看实例，仍按现有无人观看规则暂停，不为监控另设例外；也不把结束本机接收扩展为停止源设备采集。
- 重新打开监控时，按 profile 重新检查权限与台状态、建立观看，不把保存成功等同于后台一直在接收。
- 只保留 profile 指保留台选择、布局和已保存的各格声音配置，不保留监控的运行状态；既有文件缓存继续按第 7 节管理，不因退出监控误删仍被节目引用的供源内容。
- 格内的 `全屏` 按钮用于放大当前格子，退出后返回监控方阵；不切换为普通单台观看页。方阵整体全屏继续保留多台布局，两种入口应明确区分。仅退出全屏、仍留在监控界面，不按离开监控清理。
- 单格全屏期间，同一 profile 中当前已启动的其它格子继续接收、维持原播放状态，但临时静音；仅当前全屏格子可以按自身声音设置发声。当前格子原本静音或音量为零时保持其设置，不因全屏强制开启声音或提高音量。
- 退出单格全屏后，恢复其它格子各自原有的静音状态和音量，原本静音的仍静音。此临时声音处理不改写 profile；全屏期间保存 profile 时，也不能把对其它格子的临时静音保存为用户设置。用户主动调整当前格子的静音或音量，仍按普通格内设置处理。
- 单格全屏仍是当前监控会话内的展示，不新开监控外的后台播放器，不额外启动受资源限制而尚未播放的格子。若直接离开监控，仍结束全部接收，不能因全屏退出后的声音恢复而重新启动已结束的播放。

### 3.3 与观看模式的关系

普通观看者的各格默认跟随对应台的全局状态。本机暂停后恢复追全局；Plus 用户的个人模式按第 4 节处理，不能通过进入方阵为普通用户免费提供个人拖动进度。

### 3.4 资源预算与受限格位

每格独立维护媒体、连接和状态。进入实现前列出并发解码、缓冲、预读、连接、重试及事件订阅的资源预算和释放条件，再按真实设备验证；“支持九宫格”不能等同于任意设备都能无限接收高码率视频。某格失败不能使其它格或首页卡死，退出后不得残留这些监控实例的重连、预读或观看心跳；释放观看资源不能误停仍在供源的台。浏览器自动播放失败等情况需显示真实结果，不以格子存在等同于正在播放。

用户已确认：设备资源不足时，允许限制实际同时播放的数量，同时保留全部格位及 profile。未启动的格子应明确显示受资源限制，并允许用户选择实际观看哪些格子；不能静默移除格位、修改保存布局，或把资源限制误报成台下线、无观看权限或来源失效。

受限且未启动的格子不启动媒体接收、预读及解码，只保留必要的台信息和状态展示，不能在占位界面背后继续完整接收。切换实际观看格子时，结束被替换格子的媒体工作，再启动所选格子，遵守同一资源预算。

具体播放上限、判断依据和通过指标须按设备、来源类型及持续运行实测确定。本轮确认的是处理策略，没有批准固定数量，也没有证明浏览器能够准确自动判断剩余资源。

## 4. 平台 Plus Mock 与个人自由观看

### 4.1 资格与开通

Plus 绑定用户账号，不绑定设备或某个台。本阶段提供清楚标注为 Mock 的开通与资格展示，复用全局登录；未登录先登录，不创建设备级 Plus。

同一账号在不同设备使用同一资格；不因此同步隧道、创建配置或各端个人播放位置。Mock 不代表真实付款成功，不自行增加价格、固定购买周期、点数扣费或真实订单。

Plus 与普通台订阅书签、创作者专属会员分别显示。Plus 不能绕过仅邀请台、被踢设备、下线、来源失效或台资源范围等限制，也不获得管理他人台的权力。

### 4.2 跟随与自由观看

| 模式 | 节目及进度 | 对其它观看者的影响 |
| --- | --- | --- |
| 默认跟随 | 跟随台的当前全局节目和目标进度 | 无额外影响 |
| Plus 个人自由观看 | 本人可选择已经导入的节目及调整文件播放进度 | 不改全局状态，不影响其它设备 |
| 返回全局同步 | 放弃当前自由位置，取得最新全局节目与进度 | 不把个人状态写回全局 |

同一 Plus 用户在手机、电脑均自由观看时，各端节目和进度独立。一端换节目、拖动或返回全局，不改变另一端；不因账号共用资格而建立账号唯一的播放游标。

自由选择范围仍是台已导入并允许观看的节目，不开放来源目录或持续随机抽取。实时源没有文件时间轴，Plus 不因此获得录像、回看或时移。

本机静音、音量、暂停观看和文档滚动继续免费；不得为了 Plus 收回第一阶段已经确认的这些普通操作。Plus 是个人自由观看能力，与创建者或被明确授权者的全局播控分开。

真实购买与计费留待[第三阶段 P3-2](streaming-console-phase3-guide-261019.md#p3-2真实购买与资格)细化；月／季／年和点数仍是候选形式。广告及 Plus 免广告按第三阶段的条件性议题 P3-C1 记录，本阶段不开发广告系统。

## 5. 创作者专属会员 Mock

在有归属用户的台显示创作者及主页，并在该创作者范围提供 Mock 加入及会员身份展示。归属账号是会员对象，不是来源设备；同一创作者在多个设备发布台，不需要对每台重复购买一个相同概念的创作者身份。

无归属台没有创作者用户名是正常状态，不能把当前设备登录者冒充其创作者，也不能为它伪造会员归属。

创作者会员独立于平台 Plus，加入不自动成为管理员，不自动获得私人台观看许可，也不自动获准全局播控。成为会员可以是创建者决定授予权限的业务参考，但不是系统强制条件；非会员仍可被明确授权。

本阶段不擅自设计等级名称、价格、等级递进、成员专享内容或完整等级权益。完整会员业务留待[第三阶段 P3-3](streaming-console-phase3-guide-261019.md#p3-3创作者等级与权益)细化，本阶段完成 Mock 加入、身份及其与特殊授权的区分。

## 6. 串流台特殊授权与归属用户管理

### 6.1 已确认且必须落实的原则

- 由台的归属用户明确授权给指定用户，双方使用用户身份；不能把匿名设备标识当作会员账号替代。
- 授权对象支持两种选择方式：从本台当前已登录的观看者中选择，或输入账号 ID，提前授权给尚未进入本台的用户。使用现有账号标识确认目标，不把显示名或设备标识当作账号 ID，也不另造串流专属账号。
- 提前授予播控权限不附带私人台观看资格；实际使用权限时仍需满足该台的观看及访问条件。
- 按具体台、具体操作设置；不自动作用于创建者所有台或其它用户的台。
- 会员不是授予或使用权限的硬性前提；Plus、创作者会员、观看许可、订阅书签均不能直接换算为全局管理权限。
- 第一批授权项已由本轮确认：**全台播放／暂停、切换节目、调整文件全台进度**。三项分别勾选，不能勾选一项就取得另外两项；“全台播放／暂停”作为一组操作授权。
- 上述操作影响全局跟随者，应明确显示作用范围，不能伪装成 Plus 个人控制。切换节目和调整文件全台进度适用于文件节目单，不给实时源增加文件时间轴；实时台的全台播放／暂停继续遵守第 2 节的采集与送流规则。
- 授权不扩大台所选来源的读取范围，不开放来源网盘或隧道管理；不能把“管理员”三个字等同于修改来源、删除台或转移归属的完整权限。
- 授权默认长期有效，也可选择到期时间；归属用户可随时撤销。长期有效仍受主动撤销、放弃归属等既有失效条件约束，不等于不可撤销。
- 到期或撤销后，不再允许使用对应的特殊操作权限；普通观看许可及订阅书签分别管理，不因操作授权失效自动删除。
- 放弃台归属时，撤销原归属用户针对该台授予的特殊权限，保留普通观看许可及账号书签。之后重新认领不能自动复活旧授权。
- 所有授权请求及实际控制操作在服务端检查当前身份、台归属及有效权限；迟到操作不能绕过已经生效的权限变更。

### 6.2 归属用户跨设备管理范围（本轮最新确认）

归属用户在其它设备登录同一账号后，可以授予、修改和撤销本台特殊授权。用户进一步明确：**除了节目单只能在最初创建该台的设备编辑，其它台管理功能均可使用。**

- 节目单编辑包括导入、移除和重新编排节目，以及修改节目来源、逐项播放参数；仍在创建设备执行。切换当前播放节目、调整全局进度属于播控，不等同于编辑节目单，可以远程操作。
- 其它台管理功能可跨设备使用，包括基本信息及台设置、播控、可见性、邀请、观看访问管理、特殊授权管理，以及删除台、放弃归属。早期 QA Q34～Q37 和第一阶段指引中“远端不得删除台”“放弃归属仅限创建设备”等限制，与本次澄清冲突的部分由此替代。
- 另一设备仍按远端观看入口打开，展示实际来源设备，并提供归属用户可用的管理操作；不能因此把台登记为该设备创建，也不自动导入创建设备的节目单、本地文件副本或隧道集合。为管理读取所需台信息，与自动同步本机创建配置分别处理。
- 远程管理台不等于远程登录源设备或代替浏览器选择本机文件、授权摄像头／屏幕；已确认的身份和实际采集条件仍按第 2 节处理。
- 远程修改、删除或放弃归属后，源端重连及旧配置上报不能覆盖新状态、复活已删除台或恢复旧归属与授权；相关本地副本仍按引用关系处理，不能通过通用清理误删其它台仍在使用的内容。

这里扩大的是归属用户对自己台的管理范围，不是特殊授权接收者的权限。被授权用户仍只拥有第 6.1 节勾选的三项播控能力，不能因此管理授权、编辑来源、删除台或改变归属。创作者自定义等级及权限映射不纳入这批直接授权的默认要求，也不作为其它阶段功能的前置条件。以上是待开发目标，不表示当前代码已支持这些新增远程管理操作。

## 7. 第一阶段规则在扩展后仍须成立

- 每个台依旧只有一份全局权威状态。Plus 自由观看是个人模式，监控墙是本机组合，不另造互相覆盖的全局状态。
- 公开／仅邀请／下线、通用／定向邀请、24 小时默认期限、踢出与重新允许等规则同样适用于实时台；会员资格不能绕过它们。
- 订阅仍是账号级收藏，不是设备订阅，不要求订阅后才能观看，也不因移除格子或关闭采集而自动取消。
- 本机创建台集合、节目单、本地文件副本、加入的隧道和监控布局不自动跨设备同步。用户主页公开聚合继续保留；归属用户从远端观看入口管理自己的台，操作范围以第 6.2 节最新确认为准，不再沿用早期的有限管理清单。
- 多账号保留登录与切换当前账号继续分开；账号退出／确实失效只处理其本机归属台，不影响其它在线账号或无归属台。

### 7.1 文件内容缓存与来源

用户本轮明确：早期“按需加载原始来源，不复制或保留源内容”的表述，不能再作为全面禁止浏览器缓存或本地文件副本的依据。应按以下用途分别处理：

- **观看端缓存**：考虑现实网络环境，允许保留观看时取得的文件内容，后续播放可以复用。来自供源端本地文件、网盘和观看端未加入隧道的文件缓存，继续建立数据关联，并通过现有 `清理垃圾` 入口管理，避免成为清理死角。
- **创建设备的本地导入副本**：节目来自本地文件时，为保证后续读取稳定，将文件内容复制到创建设备的浏览器持久缓存，不能只依赖当前页面会话的文件引用。仍被节目引用的供源副本不能被普通清理删除；移除节目或删除台时，按实际引用关系回收，不能误删仍被其它节目或台使用的内容。
- 这两类缓存都是允许且需要延续的文件能力，第二阶段不得用旧文档中的“不复制”将其取消。缓存存在不替代观看授权，也不因 Plus 或监控扩大来源读取范围。
- 上述文件缓存不等于实时录像。摄像头／屏幕内容仍不落成录像或时移缓存；也不因串流缓存冻结网盘／隧道的原文件或记录、阻止用户删除，或改变其权限与失效规则。文件台的设备离线续播和服务器重启恢复不被实时源改造破坏。

### 7.2 即时控制留待第三阶段独立优化

用户已确认：第二阶段不新增 `启用即时控制` 开关，保留为后续独立优化。请求成本、控制方案及开关设想集中见[第三阶段 P3-1](streaming-console-phase3-guide-261019.md#p3-1请求成本与即时控制)，历史依据见[请求频率与全台控制方案分析](../streaming-console-reduce-req-261026.md)。

本阶段沿用现有播控基线，不为该开关改换通信框架或整体调整请求策略。实时源所需通信及监控资源控制仍须在第二阶段完成；不因优化延期而取消必要的观看租约、权限校验和状态恢复。

## 8. 开发顺序与原型整合

以下是后续实施安排，不表示本轮开始开发。应先完成指引复核，列明确认范围，再进入实现；不为了推进顺序而替用户决定尚未确认的业务规则。

| 顺序 | 交付内容与依赖 |
| --- | --- |
| P2-1 实时来源适配 | 复用第一阶段台、观看许可和状态服务；补摄像头／屏幕配置、授权、供流、接收及明确错误状态 |
| P2-2 生命周期 | 完成全台暂停、台下线保留采集、远程复用恢复、账号下线终止及多账号隔离；覆盖真实浏览器权限和轨道结束事件 |
| P2-3 监控墙 | 基于监控范围内的独立观看实例完成一／四／九格、本机单格及批量控制、布局 profile 和多画面全屏；与普通单台观看互斥，离开即结束全部接收 |
| P2-4 Plus Mock | 完成账号级资格、个人自由观看及返回全局，同账号多设备游标独立；确认实时源没有新增回看 |
| P2-5 创作者会员 Mock | 完成按创作者用户的加入及身份展示，验证与 Plus、观看权和特殊权限分离 |
| P2-6 特殊授权与归属管理 | 落实第 6.1 节三项独立授权、选人、期限及撤销；按第 6.2 节开放归属用户跨设备管理，只有节目单编辑限于创建设备；不实现未确认的完整等级系统 |
| P2-7 联合验收 | 覆盖权限变更、重连、源设备与服务器重启、多账号退出、移动端、原首页与文件台回归 |

P2-3 与会员部分可在实时生命周期接缝稳定后分别推进，不能共享一个全站播放器状态。权限和数据接口先约定后整合，阶段结束必须检查组合场景，不以各模块单独通过代替联合验收。

v3 主要对应：08／18／37／39 监控，14／15／20／21／32／36／38 实时源，26 中的监控与实时部分。Plus、全局用户及特殊授权的若干新状态并没有现成完整图纸，应按 QA 与既有视觉体系补齐，不能照搬旧“所有观看者共享控制”按钮作为最终权限设计。

本指南没有修改原型页面或生成新图，也没有宣称原型中已有真实会员、实时传输和权限能力。

## 9. 第二阶段验收清单

以下为开发后的验证要求，不是已执行结果。至少使用两个不同设备／浏览器验证，真实屏幕与摄像头不能仅靠媒体模拟对象代替。

| 验收组 | 场景与通过条件 |
| --- | --- |
| P2-A 初始采集 | 摄像头、屏幕／窗口／标签页选择及声音实际能力；拒绝／取消不误报开播；切模式保留文件节目单；多台不互相顶掉 |
| P2-B 暂停、无人观看与下线 | 全局暂停保留预览、停外发；仍上线的实时台无人时保留采集、不外发，有人再进入时追当前实时；不得因此解除全台暂停或下线；台单独下线且账号在线保留会话，远程上线复用；本机暂停观看不影响他人；无录制补播 |
| P2-C 会话结束 | 系统停止共享、关页、权限丢失后远端显示需要源设备动作；不伪造可静默重建的屏幕共享；实际恢复授权后再确认供流 |
| P2-D 身份生命周期 | 切当前账号不中断另一有效账号台；账号退出／真实失效结束它的采集及对外服务，不误停其它账号／无归属台；源设备重新登录不自动开播 |
| P2-E 远程归属 | B 从远端观看入口管理归属自己的台，只有节目单编辑限于 A，其它管理操作均可用，覆盖基本信息、台设置、邀请、访问、特殊授权、删除及放弃归属；不将 A 的台或文件副本导入 B；A 离线后重连不覆盖远程结果或复活已删除台；不能遥控 A 登录或绕过浏览器权限 |
| P2-F 监控 | 仅监控可多台同看，与普通／后台／小窗观看互斥；一／四／九格、profile 和全屏返回；初次全部有声，各格静音／音量可保存并恢复，自动播放受限不改写配置；资源受限时保留全部格位、提示并支持选择实际观看格子，未启动格子不暗中接收或解码；离开结束全部接收且不恢复旧后台，重新打开按 profile 校验后观看；批量只影响本机，某格失败不拖垮其它格 |
| P2-F1 格内控件 | 默认仅右上角小静音开关；左键／单指点击画面非按钮处后，隐藏静音开关并显示中央播放／暂停、左下纵向音量短条及右下全屏；再次点击非控件处或闲置 2 秒收起并恢复静音开关，拖动音量时不自动收起；控件操作不误触展开／收起，展示状态不改写声音配置；单格全屏退出回监控方阵 |
| P2-F2 单格全屏声音 | 其它已启动格子继续播放但临时静音；当前格子遵循自身静音／音量，不强制开声；退出后按各格原设置恢复，原本静音的仍静音；临时静音不写入 profile，期间保存也不污染配置；直接离开监控不恢复已结束播放 |
| P2-G Plus | Mock 标识、登录门槛及跨设备同资格；默认跟随、个人自由、返回全局；同账号手机电脑自由位置各自独立；不改他人和全局 |
| P2-H 免费与付费边界 | 普通用户仍可静音、调音量、暂停本机和阅读滚动；无 Plus 不能自由选节目／拖动；Plus 不能越过邀请、踢出、下线或读取其它来源，实时无时移 |
| P2-I 创作者会员 | 会员按创作者用户区分，与 Plus 不互相开通；Mock 加入不自动获取观看或管理许可；无归属台不伪造创作者 |
| P2-J 特殊授权 | 从当前已登录观看者选择、输入账号 ID 提前授权均正确绑定用户；三项播控分别勾选与校验，一项不隐含另外两项；仅作用于所选用户和台，非会员可获明确授权，提前授权不附带私人台观看资格；覆盖默认长期、指定到期及主动撤销，到期／撤销／放弃归属后不能继续操作，重连或迟到请求不复活权限，观看许可／书签不被误删 |
| P2-K 混合场景 | Plus／普通观看、归属远程操作、监控本机控制与被授权全局操作同时发生；迟到消息和重连不覆盖新状态或复活旧权限 |
| P2-L 回归与资源 | 第一阶段文件、邀请、Markdown 支线、订阅及重启恢复；原有摄像头、文件转发与还原、传输进度、音乐播放器、网盘、网页工坊、登录／多账号、首页手势及通知；监控反复进入退出和长时间播放的内存、连接及后台任务有界，离开后的释放有证据 |

报告各项使用的设备、浏览器、源类型、授权／登录条件与实际结果。浏览器后台、移动端屏幕共享或采集音频不支持时应如实记录能力范围，不能拿 PC 单一环境通过推断 Android／iOS 也通过。

## 11. 本轮复核问答与未决事项

本节记录 2026-11-02 本轮复核，作为本指引的最新补充；原始 QA 的历史问答及原型暂不重写。

### 已确认

- 原型同样存在与当前实现冲突的部分，以当前实现及最新明确需求为准，不按旧快照回退功能和布局。
- 用户澄清：“同设备可同时观看多台”只指监控大爷模式，普通观看、后台和小窗维持单台。
- 用户选择：收起监控或返回首页后结束多路接收、保留布局，重新打开监控时恢复观看。
- 监控进行时不保留方阵外的后台播放，跳出监控也不保留后台，只保留 profile。第 3 节据此约束进入、离开和重新打开的行为；仅退出全屏仍留在同一监控 profile，不属于离开监控。
- 设备资源不足时允许限制监控实际同时播放数，保留全部格位和 profile，对未启动格子明确提示，允许用户选择实际观看的格子；具体上限需实测确定。
- 初次进入某个监控 profile 默认开启全部声音。用户可自由调整各格静音状态和音量并保存到 profile，下次进入沿用已保存设置；保存配置不等于保留后台播放。
- 单格控件加载后默认仅显示右上角很小的 `🔇/🔊` 开关；左键或单指点击画面非按钮处后隐藏该开关，显示横竖中央的 `▶/❚❚`、左下角纵向音量短条和右下角 `全屏`。再次点击画面非控件处或闲置 2 秒收起并恢复静音开关，操作音量条期间不自动收起。
- 单格全屏时，其它已启动格子继续播放但临时静音；当前格子只在自身声音已开启时发声。退出全屏恢复其它格子原有静音／音量设置，原本静音的仍静音；临时静音不保存到 profile。
- 仍上线的摄像头／屏幕台无人观看时，保留已授权采集，无人时不外发媒体，有观众时恢复供流并接入当前实时；不录制补播，也不以新观众进入解除主动全台暂停或下线。
- 特殊授权第一批包含“全台播放／暂停”“切换节目”“调整文件全台进度”，三项分别勾选；不包含来源编辑、删除台或变更归属。
- 特殊授权默认长期有效，可选择到期时间，并可随时撤销。该期限是播控操作授权的期限，与邀请链接期限分别管理。
- 授权对象既可从本台当前已登录的观看者中选择，也可输入账号 ID，提前给尚未进入本台的用户授权；不因此附带私人台观看资格。
- 归属用户可跨设备授予、修改和撤销特殊授权；用户进一步将远程管理范围明确为：除节目单只能在最初创建该台的设备编辑外，其它管理功能均可使用。第 6.2 节据此替代旧 QA／指引中的远端删除及放弃归属等限制；被授权用户的三项播控范围不随之扩大。
- 用户重申文件缓存的后续修订：考虑现实网络环境，观看端可保留缓存；本地导入节目在创建设备的浏览器缓存中保存内容副本，以保证功能稳定性。第 7.1 节据此替代早期笼统的“不复制或保留源内容”限制。
- `启用即时控制` 留待独立优化，第二阶段不新增开关；所有留待以后处理的事项集中整理到指定的[第三阶段开发指引](streaming-console-phase3-guide-261019.md)，并区分已延期、条件性议题及未纳入范围。
