# 串流控制台第二阶段开发指引：实时源、监控、Mock 会员与特殊授权

编制日期：2026-10-19。状态：开发前指引，未表示功能已实现或已验收。

依据：[串流控制台 QA](streaming-console-QA-261016.md) 最新确认结论及其末尾“两阶段开发划分”。前置交付见 [第一阶段开发指引](streaming-console-phase1-guide-261019.md)，界面参考 [v3 原型说明](../resources/streaming-console-QA-261016/v3/README.md)。

## 1. 阶段范围与前置条件

本阶段在已可使用的文件台之上增加：摄像头实时源、屏幕／窗口／标签页实时源、监控大爷模式、平台 Plus Mock、创作者专属会员 Mock，以及创建者向观看者用户发出的串流台特殊授权。

这里的“屏幕录制”按 QA 定义落实为实时采集放送，不新增录制成文件、云端录像、回看或时移。本阶段没有真实支付、价格、账单、扣点和完整会员等级运营系统。

开发前复核第一阶段的身份、台归属、观看许可、设备隔离、全局状态、邀请及书签边界已经成立。不能用后加会员修补“普通观众已经能任意改全台进度”的错误，也不能为加摄像头重新实现一套独立的邀请和订阅系统。

QA 早期将管理员授权操作留待以后；用户此次阶段划分已把“串流台特殊授权”纳入第二阶段。仅改变开发阶段安排，不意味着会员等级、全量权限矩阵及授权期限已经确认，具体边界见第 6 节。

## 2. 摄像头与屏幕实时放送

### 2.1 来源模式与多台独立

- 文件节目单、摄像头、屏幕采集分别作为来源模式。摄像头和屏幕不插进普通文件节目单，也不参与图片停留倒计时或文件循环。
- 切换来源模式保留已保存的文件节目单和设置，不能为了直播清空原文件配置。
- 摄像头由创建设备选择实际可用输入并主动授权。屏幕共享由浏览器选择屏幕、窗口或标签页；是否可采集音频按实际设备及浏览器能力显示。
- 保存台配置不等于永久保存采集权限。首次启动或需要新建采集会话时，必须遵守浏览器授权及本机操作要求；拒绝或取消后保留配置，不显示已经开播。
- 同设备可发起多个不同台，也可同时接收其它台；某个台的切换、暂停、停止和失败，不能覆盖其它台或原项目已有摄像头功能。

本阶段不额外宣称支持 RTMP、RTSP、SRT、HLS 等未确认协议。优先复用既有 WebRTC／信令和采集能力，但串流台运行范围独立，不能直接沿用原单个摄像头广播状态而让多个台互相替换。

### 2.2 必须分开的五种动作

| 动作或状态变化 | 采集及对外发送 | 观看与恢复 |
| --- | --- | --- |
| 接收端暂停本机观看 | 不改变源设备采集或其它观看端送流 | 仅本机暂停；恢复追当前实时 |
| 有权操作者执行全台暂停 | 保留本机采集预览，停止对所有观看端发送；本机明确显示仍在采集 | 全台恢复后看当前实时，不补播暂停期间内容 |
| 账号在线，仅将台设为下线 | 保留仍有效的已授权采集会话，停止对外发送，源设备显示该状态 | 归属用户可从其它设备将台上线，复用有效会话恢复发送 |
| 主动停止本机采集、共享被系统停止、页面关闭或权限丢失 | 实际采集会话结束或不可用，不假装仍有媒体可发送 | 显示需要在源设备恢复采集／授权；不能仅靠远程上线命令静默重建屏幕共享 |
| 归属账号主动退出或确认登录失效 | 其本机归属台下线锁定，结束其对应的本机采集使用 | 用户亲自到源设备恢复登录及必要采集授权；恢复资格不自动上线 |

结束某个账号的采集使用时，不能误停其它仍登录账号或无归属台。若底层采集被复用，也应按实际使用范围处理，不能简单停止全设备全部媒体轨道。

控制台收起、打开其它功能、当前账号切换、台单独下线及账号退出不得混用一套清理动作。源设备离线不等于账号已失效，但实际无法继续的实时源必须显示不可用，不能假装与网盘文件一样可独立续播。

### 2.3 远程恢复的产品目标与浏览器边界

用户已确认：账号在源设备有效在线时，可由有权归属用户在其它设备控制台上下线，目标是尽可能自动恢复实时供流。Q46 采用保留仍有效采集会话的方式支持该目标。

必须区分：

1. 仍有效的已授权会话：台下线后重新上线，可恢复发送，不额外制造“必须本机点一次”的产品限制。
2. 已结束的屏幕会话：普通网页新调用 `getDisplayMedia()` 仍需要源页面上的用户操作和屏幕选择，不能静默绕过。远端应显示当前阻碍及需要在源设备完成的动作，不能提前显示恢复成功。
3. 摄像头会话：按已有许可、硬件和浏览器实际状态处理，不把屏幕共享的每次选择机制机械套到摄像头，也不承诺任何状态都能自动恢复。

Q45 已记录 [W3C Screen Capture](https://www.w3.org/TR/screen-capture/#dom-mediadevices-getdisplaymedia) 及 [MDN 安全要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia#security)；实施时复核所测浏览器，不把规范阅读当作实机验收。

### 2.4 实时观看界面

显示实时来源、送流状态、连接和实际播放状态，不显示文件进度拖动、快进快退或历史回放。静音、音量、本机观看暂停与全台暂停分开；暂停发送期间不偷偷录制或补播。

全局暂停、台下线及采集仍在进行的提示必须能够辨认，避免让源设备用户误认为摄像头或屏幕已经关闭。权限拒绝、设备占用、采集结束和播放受限按实际情况提示。

## 3. 监控大爷模式

### 3.1 方阵与台选择

允许同屏接收多个文件台或实时台，提供单画面、四宫格、九宫格等原型所示布局，支持添加、移除台及保存、恢复布局预设。

布局按当前设备保存，不随同账号自动同步到另一设备。添加台只改变本机布局，不自动订阅；订阅书签可以提供选择入口，但不是观看授权。恢复布局时逐台检查访问资格和实际来源状态，不借布局保存私人台访问能力。

台下线保留格位，显示状态；重连、被踢或等待采集不能随意挤走其它格位。移除格位不删除台、来源或账号书签。

### 3.2 单格及批量控制

- 单格提供本机静音／取消静音、暂停／播放观看；批量按钮对当前选定范围执行同类本机操作。
- 批量操作不修改全局节目、进度或其它观看者状态，也不因某格台归属于自己就偷偷改变整台播放。
- 如需全局管理，进入单台并明确全局操作范围，继续检查归属或特殊授权；不能从普通墙面按钮隐式升级权限。
- 退出或收起墙面按既定界面与运行生命周期处理，不自动删除布局、取消订阅或下线来源台。
- 方阵沉浸全屏保留多台布局，不误切成单个播放器全屏；退出后恢复清单、布局与原有状态。

### 3.3 与观看模式的关系

普通观看者的各格默认跟随对应台的全局状态。本机暂停后恢复追全局；Plus 用户的个人模式按第 4 节处理，不能通过进入方阵为普通用户免费提供个人拖动进度。

每格独立维护媒体、连接和状态，限制合理的并发解码、缓冲与网络开销。某格失败不能使其它格或首页卡死；资源释放不能中断仍被其它前景／后台观看使用的台。浏览器后台限制和自动播放失败需显示真实结果，不以格子存在等同于正在播放。

## 4. 平台 Plus Mock 与个人自由观看

### 4.1 资格与开通

Plus 绑定用户账号，不绑定设备或某个台。本阶段提供清楚标注为 Mock 的开通与资格展示，复用全局登录；未登录先登录，不创建设备级 Plus。

同一账号在不同设备使用同一资格；不因此同步隧道、创建配置或各端个人播放位置。Mock 不代表真实付款成功，不自行增加价格、固定购买周期、点数扣费或真实订单。

Plus 与普通台订阅书签、创作者专属会员分别显示。Plus 不能绕过仅邀请台、被踢设备、下线、来源失效或台资源范围等限制，也不获得管理他人台的权力。

### 4.2 跟随与自由观看

| 模式 | 节目及进度 | 对其它观看者的影响 |
| --- | --- | --- |
| 默认跟随 | 跟随台的当前全局节目和目标进度 | 无额外影响 |
| Plus 个人自由观看 | 本人可选择已经导入的节目及调整文件播放进度 | 不改全局状态，不影响其它设备 |
| 返回全局同步 | 放弃当前自由位置，取得最新全局节目与进度 | 不把个人状态写回全局 |

同一 Plus 用户在手机、电脑均自由观看时，各端节目和进度独立。一端换节目、拖动或返回全局，不改变另一端；不因账号共用资格而建立账号唯一的播放游标。

自由选择范围仍是台已导入并允许观看的节目，不开放来源目录或持续随机抽取。实时源没有文件时间轴，Plus 不因此获得录像、回看或时移。

本机静音、音量、暂停观看和文档滚动继续免费；不得为了 Plus 收回第一阶段已经确认的这些普通操作。Plus 是个人自由观看能力，与创建者或被明确授权者的全局播控分开。

未来若出现广告，Plus 可用于免广告；本阶段不为满足这条预留原则专门开发广告系统。真实月／季／年付费和点数形式继续留待后续。

## 5. 创作者专属会员 Mock

在有归属用户的台显示创作者及主页，并在该创作者范围提供 Mock 加入及会员身份展示。归属账号是会员对象，不是来源设备；同一创作者在多个设备发布台，不需要对每台重复购买一个相同概念的创作者身份。

无归属台没有创作者用户名是正常状态，不能把当前设备登录者冒充其创作者，也不能为它伪造会员归属。

创作者会员独立于平台 Plus，加入不自动成为管理员，不自动获得私人台观看许可，也不自动获准全局播控。成为会员可以是创建者决定授予权限的业务参考，但不是系统强制条件；非会员仍可被明确授权。

本阶段不擅自设计等级名称、价格、等级递进、成员专享内容或完整等级权益。QA 只确定了 Mock 加入与身份及它和特殊授权的关系，完整等级业务以后细化。

## 6. 串流台特殊授权

### 6.1 已确认且必须落实的原则

- 由台的归属用户明确授权给观看者用户，双方使用用户身份；不能把匿名设备标识当作会员账号替代。
- 按具体台、具体操作设置；不自动作用于创建者所有台或其它用户的台。
- 会员不是授予或使用权限的硬性前提；Plus、创作者会员、观看许可、订阅书签均不能直接换算为全局管理权限。
- QA 已举出的能力包括控制全局进度、切换节目。这样的操作会影响全局跟随者，应明确显示作用范围，不能伪装成 Plus 个人控制。
- 授权不扩大台所选来源的读取范围，不开放来源网盘或隧道管理；不能把“管理员”三个字等同于修改来源、删除台或转移归属的完整权限。
- 放弃台归属时，撤销原归属用户针对该台授予的特殊权限，保留普通观看许可及账号书签。之后重新认领不能自动复活旧授权。
- 所有授权请求及实际控制操作在服务端检查当前身份、台归属及有效权限；迟到操作不能绕过已经生效的权限变更。

### 6.2 尚未确认的细则与开发入口条件

本次阶段划分把此项纳入第二阶段，但 QA 没有确认完整授权菜单、是否还包含播放／暂停等其它操作、有效期限及管理界面细节，也没有确认创作者自定义等级如何映射到权限。

进入这项具体实现前，应基于上述原则列出准备提供的实际操作与影响，补齐真正影响验收的细则；不能把早期举例自动扩成来源编辑、删除、邀请管理等全部权限。也不能把未确认的等级体系作为摄像头、监控或 Plus 开发的前置条件。

已经明确的“归属用户在其它设备可做什么”继续按第一阶段权限矩阵执行，不应借本项重新限制或扩大。授权功能的真实完成与验收，应以届时补齐的具体清单逐项记录；不得仅搭建数据结构就宣称功能全部完成。

## 7. 第一阶段规则在扩展后仍须成立

- 每个台依旧只有一份全局权威状态。Plus 自由观看是个人模式，监控墙是本机组合，不另造互相覆盖的全局状态。
- 公开／仅邀请／下线、通用／定向邀请、24 小时默认期限、踢出与重新允许等规则同样适用于实时台；会员资格不能绕过它们。
- 订阅仍是账号级收藏，不是设备订阅，不要求订阅后才能观看，也不因移除格子或关闭采集而自动取消。
- 本机台配置、加入的隧道和监控布局不自动跨设备同步。用户主页公开聚合与同账号远程有限管理继续使用观看者视角。
- 多账号保留登录与切换当前账号继续分开；账号退出／确实失效只处理其本机归属台，不影响其它在线账号或无归属台。
- 不为了直播、Plus 或监控偷偷建立文件副本、录像或保底缓存，不冻结来源。文件台的设备离线续播和服务器重启恢复不被实时源改造破坏。

## 8. 开发顺序与原型整合

| 顺序 | 交付内容与依赖 |
| --- | --- |
| P2-1 实时来源适配 | 复用第一阶段台、观看许可和状态服务；补摄像头／屏幕配置、授权、供流、接收及明确错误状态 |
| P2-2 生命周期 | 完成全台暂停、台下线保留采集、远程复用恢复、账号下线终止及多账号隔离；覆盖真实浏览器权限和轨道结束事件 |
| P2-3 监控墙 | 基于独立观看实例完成一／四／九格、本机单格及批量控制、布局预设和多画面全屏 |
| P2-4 Plus Mock | 完成账号级资格、个人自由观看及返回全局，同账号多设备游标独立；确认实时源没有新增回看 |
| P2-5 创作者会员 Mock | 完成按创作者用户的加入及身份展示，验证与 Plus、观看权和特殊权限分离 |
| P2-6 特殊授权 | 先补齐第 6.2 节的实际操作细则，再做创建者授权、逐操作校验、失效处理和对应 UI；不实现未确认的完整等级系统 |
| P2-7 联合验收 | 覆盖权限变更、重连、源设备与服务器重启、多账号退出、移动端、原首页与文件台回归 |

P2-3 与会员部分可在实时生命周期接缝稳定后分别推进，不能共享一个全站播放器状态。权限和数据接口先约定后整合，阶段结束必须检查组合场景，不以各模块单独通过代替联合验收。

v3 主要对应：08／18／37／39 监控，14／15／20／21／32／36／38 实时源，26 中的监控与实时部分。Plus、全局用户及特殊授权的若干新状态并没有现成完整图纸，应按 QA 与既有视觉体系补齐，不能照搬旧“所有观看者共享控制”按钮作为最终权限设计。

本指南没有修改原型页面或生成新图，也没有宣称原型中已有真实会员、实时传输和权限能力。

## 9. 第二阶段验收清单

以下为开发后的验证要求，不是已执行结果。至少使用两个不同设备／浏览器验证，真实屏幕与摄像头不能仅靠媒体模拟对象代替。

| 验收组 | 场景与通过条件 |
| --- | --- |
| P2-A 初始采集 | 摄像头、屏幕／窗口／标签页选择及声音实际能力；拒绝／取消不误报开播；切模式保留文件节目单；多台不互相顶掉 |
| P2-B 暂停与下线 | 全局暂停保留预览、停外发；台单独下线且账号在线保留会话，远程上线复用；本机暂停观看不影响他人；恢复只追当前实时，无录制补播 |
| P2-C 会话结束 | 系统停止共享、关页、权限丢失后远端显示需要源设备动作；不伪造可静默重建的屏幕共享；实际恢复授权后再确认供流 |
| P2-D 身份生命周期 | 切当前账号不中断另一有效账号台；账号退出／真实失效结束它的采集及对外服务，不误停其它账号／无归属台；源设备重新登录不自动开播 |
| P2-E 远程归属 | B 仍是观看者视图及有限管理，不获取 A 的配置；可遥控有效会话的台上下线，不能遥控 A 登录或绕过浏览器权限 |
| P2-F 监控 | 多个文件／实时台同时显示；一／四／九格、格位保留、预设和全屏返回；批量只影响本机，某格失败不拖垮其它格 |
| P2-G Plus | Mock 标识、登录门槛及跨设备同资格；默认跟随、个人自由、返回全局；同账号手机电脑自由位置各自独立；不改他人和全局 |
| P2-H 免费与付费边界 | 普通用户仍可静音、调音量、暂停本机和阅读滚动；无 Plus 不能自由选节目／拖动；Plus 不能越过邀请、踢出、下线或读取其它来源，实时无时移 |
| P2-I 创作者会员 | 会员按创作者用户区分，与 Plus 不互相开通；Mock 加入不自动获取观看或管理许可；无归属台不伪造创作者 |
| P2-J 特殊授权 | 按确认后的具体操作逐项检查；仅作用于所选用户和台，非会员可获明确授权，会员不能未经授权控制；放弃归属使旧特殊权限失效，观看许可／书签不被误删 |
| P2-K 混合场景 | Plus／普通观看、归属远程操作、监控本机控制与被授权全局操作同时发生；迟到消息和重连不覆盖新状态或复活旧权限 |
| P2-L 回归与资源 | 第一阶段文件、邀请、Markdown 支线、订阅及重启恢复；原有摄像头、文件传输、音乐播放器、网盘、首页手势及通知；长时间多台播放无明显资源泄漏 |

报告各项使用的设备、浏览器、源类型、授权／登录条件与实际结果。浏览器后台、移动端屏幕共享或采集音频不支持时应如实记录能力范围，不能拿 PC 单一环境通过推断 Android／iOS 也通过。

## 10. 不在两个阶段中自动扩展的事项

真实支付、包月／包季／包年／点数计费，完整创作者等级及运营权益，主动向其它设备同步台配置或隧道集合，文件随机播放，云端录像、时移与新串流协议，均不因本次分期自动纳入。

已移出的 Media Library 删除及取帧问题不属于这份串流开发计划。新增细则应回到 QA 记录确认，不把开发时的技术选择当作未经确认的新产品需求。
