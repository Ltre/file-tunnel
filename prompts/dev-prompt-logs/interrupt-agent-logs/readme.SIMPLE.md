这里存放因各种原因被中断执行的Agent执行记录

命名原则：
    以"ir-"开头，接需求编号，
    例如`ir-261003-1.log`
    
内容格式例如：
    ```
    [编号261003-1]问：

        XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
        XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
        XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

    [因额度不足被中断]答：

        YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY
        YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY
        YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY
    ```

如何向Agent提任务恢复需求？
以下是示例的`任务恢复需求`


-------------------------------------------------------------
               `任务恢复需求`示例1 - 简单
-------------------------------------------------------------

    [编号261003-2]问：

        上一轮任务(`编号261003-1`)因额度不足被中断，请结合`prompts\dev-prompt-logs\interrupt-agent-logs/ir-261003-1.log`中对于上一轮需求和Agent执行记录，以及在本Codex程序中的记忆上下文，定位上一轮任务被中断的位置，并按照`ir-261003-1.log`中的原始需求，继续执行任务。
        特别注意：如果上一轮任务的中断点恰好存在没有完美收尾的情况，那么应该完整验收该细节的完成度，避免中断点出现未完成/错误完成的情况。


-------------------------------------------------------------
                 `任务恢复需求`示例2 - 严谨
-------------------------------------------------------------

    [编号261003-2]问：


        上一轮任务（`编号261003-1`）因额度不足被中断。请结合 `prompts\dev-prompt-logs\interrupt-agent-logs/ir-261003-1.log` 中记录的上一轮原始需求及 Agent 完整执行过程、本 Codex 程序中的记忆上下文，以及当前工作区的实际代码状态，准确恢复上一轮任务的执行上下文，并继续完成任务。

        当前工作分支为 `dev/2609-s5-disk-chunks-progressive-push`。除 `prompts/dev-prompt-log/dev-2609.md` 以外，本分支当前所有**未提交、未暂存的代码相对于 HEAD 的差异，均属于上一轮任务产生的改动**。恢复任务时应将这些现有差异作为判断上一轮实际执行进度的重要依据，不要误删、覆盖或重复实现。

        恢复时不要简单地从日志最后一行机械续接。应根据上一轮原始需求，结合执行记录、记忆上下文以及当前相对于 HEAD 的实际代码差异，逐项核对并区分：哪些内容已经正确完成、哪些正在执行时被中断、哪些尚未开始，同时检查中断前产生的代码修改是否已经完整落地，避免重复修改、遗漏修改或破坏已经正确完成的成果。

        特别注意：如果中断点恰好位于某项修改、测试或验收过程中，应重新检查该细节及相关代码的实际完成状态，不能默认中断前的操作已经成功完成。确认中断点不存在半成品、错误完成或状态不一致的问题后，再从正确的位置继续执行。

        最后，应重新按照 `ir-261003-1.log` 中 `编号261003-1` 的原始需求对整个任务进行完整验收，而不能只验收本轮续接后新增的部分，确保上一轮任务最终整体完整、正确地完成。

    - `description` 以中文为主；

    - 每个小节使用几行列表概括主要修改；

    - 将git日志的title和description分开显示，并分别使用代码模式以便于一键复制。
