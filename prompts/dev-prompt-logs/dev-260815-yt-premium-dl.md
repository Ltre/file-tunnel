# 私人 Youtube Premium 媒体下载功能

在现有系统中增加一个**仅供私人使用的 youtube premium 媒体下载页面**。该页面入口位于 /admin页面，并且使用管理员身份校验。

本功能使用**独立的私人 YouTube Premium 账号 Cookie**，不得与系统公共 SNS 下载使用的 Cookie 混用。

## 1. 私人配置与安全

* 在 /sns-cookies 页面中增加一个新textarea框（标题写"私人 Youtube Premium"）以填写私人专用cookies。
* 不得下发到浏览器。
* 不得写入普通任务记录、日志或错误详情。
* 一般的youtube下载任务继续使用现有的Youtube/YTMusic Cookie配置，而私人Youtube Premius媒体下载功能页面的下载任务则使用私人Youtube Premius的cookies。
* 私人页面除隐藏入口外，还应有独立的服务端访问校验；隐藏 URL 本身不能作为唯一权限控制。

## 2. 页面主要区域

页面顶部提供：

```text
URL
[________________________________]

抓取方案：
(*) 默认
( ) 自定义

[开始下载] 
```

下方为私人下载任务记录区域，并支持分页。

---

## 3. 默认抓取方案

选择“默认”时，不显示格式选择区域。

用户提交 URL 后，先识别媒体类型。

### 音乐

如果识别为音乐，完全复用目前已有的音乐下载方案，包括：

* 默认音频格式/质量选择；
* 文件命名；
* 歌曲名称；
* 艺术家；
* 专辑；
* 年份；
* 时长；
* 比特率/编码；
* 封面；
* 现有音乐元数据填充逻辑。

不要重新实现另一套音乐下载规则。

### 视频

如果识别为普通视频，完全复用目前已经存在的视频默认下载方案：

* 自动选择现有默认视频码率/格式；
* 自动选择现有默认音频码率/格式；
* 必要时由 yt-dlp/ffmpeg 合并；
* 最终生成一个正常的视频文件。

---

## 4. 自定义抓取方案

用户选择“自定义”后，在 URL 输入框下方出现“媒体格式”区域。

输入 URL 后，服务端使用该私人 Cookie 执行等效于：

```bash
yt-dlp -F <URL>
```

的格式分析。

分析期间显示：

```text
正在解析媒体格式...
```

解析成功后，把 `yt-dlp -F` 得到的所有可选 format 按行展示。

每一行至少显示：

```text
[checkbox] Format ID

类型：视频 / 音频 / 视频+音频
容器：webm / mp4 / m4a ...
分辨率：1920×1080 / 1280×720 ...
FPS
视频编码
视频码率
音频编码
音频码率
采样率
文件大小（能够取得时）
其他 yt-dlp 返回的重要格式信息
```

纯音频格式不显示无意义的视频字段。

### 默认勾选

所有格式加载完成后，系统仍然先执行一次现有“默认抓取方案”的格式选择判断。

然后自动勾选默认方案实际会使用的 format ID。

例如默认方案最终使用：

```text
137 + 140
```

则格式列表加载完成后自动勾选：

```text
[x] 137  视频
[x] 140  音频
```

用户可以在此基础上自行修改。

### 格式组合规则

自定义模式允许：

* 选择一个已经包含音视频的完整格式；
* 或选择一个纯视频格式 + 一个纯音频格式，由现有 ffmpeg 合并逻辑生成最终文件；
* 纯音乐下载可以选择一个音频格式。

应阻止明显无效的组合，例如同时选择多个互相冲突的视频格式后直接合并。

开始下载前，在页面上显示最终选择，例如：

```text
最终格式：137 + 140
视频：1080p / AVC
音频：AAC 128kbps
输出：MP4
```

## 5. 下载任务

点击“开始下载”后创建一条私人下载任务。

任务状态至少包括：

```text
等待中
解析中
下载中
合并中
元数据处理中
已完成
失败
已取消
```

下载中显示：

* 百分比；
* 已下载大小；
* 总大小（能够取得时）；
* 下载速度；
* 预计剩余时间。

完成后显示：

* 标题；
* 来源 URL；
* 封面；
* 使用的抓取方案：默认 / 自定义；
* 实际 format ID 或 format ID 组合；
* 最终文件名；
* 文件大小；
* 完成时间；
* 下载/获取文件入口。

任务失败时保存简化后的失败原因，但不得把私人 Cookie、Cookie 文件路径或敏感 yt-dlp 参数写入任务详情。

## 6. 私人任务记录

私人功能页下方保存该功能产生的任务历史。

任务记录与普通隧道传输记录分开，不要自动出现在任何普通隧道中。

按创建时间倒序排列，并提供分页。

每条任务至少保存：

```js
{
  id,
  url,
  title,
  cover,
  mode: "default" | "custom",

  selectedFormatIds,
  mediaType,

  status,
  progress,

  outputFileName,
  outputFileSize,

  error,
  createdAt,
  completedAt
}
```

刷新页面或重新进入私人功能页后，仍能查看以前的任务。

正在运行的任务重新进入页面后应恢复当前任务状态和进度展示。

## 7. 与现有代码的复用要求

优先复用现有已经实现的：

* URL/SNS 类型识别；
* yt-dlp 调用封装；
* YouTube 音乐识别；
* 音乐默认格式选择；
* 视频默认格式选择；
* ffmpeg 音视频合并；
* 音乐元数据提取和写入；
* 封面处理；
* 下载进度解析；
* 文件下载/获取能力。

不要为了私人页面复制一套相同的 yt-dlp 下载实现。

应把“公共 Cookie”和“私人 Cookie”作为不同的下载凭据来源传给同一套底层下载服务：

```text
公共 SNS 功能
    ↓ public credentials

             → SNSDownloader → yt-dlp

私人下载页
    ↓ private credentials
```

两者的 Cookie、任务记录和权限必须保持隔离。
