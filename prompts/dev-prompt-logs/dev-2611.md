    ---------------- 

    目前markdown/网页ZIP还是以隧道内设备之浏览器缓存为存储介质，并非服务端存储。因此对于一些需要公开给他人的传输记录，应该提供以telegram网盘为存储基础的服务端托管。

    用户可以对任意传输记录点击其汉堡菜单的`加入个人库`按钮，传输记录的元数据及文件内容

    将按照以下类型对应策略执行存储：
        纯文本 - 直接保存到sqlite
        富文本 - 文本整体结构和引用的文件分开保存到网盘，一些必要的关联数据保存到sqlite
        markdown - 文本整体结构和引用的文件分开保存到网盘，一些必要的关联数据保存到sqlite
        网页zip本身 - 整个html.zip文件保存到网盘，一些必要的关联数据保存到sqlite
        单文件/合辑 - 文件保存到网盘，，一些必要的关联数据保存到sqlite

    用户在个人库中可以对所加入的传输记录点击`发布`按钮，将会执行：
        读取sqlite获取传输记录的必要关联数据，组成发布后的落地页内容框架；
        从网盘中查找这条记录所引用到的所有文件，为这些文件启用静态资源开放，静态链接的有效期根据`发布`时设置的有效期为准；
        在内容框架中引用这些文件的静态链接，组成内容完整的落地页，这一步的落地页是由服务端动态获得的，可以直接预览，但仅限该个人库的用户账号下可见；
        将内容完整的浏览面静态化存储于网盘指定位置并启用网页静态链接，链接有效期根据`发布`时设置的有效期为准；
        将个人库中的本条记录标记为已发布，并关联静态链接及有效期。

    后台增设"用户内容库"页面。该页面会有一个`基础设施设置`，没有配置的都会强制切换到`基础设施设置`界面，已经配置了的，会默认切换到内容库列表。
        在`基础设施设置`界面，要求指定所有用户内容库统一保存的位置（网盘账号->分区->目录路径）。
        入库存储具体位置：在指定网盘位置下，被传输记录引用的文件保存的接续目录路径为 `TUN-{隧道ID}/{传输记录ID}/files/`。
        发布产物存储具体位置：发布的落地页保存的接续路径为`TUN-{隧道ID}/{传输记录ID}/index.html`。并为此接续目录`TUN-{隧道ID}/{传输记录ID}/`启用静态资源作用域开放。接着在落地页面中，直接以`files/`为前缀的相对路径引用文件。

    对于隧道中的同一条传输记录，多个用户都将其加入到个人库，仅需保存一份到网盘即可。并且共享发布状态（是否已经发布对外静态链接）。
