# 网盘协同挂载、目录上传与文件编辑开发指南（精简原则版）

## 使用约定

适用于 `dev/2609-s7-disk-partition-collaboration-mount` 分支。本指南合并两份旧稿，并纳入用户最新确认：**Mount 开放静态资源后仍允许本地改名、移动、删除；普通分享不冻结原文件。**

本稿作为后续开发的统一需求依据。两份旧稿仅保留为调查参考，冲突内容以本稿及用户后续修正为准。

各项功能必须满足下面的业务原则和验收结果；具体模块、接口、数据结构、状态名称和实现顺序由开发者结合最新代码合理选择，不机械照搬旧稿。复用已经稳定的能力，控制改动范围，保持现有数据和外围功能兼容。

## 1、回收站正确展示原始资料

**需求原则：**

- 显示删除前的文件名或目录名、完整原位置、类型、大小及删除时间；目录显示内部文件总大小和文件数量。
- 内部保留名称不能成为用户看到的名称。已经保存错误名称的历史回收站记录，也应依据可信原始资料修复；资料不足时明确提示，不猜测。
- 只修正展示资料，不能破坏回收站分区隔离、原层级、内容引用、整项还原及彻底删除规则。

**验收重点：**新旧回收站记录都能辨认原项目；还原后名称、位置和正文正确，名称冲突时明确说明原因。

## 2、协同列表固定关闭区域

**需求原则：**

- “查看协同列表”浮层的右上角关闭按钮和底部关闭操作区始终可见、可点击。
- 长列表只在中间内容区域滚动；兼顾窄屏、触摸滚动和虚拟键盘，不遮挡项目操作。
- 不改变原有协同列表入口的打开方式：受邀项目打开全屏协同页，自己创建的项目定位到自己的网盘。

**验收重点：**列表滚到任何位置，两处关闭入口都正常；原有项目入口和操作不受影响。

## 3、网页工坊从网盘导入显示 Loading

**需求原则：**

- 点击“导入”后立即显示按钮旋转 Loading，覆盖来源规划、完整读取和导入过程；草稿保存阶段也应有准确反馈。
- 期间禁止重复提交，但保留取消能力。成功、失败、取消都应及时结束忙碌状态。
- 取消后不得继续导入；文件未完整取得时，不留下看似成功的草稿节点。
- 保留网页工坊现有保存、最小化、预览、发布以及 20 层/100MB 项目限制。

**验收重点：**慢网络、多文件、失败和取消均有真实反馈，不假完成、不永久转圈、不产生残缺导入。

## 4、协同挂载在同一网盘界面中浏览和操作

### 4.1 入口与数据归属

- 点击原生目录中的 Mount，在当前网盘列表和面包屑中进入协同内容，复用网盘的列表/网格、排序、多选及操作体验，不再因此打开 iframe。
- 顶部“查看协同列表”和独立邀请页保持原有行为，不随挂载入口一起改造。
- 单文件挂载提供对应文件的预览、属性及允许的操作，不伪装成可任意下钻的目录树。
- Mount 始终是自己的本地指针，内部资源仍属于原所有者。浏览不是复制，不能把远端节点混入自己的原生目录或逻辑文件记录。
- 返回、刷新、搜索、分区切换及浏览历史应保持正确来源和位置，不能串用其它用户、分区或挂载的数据。

### 4.2 Web 操作与权限

- 内部支持多选、预览、下载、重命名、复制/移动、复制路径、属性、缓存到浏览器、复制到协同项目、转发到隧道、分享、复制静态链接及删除，按实际权限提供入口。
- viewer 可以读取、复制可读内容到自己的网盘以及分享；editor 才能在授权范围内修改、移动和删除原所有者的真实资源。
- 修改 Mount 名称、移动 Mount 或移除 Mount，只改变本地指针，不改远端名称、不删除远端内容。
- 删除协同内部文件/目录属于真实来源删除，应明确提示影响，并按现有 Web 删除规则处理；进入回收站时归原所有者，不能归挂载者。
- 不提供挂载内部的防失联修复、二次邀请或二次开启协同。保留授权根保护，禁止越界、父目录进入自身后代、重名及嵌套挂载污染。
- 权限由服务端实时验证，长操作完成前再次核对。撤权或来源失效后，不能依靠旧列表、缓存或旧链接继续读取和变更。

### 4.3 复制与跨边界移动

- 协同内部复制/移动按授权范围执行；跨协同项目复制及本人原生分区间复制/移动保持已有能力。
- Web 允许把协同内部文件/目录移动到自己的指定分区和目录，采用“完整复制成功，再删除来源”。目标副本属于自己，并正确复用共享内容。
- 复制失败不能删源；复制成功但删源失败，应明确显示“已复制，来源仍保留”，列出结果并提供安全重试。
- 来源正文、目录成员或授权在过程中改变时，不得凭旧快照删除新数据。取消、重复请求及服务重启也不能重复复制或误删。
- 来源进入回收站后，保留还原需要的内容引用；不能因目标已复制就提前清理来源仍需使用的正文。
- 本轮新增跨边界移动明确限于“协同 → 本人网盘”，不自行扩大到其它跨协同移动方向。

### 4.4 普通分享与 Mount 静态资源

- 普通分享不冻结原文件，无论原生分享还是挂载来源分享，都不因分享新增改名、移动、修改或删除限制；其它独立保护规则仍适用。
- 有读取权限的受邀用户默认可以再分享。挂载来源的分享记录只属于分享者，不在原所有者名下生成记录，也不重复存储正文。
- 分享访问始终限于所选范围，并验证来源及分享者的协同授权。来源删除、移出范围或授权失效时停止访问，不能把同路径重建的项目误认成原项目。
- 静态资源设置只作用于 Mount 本体，只在本地建立开放记录；内部项目不单独设置，只复制由 Mount 开放范围派生的链接。
- **Mount 开放静态资源后，不限制其本地改名、移动、删除。**建议依据稳定的挂载身份维护链接，尽量不受本地名称和位置变化影响；不得误绑定到其它资源。删除 Mount 后相关开放停止，后续访问失败。
- 本地开放不冻结原所有者的资源，也不改变其静态资源配置。远端相对路径改变时，旧路径链接可能失效。
- 明确服务器撤权与缓存的边界：后续服务端读取必须验证权限，但不能承诺收回用户或第三方已经保存的副本。缓存策略应兼顾此边界与用户配置，不擅自把某一种技术策略当成新需求。

### 4.5 S3 与传统网盘 API 只读

- Mount 本体及内部对 S3/传统外部网盘 API 一律只读，允许列出、属性及读取/下载；editor 身份也不获得 API 写权限。
- 禁止新增、上传、覆盖、改名、移动、删除和移除挂载；批量操作、不存在的子路径、复制目标及父目录递归操作也不能绕过。
- 对自己的普通原生资源保持现有 API 能力，不能把整个分区误设为只读。Web editor 的合法操作也不应被一并封禁。
- 凭证只代表调用者，不能变成原所有者身份；所有读取均限制在当前有效授权内。

**验收重点：**覆盖不同用户/分区、文件与目录挂载、viewer/editor、撤权、同名项目、原地与旧入口、分享/静态访问、跨边界移动部分失败及 API 间接写入。确认实际修改的是正确所有者的数据，本地删除指针绝不递归删除远端。

## 5、整目录全量下载（暂缓）

本轮不开发目录打包下载，也不开发“是否包含挂载协同内容”的全量下载选项。现有单文件下载保持不变。

## 6、系统目录递归上传与个人全局设置

**需求原则：**

- 支持从系统文件管理器拖入目录，完整枚举各层文件和目录，保留顶层名称、内部结构及空目录。浏览器能力不足或来源不可读时明确说明，不静默漏文件。
- 上传前完成全量枚举与校验，展示数量、总大小及目标分区/目录，经用户确认后开始。
- 个人网盘全局设置新增“上传文件夹最大尺寸”和“网盘允许最大目录层级”，默认分别为 500MB、30 层；持久保存并跨分区一致生效。
- 500MB 指同次来源目录内所有层级文件的合计大小，不是目标目录容量，也不替代现有单文件限制。统一大小单位，不能保留另一套固定 300MB 限额。
- 网盘系统目录上限统一为 30 层，个人设置可以降低，不能超过 30。层数包括真实目标已有层级和新增目录层级，不把文件名计为目录层。
- 各创建、上传、复制/移动、还原及 API 入口遵守同一有效规则；写入协同内容时按真实目标所有者的限制执行，不叠加本地 Mount 的虚拟层级。
- 降低限制不删除或隐藏已有深层数据；后续超限操作应明确拒绝。网页工坊自身的 20 层/100MB 规则不因此改变。
- 大目录自动分批，整体总量不能因拆批绕过校验。复用现有上传、内容复用、进度和恢复能力，保持既有批次的成功提交规则。
- 部分失败时准确说明成功、失败和未处理内容，支持安全重试或清理；不能承诺未实现的整目录原子回滚，不能删除目标中原有或后来修改的数据。

**验收重点：**30/31 层、500MB 边界、多目录合计、空目录、超过单批数量的目录、非 ASCII 名称、取消和断线恢复。前端预检与服务端权威校验一致，上传进度不能假完成。

## 7、新建和编辑纯文本、Markdown、十六进制文件

**需求原则：**

- 提供三种新建和编辑模式；Markdown、十六进制具有编辑与预览双栏，窄屏合理适配。
- 文本正确处理编码和换行；Markdown 预览防止恶意内容执行；十六进制保存真实字节，而不是其文字表示。输入错误和编辑能力限制明确提示。
- 创建和保存遵守名称、路径、分区、权限及独立保护规则。协同编辑保存到真实来源，不误存为挂载者自己的文件。
- 正文改变采用写时复制：创建或合法复用对应新正文的 Content Object，再只切换当前 Logical File 的引用；其它引用旧正文的文件保持不变。
- 正文未改变时无需产生新内容或高成本上传。普通编辑与同正文托管修复区分，不能为编辑放宽修复校验。
- 保存期间发生并发修改、删除或撤权时，明确报告冲突，保留用户编辑内容，不静默覆盖。
- 保存失败保留旧文件，妥善清理未关联的新资源；成功后更新预览、缓存及相关内容版本，不能继续展示旧正文。

**验收重点：**文本/Markdown/hex 保存重开正确，同共享内容的其它文件不被改动；并发冲突、失败恢复、缓存刷新和恶意预览内容均正确处理。

## 开发与验收共通要求

先完成小修复和来源/权限基础，再整合挂载操作、分享/静态及 API 只读，随后完善目录上传与文件编辑；具体顺序可依真实依赖调整。

每项都应验证实际结果，并覆盖并发、撤权、取消、失败和服务重启。不能只检查 UI 或源码文字；不能因远端传输长时间阻塞其它用户操作。涉及历史数据和持久化结构时，保留可恢复备份，迁移可重复且不破坏已有记录。

错误保留错误码，同时说明业务原因、操作结果和处理建议；不得泄漏敏感凭证或内部堆栈。开发记录写入 `docs/devlog/dev-2610-features.md`，明确真实测试结果及未验证事项。

完整覆盖需求 1、2、3、4、6、7，第 5 条标为暂缓。未经用户另行授权，不暂存、不提交、不推送。
