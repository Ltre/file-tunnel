# 网盘错误提示可读性增强实施指南

错误提示增强应保留现有错误码，同时补充**具体原因、操作影响和处理建议**。业务原因说明到用户能判断下一步；SQLite、Content Object 等底层原因只概括，不直接输出 SQL、堆栈或内部数据。

1. **统一显示格式**

   ```text
   复制失败 [CONTENT_COPY_SCOPE_INVALID]

   无法将目录“资料”复制到“资料/图片”：
   目标目录位于来源目录内部，当前不允许将目录复制到自身或其子目录。

   请重新选择来源目录之外的目标位置。
   ```

   错误码始终可见；只有确认事务已回滚时，才补充“本次未产生复制结果”，不能笼统承诺操作完全没有影响。

2. **后端区分具体拦截原因**

   同一个错误码下增加稳定的 `reason`，不要让前端猜测触发条件。例如：

   ```json
   {
     "error": "CONTENT_COPY_SCOPE_INVALID",
     "code": "CONTENT_COPY_SCOPE_INVALID",
     "userMessage": "目标目录位于来源目录内部，不能执行此次复制。",
     "errorDetails": {
       "reason": "DESTINATION_INSIDE_SOURCE",
       "requestId": "..."
     }
   }
   ```

   优先修改 `server/disk-api.js`、`server/disk-content-repository.js` 中共用错误码的校验分支，并扩展 `server/disk-errors.js` 的安全输出规则。数据库写入阶段发现的问题也要分类，不能全部归入“操作失败”。

3. **按原因生成可读说明**

   | 原因类别 | 应说明的业务细节 |
   |---|---|
   | 路径与作用域 | 来源、目标及越界方向；是自身、子目录、协同范围之外，还是不允许操作协同根目录。 |
   | 项目类型 | 单文件授权不能作为目标目录；来源与目标不能是同一个协同项目。 |
   | 权限与授权 | 来源无法读取、目标没有编辑权限、已退出协同、授权版本发生变化；建议刷新或重新选择。 |
   | 文件与目录状态 | 文件被删除、目录不存在、父目录不可用、来源在操作期间发生变化。 |
   | 名称与分区 | 哪个目标位置发生重名；目标分区已删除或不可用；复制后的目录层级超限。 |
   | 静态资源与挂载 | 哪个项目受静态开放保护；目录包含不能随此次操作复制的挂载项。 |
   | 内容引用与缓存 | 来源缺少可复用内容引用、正文暂不可用、租约过期、缓存或残留清理范围不合法。 |
   | 底层一致性 | 粗略说明“内容引用状态不一致”“目标写入信息不一致”“数据库写入发生冲突”，附请求编号供排查。 |

   例如，历史文件缺少 Content Object 时可以提示：

   > 复制失败 [CONTENT_COPY_SOURCE_INVALID]：来源文件尚未建立可复用的内容引用，当前无法通过此方式复制。

   SQLite 写入校验异常则可以提示：

   > 复制失败 [CONTENT_COPY_SCOPE_INVALID]：目标写入信息与当前授权不一致，系统已拦截此次操作。请刷新后重试；持续失败时提供请求编号。

4. **前端统一呈现，保留现有判断逻辑**

   - `DiskClient` 保留现有 `error.message` / `code`，避免破坏依赖错误码的分支判断；新增 `userMessage` 等展示字段。
   - 协同页、个人网盘、分享页共用格式化入口，优先显示服务端具体说明，再补充错误码。
   - 老服务端没有说明时，使用本地通用文案作为兜底。
   - 只展示用户有权获知的名称、路径和资源状态；不输出 Bot Token、服务器文件路径、原始 SQL 或未授权资源信息。
   - 多项目操作应指出哪个项目失败，以及哪些已经完成、哪些未执行；不自动重复执行整个操作。

5. **验收范围**

   为每个拦截原因验证“错误码＋具体说明”，重点覆盖父目录复制到子目录、同项目、越界、权限降级、授权撤销、重名、静态保护、挂载项、历史内容引用和操作期间数据变化。另测旧响应兼容、底层异常概括及敏感信息过滤。

   本次改动只增强错误分类和展示，现有权限校验、事务边界及复制限制保持原有行为。
