# Drop2Tunnel S7：网盘协同挂载与文件操作开发指南（需求原则版）

> **目标分支**：`dev/2609-s7-disk-partition-collaboration-mount`。供 Codex 使用。
>
> 本文只约定**产品行为、操作边界和数据安全原则**，不指定函数、接口、数据表或实现顺序。请先核对实际分支、现有代码和未提交改动，优先复用已有能力；允许按技术现实灵活设计，但**不得擅自改变已确认的需求**，关键偏差和无法完成的部分须如实说明。

## 1. 回收站：显示真实文件信息

回收站至少显示删除前的**真实文件/目录名、完整原位置、文件类型、大小、删除时间**，不得把 `:recycle:...` 等内部标识展示为文件名。目录可显示合计大小及子文件数；既有异常记录应尽量从可信历史数据修正，无法恢复的信息不得编造。

**原则**：仅纠正数据记录与展示，不破坏内部回收隔离、还原、永久删除、同名冲突和 Content Object 引用清理。以 `新建 Microsoft Word 文档.docx` 被删除后能正确展示并完整还原为验收案例。

## 2. 「查看协同列表」固定关闭按钮

打开网盘顶部「查看协同列表」后，**右上角 × 与右下角「关闭」均须固定可见**，不受中间列表滚动遮挡，适配长列表和窄屏。注意是该列表弹层，不是其它协同管理小面板。**点击列表中的协同项目仍以旧方式打开全屏协同页。**

## 3. 网页工坊「从网盘导入」显示 Loading

点击导入后，按钮立即显示旋转 Loading，**实际下载与导入结束前不得消失**。禁止重复触发；成功、失败或取消后正确结束，失败可重试。动画必须与真实任务状态一致，不以固定时长冒充进度。

## 4. 已挂载协同项目：在原生网盘原地操作（重点）

### 4.1 入口与数据归属

- **从原生网盘目录打开 Mount**：在当前网盘界面**原地进入**协同内容，沿用原生列表、多选、预览、菜单、面包屑、返回等交互；不能只是缩小或嵌入旧协同页 iframe。文件级协同与目录级协同应分别正确处理。
- **从顶部「查看协同列表」打开**：继续使用原来的**全屏协同页**，不改此入口行为。
- **Mount 本体是我的特殊入口，不是真实目录**；内部文件/目录仍归原所有者。原地浏览不等于复制到我的网盘，不能因此混淆存储、统计、搜索、缓存、权限或删除范围。访问时始终核实当下有效的协同授权。

### 4.2 Web 网盘操作的真实含义

挂载内部应按权限提供与原生网盘一致的**多选、预览、下载、重命名、复制/移动、复制路径、属性、缓存到浏览器、复制到协同项目、转发到隧道、分享、复制静态链接和删除**。

- **Mount 本体**：改名、移动只调整我的挂载入口；移除挂载**绝不删除远端文件**。仅本体可以设置静态资源开放。
- **Mount 内部文件/目录**：`editor` 的修改、改名、移动、删除是对**原所有者真实资源**的操作，删除须清楚提示；`viewer` 不得修改或删除，但可读取及按下述规则分享。
- 内部不提供「防失联检测」「邀请协同编辑」，也不能再次设立协同或挂载。不要为复用 UI 而绕过协同范围、角色或真实所有权。

### 4.3 复制/移动与失败保护

- 同一协同授权范围内，`editor` 可正常复制、移动；不得越界或将目录移到自身后代。
- **协同项目 → 本人指定网盘分区/目录**：Web **同时支持 Copy 与 Move**。Move 可使用**先完整复制并确认，再删除来源**；删除前重新核验授权与来源未被不安全地修改。
- 复制失败**绝不删源**；复制成功而删源失败，应明确标示**“已复制，来源仍存在”**并安全恢复，不能误报成功或无意重复复制。共享 Content Object 的引用、租约及清理不得导致其它文件损坏。
- 不借此扩展所有其它跨作用域 Move；本人原生分区之间现有 Copy/Move 保持不变。

### 4.4 分享与静态资源：只归挂载者

- **默认允许再次分享**：受邀者对有权读取的协同文件/目录，可以向其他人分享，无须原所有者额外批准。未来如有明确的细粒度禁分享权限，再按该权限执行。
- 分享记录**仅属于挂载者账号**，不在原所有者网盘增加分享记录；**不能因为挂载者分享而冻结原所有者的修改、移动、删除**。原文件消失、超出授权范围或挂载者失去权限后，分享必须停止读取，不能错误指向后来同名的资源。
- **静态开放只能设置在 Mount 本体**，记录亦仅在挂载者网盘。内部文件/目录可以复制基于**该 Mount 有效静态链接和相对路径**生成的链接，**不单独设置、不逐项建立开放记录**。
- 静态访问同样受挂载状态、开放期限及当前协同权限约束。原所有者无需冻结源内容；旧路径的 URL 不保证永远有效，已被第三方缓存的副本也无法确保收回。

### 4.5 S3API 和对外网盘 API：挂载一律只读

这是用户**最终确认**的规则：不论 `viewer/editor`，**Mount 本体及内部内容在 S3API 和对外网盘 API 中一律只读**，只允许列举、查看、读取、下载；**禁止新增、上传、覆盖、改名、移动、删除、移除挂载**。

- S3 可将 Mount 展示成**只读虚拟目录前缀**，不创建真实本地目录和文件副本。
- **必须从服务端堵住所有间接写入**：批量删除、逐项删除、覆盖、通过父目录递归清理、通过其它路径操作挂载等，均不能损害指针或远端数据。
- 只读限制**仅针对外部 API 的挂载命名空间**：用户自己的 Native 文件仍沿用已有 API 能力；Web 网盘仍能按协同角色正常编辑。不能只隐藏按钮，或错误地将 Web 所需的内部调用全部禁写。

### 4.6 绝对安全边界

- **禁止嵌套污染、子套父、循环引用和二次协同**：Mount 不能进入另一个 Mount；含 Mount 的原生目录不能被开启为包含该 Mount 的协同；已有协同目录中不能移入 Mount 或再设新协同。
- **禁止名称重复**：原生同一父目录内的普通文件、目录与 Mount 不能同名。移动、恢复、并发操作后仍须保持结构合法。
- **递归操作不得穿透 Mount**：删除原生父目录、回收站、分区复刻、统计等只能处理本地资源与挂载指针，**不得递归删除或改写远端文件**。
- 所有操作均按**真实操作人、所属 owner、当前角色、授权范围、来源和目标、访问渠道**进行服务端校验。撤权或资源变化后不能通过旧链接、缓存或路径拼接绕过。

**本项验收核心**：Web 中可原地访问并正确修改有权限的协同内容；顶部协同列表入口不变；分享/静态记录只在挂载者处；S3/外部 API 只读；删除挂载不删除远端；授权失效后无法继续读取。

## 5. 目录全量下载：暂缓

「下载指定目录全部内容，并可选包含挂载协同内容」**本轮不开发、不验收**。

## 6. 系统文件夹递归拖放上传与全局设置

- 支持从系统文件管理器拖入整个文件夹，**递归上传文件和子目录，保留文件夹名称、各级相对路径及可读取的空目录**，不能把所有文件平铺上传。
- 网盘最大目录层级统一为 **30 层**，按照操作完成后的真实层级计算；**30 允许、31 拒绝**。前端和服务端相关创建、复制、移动、恢复等操作均须统一，不能残留旧的 20 层上限。
- 拖放上传文件夹的**内部文件大小合计上限默认 500MB，允许修改**。只算本次拖入的全部文件夹及后代文件，**不是**目标目录总容量或单文件上传限制；早期固定 300MB 的要求作废。
- 在齿轮的**个人网盘全局设置**中提供上述两项配置，跨分区及重新登录后持续生效；可调整目录限制但不能突破系统统一 30 层上限，不得因此删除旧目录。
- 上传前检查总体积、最终层级、重名及非法路径；**服务端也必须校验**。大量文件自动分批、维持完整目录结构和整体进度；失败、取消、权限不足、无法枚举的文件夹不能静默漏传或谎称全部成功。

**验收核心**：复杂目录与空目录可保留，多文件可自动分批；30 层与 500MB 的边界准确，个人全局设置在各分区一致，出错后可以安全恢复。

## 7. 新建/编辑纯文本、Markdown、十六进制文件

- 新增**「新建文件 → 纯文本｜Markdown｜十六进制」**。纯文本可编辑；Markdown 和十六进制均提供**编辑 + 预览双栏**，窄屏可自适应。Markdown 预览不得执行不可信脚本；十六进制必须保真处理字节，不可由文本编码转换损坏二进制。
- **编辑现有文件必须写时复制**：用新的 Content Object 保存修改后内容，再安全更新当前 Logical File 的引用；**绝不可原地修改仍被其他 Logical File 共享的旧 Content Object**。
- 确认新内容有效、权限与版本仍正确后才切换引用；失败、并发编辑、撤权时保证旧数据和其它引用完整。旧内容清理遵守原有引用与租约规则。
- 文件创建与编辑始终遵守真实分区、协同所有者、权限和名称约束，不能误把外来协同内容写进自己分区。

**验收核心**：三种格式可准确保存和重新读取；双栏正确预览；编辑共享旧正文的其中一份，不改变另一份；失败不破坏原文件。
